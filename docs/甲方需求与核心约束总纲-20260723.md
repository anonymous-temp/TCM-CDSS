> 文档版本：v1.0  
> 定稿日期：2026-07-23  
> 文档性质：后续需求、开发、测试、部署和交付的规范性基线

5. 已被后续决策废止的旧口径，防止后续开发误用旧材料。

本文适用于：

- 需求评审；
- 产品和临床方案设计；
- Prompt、模型编排、确定性规则和治理数据开发；
- 前后端功能开发；
- 测试用例、评测器和发布门禁设计；
- 镜像构建、正式部署、线上验收和交付签收。

## 2. 最高优先级核心约束

以下约束是后续开发不得偏离的底线。

### GOV-01：发现一个问题，解决一类问题

- 不允许只针对一个病例、一个字符串、一个药名或一个截图加特殊分支。
- 每个缺陷必须先归类：事实、极性、时态、主体、结构合同、医学推理、知识覆盖、展示、审方、外部接口或部署。
- 修复必须覆盖同类表达、同义变体、否定式、既往式、稀疏和稠密输入。
- 每个修复必须新增类别级正例、反例、边界例和变体回归。

### GOV-02：优先使用模型语义能力，但安全权威不能交给模型

- 开放语义理解、临床推理、问题质量、诊断分析、病机拆解和候选选择应充分使用 LLM。
- 规则、正则和关键词只承担适合确定性实现的职责，不得用少量词条假装覆盖开放语言。
- 必须使用规则时，词条应进入治理表，建立别名、来源、冲突、覆盖度和回扫测试。
- 红旗硬结论、危急生命体征、签名、剂量边界、药名歧义、处方结构完整性和外部审方提交条件必须由确定性层掌握。
- LLM 可追加风险和澄清建议，不能取消确定性红旗或绕过安全门。

### GOV-03：不要把信息等级做成非此即彼的阻断器

- C 级是追问和信息收集的优先目标，不是唯一可继续诊疗的门票。
- 系统应优先通过一轮高信息增益追问提升信息量；医生可以点选、自由输入或跳过。
- 追问后仍得不到有价值信息，或患者确实无法补充时，应基于现有事实继续做有限、保守、可解释的推理，不能卡死流程。
- 诊断和剂量权限必须由多维条件共同决定，不得简化为“非 C 一律不得进入剂量链”。
- 缺失真正决定剂量安全的要素时，可降为非剂量或人工复核，但医生的病例浏览、判断和后续操作不得被系统锁死。

### GOV-04：系统是辅助建议，不阻断医生看病流程

- 红旗、审方、模型复核和证据提示均为临床辅助，不替代医生或药师最终决定。
- 自动链路可以拒绝生成不安全的剂量、拒绝调用不完整的审方请求或要求人工复核，但页面必须允许医生继续查看病例、补充信息、重试、记录人工决定。
- 审方风险结果只提示，不作为系统自动签章、自动放行或最终裁决。
- 不得把 fail-closed 实现成页面卡死、无限转圈或医生无法继续处理患者。

### GOV-05：测试结果必须诚实，不得把“请求成功”说成“全部通过”

- HTTP 200 不等于结构化结果成功。
- 模型返回不等于合同通过。
- 合同通过不等于医学质量通过。
- M04 返回不等于形成了可审查处方。
- 灵犀单接口可用不等于 M01–M05 全链已经到达审方。
- EviMed 检索接口可用不等于每条诊疗结论都已正确引用证据。
- 有阻断项、降级项、未执行项或外部接口未验证时，禁止宣称“全部通过”“全部上线生效”。
- 测试报告必须分别列出通过、失败、降级、未执行、基础设施错误和人工待审。

### GOV-06：禁止无穷无尽地边测边改

- 每轮迭代先冻结范围和 checklist，未被提到的内容不得擅自扩改。
- 测试发现范围内同类缺陷时，做根因修复并回归；发现范围外问题时，先登记并交用户判断。
- 用户明确要求“只测试、先汇总、不修改”时，任何产品代码都不得改动。
- 到达已约定验收标准后立即收口，不再为了追求抽象“完美”无限修改。
- 每轮必须给出明确结束条件、剩余项和是否允许部署的结论。

### GOV-07：正式环境必须是真实部署，不得使用临时隧道或临时入口

- 不得使用临时隧道、临时反向代理或只在当前电脑存活的入口冒充正式上线。
- EviMed 和灵犀审方必须调用约定的正式接口，不得误用本地临时入口或测试替身。
- 对外地址必须保持 `http://82.156.128.153/tcm-cdss/login`，未经用户书面确认不得更换。
- 登录密钥保持现有正式值不变，但不得写入源码、文档正文、日志、镜像层或版本库。
- 正式部署位于用户腾讯云，通过正式 Nginx 子路径代理提供服务。

### GOV-08：所有后台文本模型统一使用 DeepSeek V4 Pro

- M01、M02、M03、M04、结构修复、临床事实抽取、独立临床复核、处方复核等全部文本模型统一为 `deepseek-v4-pro`。
- 不允许阶段间静默回落到其他文本模型。
- GLM 仅允许用于用户明确启用的舌象视觉，不得接收完整病历做文本推理或复核。
- 健康检查必须显示实际生效的 provider、model 和各阶段覆盖配置。

## 3. 产品定位与流程总要求

### PROD-01：产品定位

- 系统是门诊中医临床决策支持副驾驶。
- 系统输出为建议性质，不替代执业医师诊断、处方、审方、调剂和签章。
- 每条关键结论必须能追溯到患者事实、确定性规则、治理知识或真实外部证据。
- 不得伪造指南、文献、说明书、批准文号、药典条文、方剂出处、DOI 或院内规则。

### PROD-02：M01–M05 连续流程

1. M01：病例采集、结构化和红旗初筛；
2. M02：一轮高信息增益追问与结构化回填；
3. M03：西医诊断、中医病名/证候、病位病性、病机和治则治法；
4. M04：候选方药、中成药/西药提示、随症加减、非药物治疗和监测；
5. M05：合理用药审查结果、处方后风险和个性化随访。

任何阶段失败都必须：

- 显示具体原因；
- 保留已完成的上游结果；
- 提供重试或人工处理入口；
- 不让下游继续空转；
- 不伪装成完整成功。

### PROD-03：当前架构边界

- 当前正式实现是 M01–M05 线性流水线，不得把目标文档中的 LangGraph/ReAct、多智能体或统一 `/api/tcm-cdss/run` 描述为已上线能力。
- 当前病例主要存在浏览器状态和服务端加密快照中；没有集中业务数据库的能力不得对外虚假承诺。

## 4. M01 病例采集要求

### M01-01：最小必填

- 主诉和性别是全局最小必填项。
- UI 必填、服务端请求合同和后续剂量权限必须同源。
- “其他或未明确”可视为完成采集，不阻断医生继续，但不能被当成已知男/女性生理状态，剂量权限应保持保守。

### M01-02：事实忠实

- 不得把未提及当成否认。
- 不得自动补造舌象、脉象、生命体征、过敏史、用药史或检查结果。
- 快捷输入和默认值不得伪装成患者真实事实。
- M02 新回答不得导致先前主诉、现病史、四诊和五史被清空。

### M01-03：主体、极性和时态

- 必须区分患者本人、家属代诉、亲属本人病史、引用病例和宣教文本。
- 必须区分阳性、可能、阴性、既往、已缓解和未知。
- 当前妊娠、既往妊娠、备孕和哺乳必须按真实时态处理。
- 既往稳定疾病不得自动转换为当前活动性治疗目标。

### M01-04：生命体征

- 结构化字段和自由文本中的当前生命体征必须共用同一解析与范围校验。
- 危急值触发确定性安全处理。
- 非法值如 `SpO2=999%` 必须明确提示重录范围，不能静默丢失。

### M01-05：舌象与隐私

- 舌象视觉必须显式启用；未启用时不允许静默降级为其他模型。
- 上传前应去除 EXIF，并提供预览和人工确认。
- 舌象图片不进入病例快照。
- 患者文本、准标识符和图片外发必须遵守最小化原则。

## 5. 红旗与安全要求

### SAFE-01：红旗权威结构

- 确定性规则和经验证生命体征阈值是硬安全结论的权威。
- LLM 语义事实只做 additive-only 的补充发现、紧急度建议和澄清，不能取消确定性结果。
- 语义层结果必须有逐字 quote、主体、极性、时态和 schema 校验。

### SAFE-02：触发边界必须可解释

- “突发胃痛 3+ 小时”和“胃痛 3+ 小时”不得仅靠一个关键词形成不可解释的二元悬崖。
- 红旗结果至少应包含风险类别、级别、患者原文依据、命中方式和下一步动作。
- 必须覆盖否定、既往、已缓解、基线症状和当前恶化的边界。
- 急危重、优先评估和一般提醒应分级展示。

### SAFE-03：类别覆盖

至少覆盖并持续治理：

- 心血管急症；
- 神经急症、意识障碍、昏迷、抽搐和惊厥；
- 消化道出血和其他活动性出血；
- 急腹症；
- 严重呼吸困难、喉头阻塞和低氧；
- 脓毒症、休克、过敏性休克；
- 产科急症；
- 儿童危重；
- 中毒和代谢急症；
- 自伤、自杀和严重行为危机。

### SAFE-04：高风险人群

- 婴幼儿、儿童、妊娠、备孕、哺乳、CKD 3–5 期、心衰、抗凝、免疫抑制、糖尿病足、活动性自身免疫病等必须进入专门风险判断。
- 高风险类别不是靠一份永远列不完的硬编码清单解决，应采用治理数据、模型语义识别和确定性安全边界融合。
- 高风险不等于页面阻断；应优先追问、降低方案强度、限制剂量或转人工复核。

## 6. M02 追问要求

### M02-01：一轮、少而精

- 每轮只输出 1–2 个真正能改变处置、首要鉴别、主证权重或用药边界的问题。
- 不得为了达到数量而补舌脉、人口学或泛化病程问题。
- 不进行无限追问；提交任一题、自由输入或跳过后都进入后续推理。

### M02-02：信息增益

- 输出前必须对已知事实做语义审计。
- 已记录的持续时间、时序、诱因、缓解因素、伴随症状、阴性史和用药反应不得换一种说法再问。
- 并列问题必须逐项拆解；其中任一子条件已知时，不得把已知条件与未知条件用“或/和”捆绑后继续追问。
- A/B 必须互斥并代表明确临床事实；未知只放 C。
- 问题、理由和预期决策影响的时间范围必须一致。

### M02-03：回答回填

- 点选和自由文本回答都必须回填到正确结构化字段。
- 必须保持否定、未知、时态和主体。
- 刷新恢复后，回填事实仍应存在并参与 M03/M04。
- 追问获得的判别性事实必须真实提高完整度计算，不能退化成“有没有舌脉”的二值评分。

### M02-04：降级

- 模型问题不可用时可给有限兜底问题，但必须有明确降级状态。
- 不得把高质量模型问题静默替换成通用“加重、缓解还是波动”后冒充正常结果。

## 7. M03 西医诊断与中医辨证要求

### M03-01：西医诊断

- 西医诊断不得混入“痰湿型、肝火型、气虚证”等中医分型。
- 诊断名称应为一个可理解的工作诊断；多个可能方向进入鉴别诊断，不得压在一个含“或/待鉴别”的名称里。
- 应尽可能给出对应 ICD-10 编码。
- ICD 只能在唯一、受治理的名称或别名映射成立时输出；歧义时宁可不编码或提示复核，不能给错码。

### M03-02：西医诊断依据必须有推理

- supporting facts 只列与当前主诊断直接相关的患者事实。
- 年龄、性别、正常生命体征、舌脉和无关既往史不得凑数。
- 临床分析必须解释“阳性事实如何支持诊断、为什么暂不采用更具体病因或相邻诊断”。
- 禁止把现病史换标点重抄一遍。
- 西医鉴别必须写具体理由和区分要点，不能只罗列病史。

### M03-03：中医诊断

- 必须输出中医工作病名、主证、兼证或边界说明。
- 中医辨病辨证依据临床表现和四诊合参，不得把缺 CT、MRI、实验室或量表当成不能辨证的理由。
- 疾病名称不能直接机械推导中医证型：
  - 高血压不能在无头晕时自动生成“眩晕”；
  - 房颤不能仅凭疾病名称推导“心气不足、心神不宁”；
  - 湿疹、类风湿、狼疮等在四诊不足时不能形成确定性证型。
- 证候支撑必须逐条落到当前患者阳性事实，不能用疾病标签充当证候证据。
- 必须提供中医鉴别诊断；确实无法形成鉴别时，显示具体原因，不能整节消失。

### M03-04：病位、病性和病机

- 页面必须显示病位结论或明确的未定状态，不能因数组为空直接隐藏整个病位模块。
- 病位必须四诊合参，不能只按“咳嗽→肺”机械定位；需要综合痰、纳运、二便、舌脉和其他阳性事实。
- 中医病位不等于西医脏器定位，不需要影像学佐证。
- 病性应使用规范术语，区分气滞、火热、湿、痰、瘀、虚等，不得把“胃失和降”等病机直接填进病性。
- 总体病机不能复述主诉。
- 病机链必须形成：
  `患者事实 → 辨证意义 → 病位/病性 → 病机变化 → 对应治法`
- 多个子病机不得复制同一句病机和同一治法。
- 症状簇与病机映射必须医学合理，不能把无直接关联的症状强行推导成胃肠热结等结论。

### M03-05：治则、总治法和分治方向

- 治则是上位治疗原则，如正治、反治、治标治本、标本兼顾、扶正祛邪、调整阴阳和三因制宜。
- 总治法是本例整体治疗策略。
- 分治方向逐项对应不同病机节点。
- 治则、总治法和分治方向不得全部写成同一句。
- 禁止跨病例固定使用“因人制宜”等默认治则。
- “标本兼顾”允许说明主次优先级，但必须同时对应“本”和“标”的目标，并解释当前优先级；不能机械禁止主次，也不能只喊口号。

### M03-06：话术与把握度

以下医生可见话术禁止出现：

- “判断把握度：低”；
- “当前为有限资料下的工作判断”；
- “接诊时核实相关症状是否存在”；
- “程序化安全门控”；
- “剂量级”；
- “bounded”；
- schema、JSON、API、reason code 等工程术语；
- 只为免责而存在、没有临床动作价值的套话。

信息有限时应：

- 先在 M02 问真正有价值的问题；
- 跳过或无法补充后，用具体事实和具体限制表达结论边界；
- 不展示抽象低置信标签；
- 不重复提醒“由医生决定”占用主要页面空间。

### M03-07：结构与独立复核

- M03 必须形成完整 sentinel、合法 schema、阶段所有权和病例绑定签名。
- 修复后的结果必须重新送独立模型复核。
- 最终展示和证据清洗改变临床字段后，必须重新校验或安全重绑，不能把已复核的另一份 payload 冒充最终结果。
- 结构失败、截断、复核失败和修复 fixpoint 必须有限收口，不得无限重试。

## 8. M04 方剂、药物与治疗建议要求

### M04-01：经典方与自拟方

- 能匹配经典方时，应展示方名、规范出处、基础组成和本例加减。
- 方剂检索应使用“病例阳性事实召回 → M03 后证型/病机精确召回 → 多路融合”的正确时序。
- 不得为了提高命名方率强推经典方；错误锁定率和安全弃权率比表面锁定率更重要。
- 自拟方必须明确标注为自拟，并用本例病机说明为什么未采用可核验经典方。
- “模型推断”不得作为医生可见的方剂出处。

### M04-02：方证药一致

- 候选方必须与签名 M03 的主证、兼证、病机节点和治法一致。
- 君臣药功能并集应正向覆盖主要治法，不能只做“没有相反方向”的消极校验。
- 不得出现跨病种万能君药偏置。
- 君、臣、佐、使的本例配伍意义必须不同，不能全部重复同一病机句。

### M04-03：药名、剂量和煎服

- 药名使用标准名；俗名和炮制品必须经过 T9 规范身份解析。
- 真实歧义必须 fail-closed，不能靠字符串相似度或 LLM 猜。
- 不能通过展示层静默改名掩盖模型不依从；生成、校验和展示应使用同一规范身份。
- 每味药剂量必须是单一可解析数值和单位，并满足治理剂量边界。
- 先煎、后下、包煎等特殊要求不得遗漏。
- 处方必须明确总剂数、每日剂数、每日分服次数、疗程和复诊节点；这些字段必须是审方和展示共用的单一事实源。

### M04-04：独立处方复核

- 处方修复后必须再次送独立模型复核。
- `clinicalReview=unavailable` 时不得把剂量结果当作已复核结果展示，应降为非剂量/需人工复核，但不锁死医生流程。
- `repair_demanded` 持续无法收口时走既有非剂量安全降级。
- 独立复核必须核对方证、药味角色、剂量、患者特殊情况和本例治疗方向。

### M04-05：随症加减

- 加减只针对当前病历已经记录的伴随症状。
- 不得提前假设复诊时可能出现的症状。
- 每条加减必须包含触发症状、来源、对应病机、加/减/调动作、药名和理由。
- “相关症状”必须写具体，不得使用指代不明的占位词。
- 没有合格加减时，应显示本例为什么没有加减或被过滤的类别，不得静默空白。
- 加减依据应来自可追溯治理表、方剂条文或明确患者病机，不能用文件顶部常量冒充依据。

### M04-06：温清反佐和知识缺口

- 温清反佐不能被简单的寒热极性冲突规则一刀切拒绝。
- 左金丸式黄连与吴茱萸等结构必须显式建模反佐角色、比例、适应病机和安全边界。
- 麦冬、生地黄等功用知识缺口应从数据源和治理表补齐，不能靠病例特判。

### M04-07：中成药和西药候选

- 中成药和西药板块不能长期全空。
- 正确结构是“服务端检索定边界，模型在候选集内选择与论证，服务端再绑定和否决”。
- 中成药候选应综合证型、治法、症状、适应证、特殊人群和真实说明书证据。
- 每个候选必须绑定真实说明书或本地治理条目的 ID 与指纹。
- 候选集外药名视为编造，不得输出。
- 西药第一阶段只做 discussion-only 提示，不输出剂量。
- 无合格候选时显示具体原因，例如“未检索到与本例诊断/证型匹配且可核验的说明书条目”，不能空白或输出通用套话。

### M04-08：中医非药物治疗

- 不得无论什么病例都只推荐针刺和推拿，也不得固定重复“气功导引+灸法+拔罐”套餐。
- 候选项目应结合主证、病机、疾病阶段、年龄、体能、局部皮肤状态和禁忌。
- 婴幼儿湿疹不应常规推荐针刺、刮痧。
- 心肾功能不全、糖尿病足、骨折、严重骨质疏松、急性炎症、出血倾向、抗凝、妊娠禁忌部位和局部感染等应进入项目适用性判断。
- 页面必须提供机构中医诊疗项目配置入口。
- 只能推荐机构已配置、当前可开展的项目；配置变化应立即影响候选，并进入健康检查。
- “评估定位：由本机构医生结合现场查体决定”这类跨病例相同字段不应展示。
- 只有适应证精确匹配且治理证据包含参数时，才输出具体穴位/部位、频次/疗程和注意事项。
- 无来源参数不得编造；不满足质量门槛的项目应省略或保持明确评估级，不得展示空壳方案。

## 9. EviMed 证据检索要求

### EVI-01：正式接入范围

必须真实接入并验证：

- 指南；
- 文献；
- 药品说明书；
- 药品标签或等价受控来源。

不得再把 EviMed 整体描述为“全不可用”；单次失败必须区分鉴权、限流、网络、单端点失败和无结果。

### EVI-02：正式入口和密钥

- 使用用户提供的正式 EviMed API key，并存放于正式环境变量/密钥管理中。
- 不得把 key 写入源码、文档、测试输出、镜像层或版本库。
- 不得调用本地临时入口冒充正式证据检索。
- 健康检查应分别探测指南、文献和说明书等端点，不能只探测一个总地址。

### EVI-03：推理利用

- 接口可用只是第一步；M03/M04 推理必须真正消费相关证据。
- 证据检索应按本例问题做相关性选择，不能把无关结果塞入 prompt。
- 医生可见内容只展示与当前结论实际相关的来源类型、题名、链接/DOI、检索时间和决策绑定关系。
- 病例内模型推理不能冒充外部证据。
- 无证据时可以诚实省略或给出具体无匹配原因，不得伪造来源。

## 10. 灵犀合理用药审查要求

### RX-01：名称与展示

- 原“Lingxi 建议性复核”统一改为“合理用药审查”。
- 有明确风险时展示风险内容。
- 明确完成且未发现风险时，不在主页面输出大段“未见明确风险提示”绿色套话；内部审查状态仍应留存。
- 服务不可用、审查范围不完整或数据缺失时，必须显示“未完成/需人工复核”，不能按“无风险”隐藏。

### RX-02：正式接口

- 必须调用对外正式审方入口，不得调用本地临时入口或仅用于调试的 route。
- 应验证正式租户、目录、系统编码、token、返回 issue ID、风险级别和药味关联。
- 灵犀单接口测试和完整产品链到达率要分别报告。

### RX-03：不完整处方不得送审

- 缺任一药味剂量，不调用外部审方。
- 缺给药频次、疗程或复诊节点，不调用外部审方。
- 缺结构化药味，不调用外部审方。
- 本地必须返回明确输入问题、涉及药味/字段和“本次未调用外部审方接口”。
- M05 仍可继续生成人工复核和随访提示，不得阻断医生流程。

### RX-04：审查范围

- 中药饮片、中成药和西药必须明确各自是否进入真实审方。
- 不能只审饮片却把 PASS 展示成整张处方全部通过。
- 外部审方不支持的品类必须显示“未提交该品类，需人工复核联用风险”。

### RX-05：失败与降级

- 审方不可用、超时、解析失败或结果不完整时 fail-closed 到人工复核。
- 不得伪造本地 provider issue ID 冒充灵犀结果。
- 同义、重复和噪声告警应合并；否定史不得误触发。
- 审方仍是建议性质，不硬性阻断医生最终临床决定。

## 11. M05 随访与健康宣教要求

### M05-01：个性化时间轴

M05 应直接输出结构化：

```text
timelineItems = [{
  time,
  action,
  indicators[],
  triggers[]
}]
```

- 前端只渲染，不再从 Markdown 表格反向猜字段。
- 观察指标、触发处置、疗效标准和复诊动作必须语义分离。
- 无依据的格子不写，不用通用句兜底。

### M05-02：禁止模板错位

以下错误不得出现：

- “无效或加重”的触发处置写成“本次主诉及伴随症状变化”；
- 疗效观察与安全观察混在同一格；
- 指标字段放入处置命令；
- 处置字段放入观察内容；
- “。；”等机械拼接；
- 所有病例固定输出同一组皮疹、胃肠不适、头晕乏力、心悸胸闷和出血倾向。

### M05-03：个性化内容

- 随访时点根据病情、疗程、药物风险和 M04 monitoring 决定。
- 指标应引用本例主诉、伴随症状、舌脉、客观指标、用药和审方风险。
- 触发处置必须包含条件和具体动作。
- 健康宣教应与本例病情、饮食、作息、情志、运动和用药边界相关，不得只输出万能宣教。

## 12. 医生可见输出与 UI 要求

### UI-01：医生可见内容清单

最终系统应按实际数据和状态覆盖：

- 红旗预警及依据；
- 需要补充的信息及原因；
- 西医诊断、ICD、分析和鉴别；
- 中医病名、主证、兼证、依据和鉴别；
- 病位、病性、总体病机和病机链；
- 治则、总治法和分治方向；
- 候选方名、出处、组成、剂量、君臣佐使、加减、用法、煎法、疗程；
- 中成药/西药候选或具体无候选原因；
- 中医治疗项目或具体无项目原因；
- 合理用药审查范围、风险和人工复核状态；
- 个性化随访与健康宣教；
- 不能诊断、不能给剂量、不能送审或不能推荐的具体原因与下一步动作。

### UI-02：唯一输出权威层

- 正常结果、受限结果、红旗结果、非剂量结果、M05、下载报告和 HIS 输出必须消费同一输出合同注册表。
- 不得在 prompt、服务端模板、前端解析和 JSX 中分别维护五套标题、顺序和空态文案。
- 屏幕与下载报告必须同源。

### UI-03：收敛与可读性

- 结论先行，依据和详细分析可折叠。
- 同一事实不在多个卡片重复罗列。
- 单条患者依据保持短而准确，不整段复制现病史。
- 西医内容通常较多，中医内容较少时不得使用僵硬等宽双栏；采用内容权重、自适应高度或折叠布局。
- 西医鉴别可以下沉为折叠区，中医侧应完整显示病位、病性、兼证和鉴别。

### UI-04：删除无价值内容

- 删除“本次生成依据”中只写模型套话、流程说明或免责话术的板块。
- 只有真实来源或真正参与本次结论的资料才显示为参考文献/依据。
- 删除统一“评估定位”。
- 删除低把握度标签和“有限资料下工作判断”。
- 无明确风险时不展示大段无风险提示。

### UI-05：空态和受限态

任何空态或受限态都必须用三段式表达：

1. 正常生成标准；
2. 本例具体未满足项；
3. 医生可以采取的补充、重试或人工处理动作。

不得统一写“本次未形成可核验候选”“请结合现场情况决定”后结束。

### DATA-02：方剂与饮片的真实边界

- T8 的“方名身份可锁定”“患者级剂量可编译”“真实处方已审查”是三道独立门禁，禁止混为一个数字。
- 当前治理目标必须完整纳入 500 首方剂身份。
- 历史“337 首具剂量编译底本”是数据输入口径；最终可执行数量必须以逐味身份解析和数值型内服剂量边界通过后的安全统计为准，不得为了报数把不可执行方算作可执行。
- T9 真实歧义必须进入明确 SLA 队列，不得自动猜测。

### DATA-03：数据表不是摆设

- 每张表必须有唯一运行时消费入口。
- Prompt 注入、确定性校验、UI、健康检查和测试应尽量同源。
- 每张表必须有 schema、来源、版本、SHA-256、规模、歧义和隔离统计。
- 必须进行表内完整性、别名闭环、语料回扫和变异矩阵测试。
- 数据不全时如实记录缺口，不复制、伪造或凑数。

### DATA-04：外部参考资产

- 参考教材、经典方、医案和其他中医资料可用于知识治理、召回、鉴别和评测。
- 参考资料不能替代现行标准、药典、说明书或甲方院内规则。
- 高风险、来源不明或不可执行内容必须隔离。
- 联网搜索可用于治理补充和来源核验，不能把未经核验的网页内容直接变成患者级处方依据。

## 14. 安全、隐私和鉴权要求

### SEC-01：访问控制

- UI 登录使用 httpOnly cookie。
- API 支持专用 token header 或 Bearer token。
- 未授权请求返回 401。
- 登录失败、API 和模型调用必须限流。
- Cookie 鉴权写请求必须验证 Origin/Sec-Fetch-Site。

### SEC-02：密钥

- CDSS 登录 token、快照密钥、推理签名密钥、模型 key、EviMed key 和灵犀 token 必须分离管理。
- 不得读取后打印、提交或写入交付文档。
- 构建镜像不得把真实 `.env` 或 key 固化进层。

### SEC-03：PHI

- 姓名、手机号、证件号、地址、出生日期、精确时间、唯一职业等送外部模型前脱敏。
- 必须覆盖无标签地址和口语化准标识符。
- 任何新增外部出口必须复用同一脱敏链，不能另开旁路。

### SEC-04：签名和快照

- M03/M04 可执行结果必须与病例事实、患者状态和版本绑定签名。
- 病史、用药、过敏、人口学或诊断变化后旧签名失效。
- 病例快照采用 AES-256-GCM 并绑定所有者。
