# 辨证框架层 迭代方案 v2：影子观察链

2026-08-15。**本版取代 v1**（`docs/辨证框架层-迭代方案-20260815.md`）。v1 的现状实测部分仍然有效、不重复；本版只写路线与任务。

---

## 版本说明：v1 被推翻的三处，两处是自相矛盾

| v1 的设计 | 问题 | v2 |
|---|---|---|
| `excludeTerms` 命中即出局 | **与自订原则矛盾**。v1 自己写「规则不判是什么，只判够不够」，转头设计硬淘汰。且硬淘汰会让医生看不到「为什么排除」 | 软扣分 + **分层**；反证方降到 `contradicted` 层但**保留可见**，仍作鉴别对象 |
| `allowsSyndromeLock` 由模型填 | **与 CLAUDE.md 第一原则矛盾**：模型永远不做安全决策。模型自填等于自我批准 | 改名 `derivedReadiness`，**只能由服务端计算**，模型无权写 |
| T4：`missingDecisive` 喂回 M02 | **时序不成立**。实测流程 `question`(M02) → `diagnose`(M03)，且全仓**没有任何重开追问通路**（`questionRounds` 仅一处 `< 1` 门控） | 第一阶段**不做 T4**；影子层只记录「若重新追问该问什么」。真要闭环需新建回路，工作量单列 |

另外两项本版新增的约束：

- **不再新造 `excludeTerms`**：实测 `edges[].sides.{from,to}.{supportTerms,againstTerms}` **167/167 条边全都有**，反证词本来就在库里。再造一套必然漂移。
- **影子层不得占用 M03 的时间预算**（v1 与复审都没提，见 §5）。

## 一、总体架构：正式链路不动

```
M01 → M02 → M03 → M04 → M05        ← 医生看到的，一行不改
             │
             └─（只读复制）→ 辨证框架影子评估 → 落盘审计
```

### 六条隔离原则

1. 不写入正式 `ClinicalReasoningResultV2`。
2. 不参与 M03 签名、修复轮与驳回码。
3. 不改变 M02 追问、M03 锁证、M04 锁方。
4. 失败/超时/数据不足一律静默记录，不影响医生结果。
5. 审计只存规则编号、事实引用 ID 与错误码，**不持久化患者原文**。
6. **不得增加 M03 的模型输出负担**（新增，见 §5）。

## 二、影子载荷：框架三分类，不强制单一 primary

复审这条是对的：八纲、气血津液是**横向维度**，与六经/脏腑/卫气营血并存，强要「有且仅有一个 primary」是把不互斥的东西硬做成互斥。

| 类别 | 框架 | 角色 |
|---|---|---|
| 基础坐标 | 八纲 | 表里·寒热·虚实·阴阳。**不参与争夺组织框架** |
| 组织框架 | 六经、脏腑、卫气营血、三焦 | 组织本例辨证与传变逻辑 |
| 病机维度 | 气血津液 | 跨脏腑的病理机制补充 |

```
FrameworkShadowAssessment[]
├─ frameworkCode          八纲 | 六经 | 脏腑 | 气血津液 | 卫气营血 | 三焦
├─ frameworkCategory      基础坐标 | 组织框架 | 病机维度
├─ modelProposal          organizing | supporting | not_selected | insufficient   ← 模型给
├─ evidenceStatus         supported | partial | unsupported | conflicted           ← 服务端算
├─ positiveFactRefs[]     规范化临床事实 ID（保留极性）
├─ contraryFactRefs[]     同上
├─ missingRuleIds[]       只能引用受治理鉴别边 ID，模型不得自由编造追问
├─ derivedReadiness       ready | bounded | not_ready                              ← 服务端算
└─ validationCodes[]      证据缺失 / 框架混用 / 组织框架冲突 …
```

**极性口径**（沿用 `clinical-state.ts`，不新写一份）：

- 明确阳性 → 支持证据；
- 明确否认 → 可作某候选的反证；
- **unknown / 未提及 → 既不支持也不反证**；
- 缺温病证据只能记 `unsupported` / `insufficient`，**不得写成「卫气营血不适用」**。

**流派偏好不参与框架适用性计算。** 实测现状已经是干净的（`tcm-classic-inference.ts` 不读 `tcmLineagePreference`），本版加一条防漂移断言钉住——这类「现在干净、以后被接上」的退化，本轮已经抓到两例。

## 三、方证候选：分层鉴别，不用人工权重

复审这条也对：早期样本不足时，「定义性 3 分 / 支持性 1 分 / 反证 −3 分」这类权重会变成**未经验证的新隐性规则**。

```
FormulaShadowScore
├─ decisiveSupport[]        决定性支持证据
├─ decisiveAgainst[]        决定性相反证据
├─ supportingEvidence[]     一般支持
├─ sharedEvidence[]         多方共有，不参与主排序
├─ unknownDiscriminators[]  尚未取得的关键分叉 → 追问建议来源
├─ conflictState            两侧证据是否同时出现
└─ safetyState              独立安全规则结果（不受本层影响）
```

**先按临床状态分层，层内再比信息量**：

| 层 | 含义 | 太阳伤寒案（发热恶寒无汗身痛脉浮紧） |
|---|---|---|
| `supported` | 有决定性支持且无明确反证 | **麻黄汤** |
| `partial` | 只有一般支持，决定性信息缺失 | 汗出未知时，麻黄汤与桂枝汤都在此层 |
| `conflicted` | 支持与反证同时出现 | — |
| `contradicted` | 有明确反证，**但保留为鉴别对象** | **桂枝汤**（不删除，医生要看见为什么排除） |
| `no_evidence` | 不进入展示候选 | 其余 |

反证只**降层**，不淘汰。**只有确定性安全禁忌才能硬阻断**——那条路径不属于本层。

## 四、词表治理：只剔 14 个词，且判据是「能不能观察到」

实测两张表的污染（去重后）：

| 表 | 词总数 | 诊断标签 | 治法/病机表述 |
|---|---|---|---|
| 节点 `supportTerms` | 832 | 8 | 3 |
| 边 `sides` | 2364 | 45 次 / **11 种** | 18 次 / **3 种** |

**自证加分已实测坐实**：

| 病历内容 | 麻黄汤排名 |
|---|---|
| 纯症状 | 第 6 名 `score=1` |
| 同症状 + 病历写了「太阳伤寒」 | **第 1 名 `score=2`** |

医生写了证名，系统就给对应方加分——真循环，必须切断。

**去重后需重分类的共 14 个词**：

- 诊断标签（11）：太阳中风、太阳中风兼项背强、太阳伤寒、太阴病腹满时痛、少阳病往来寒热、少阴病初得兼表、少阴病得二三日、少阴病心中烦、不能食而无表证、纯出血无气分证 等
- 治法/病机表述（3）：解肌调营卫、发阳宣肺、发汗伤心阳

**判据不是「像不像治法」，而是「接诊时医生能不能观察到」**：

- `发汗后腹胀满`、`发汗太过`、`发汗后脐下悸` → **保留**。这些是坏病病程的可观察事实，正是《伤寒论》里厚朴生姜半夏甘草人参汤、桂枝甘草汤的原始指征。实测「发汗后腹胀满，纳呆」→ 该方第 1 名，命中的就是这个词，剔掉会丢真信号。
- `太阳伤寒`、`解肌调营卫` → **移出评分位**。前者是结论，后者是治疗主张。

**移出不等于删除**，按用途分三个位：

| 词类 | 可用于 | 不可用于 |
|---|---|---|
| 患者可观察事实 | M02/M03 前的候选评分 | — |
| 诊断标签 | M03 **之后**的一致性复核 | 候选评分 |
| 治法/病机表述 | 病机—治法—方剂链验证 | 候选评分 |

## 五、影子层不得占用 M03 时间预算（本版新增）

实测线上 M03 耗时：27s / 29s / 30s / 33s / **161s**，总时限 180s——最坏一例已用掉 **89%**。

若让模型在 M03 契约里多填一段 `syndromeFrameworks`，等于在这条已经很紧的预算上再加输出，而 `[TRUNCATED]` 是本仓库付过代价的老问题。因此：

- 服务端确定性部分（`evidenceStatus` / `derivedReadiness` / 分层评分）**零模型调用**；
- `modelProposal` 若确需模型给，**走带外独立调用**：不进 M03 契约、不占 M03 时限、失败即静默留空。

## 六、修订后的任务与顺序

复审的排序建议正确：**先有基线，再谈改进**。

| 序 | 任务 | 内容 | 依赖 |
|---|---|---|---|
| **1** | **T2′ 反事实基线** | 单变量翻转，指标用 **BTR**（基础病例答对前提下反事实答错的条件概率）。先跑**改动前**表现存档；
**基线病例从 L2 抽取并封存**——一旦作为对照发布就不得再用于定位缺陷，否则前后对照本身被污染 | 无 |
| **2** | **T0′ 词表分位** | 14 个词按用途移出评分位；节点与边两张表同步；`againstTerms` 复用不新造 | 无 |
| **3** | **T1′ 影子排名** | 分层评分与现行排序**并行计算**，仍把现行排序交给 M03；只记录差异 | T2′ 基线 |
| **4** | **T3′ 影子框架评估** | 三分类 + 服务端算 `evidenceStatus`/`derivedReadiness`；不强制单一 organizing | T1′ |
| **5** | 中医师复核影子误判 | 抽样复核，定误报率 | T3′ 数据 |
| **6** | 决策点 | 依据数据决定是否让影子层影响 M02/M03 | 上一步 |
| 后置 | T4′ 追问回路 | **需新建回路**（无现成通路），工作量已上调 | 决策点通过 |
| 后置 | T5′ 鉴别边补全 | 中医师工作包；**数据源改为 L1 开发可见集** | T2′ 数据 + T7′ |
| 可并行 | **T7′ 外部评测集接入 + 回归用例分层** | 见 `docs/外部评测集接入与回归用例分层-20260815.md`：
许可证核实 → evaluationOnly 模式接入 → L1/L2/L3 按「谁能看」分层 + 流转登记。
**外部标注不直接进知识库**（我们 GB/T 16751.2-2021 vs TCM-SD 的 GB/T 15657-1995，差 26 年；
且会破掉「国标定义只存 SHA-256 不复制原文」的既有版权纪律；证据等级也更弱）。 | 无 |

### 第一阶段只记录这五项

1. 新旧 Top-K 排名差异；
2. 正确方是否进入更高层；
3. 反证方是否降层；
4. 新排序与 M03 最终选方是否更一致；
5. **是否出现「排序改善但最终选方不变」**。

第 5 项最要紧：M03 还受另一套经典方检索影响，**不能把影子排序改善直接宣称为临床质量提升**。这条是复审提的，我完全同意——它正是「证明新增字段能输出」与「证明临床质量提高」的分界。

| 任务 | 验收 |
|---|---|
| T2′ | 第一批 5 组变量 ×3 次重复，BTR 与稳定率成表落盘；改动前基线独立存档 |

## 八、已知风险与未决

1. **词表分档需中医师终审。** 14 个词的重分类我可以给候选，但 `decisive` / `supporting` / `shared` 的分档**不经终审不进硬判据**，只作影子排序提示。
2. **中医领域无单变量反事实评测先例**（公开可检索来源内未查到；CNKI/万方本次访问不到，建议补检）。BTR 的形态借自 MamaBench（arXiv:2607.14385，非中医），其结论「base accuracy 比 robust accuracy 高估 16–28 个百分点」是做这项测试的理由，但**该数字不能直接外推到中医**。
3. **T1′ 的先例是专病**。CHD-SEDD LLM（中国实验方剂学杂志 2025;31(19)）报告逻辑冲突率 37%→4%，但覆盖面是冠心病心绞痛 8 要素 6 证候，通用八纲/六经要我们自己铺。
4. **影子审计的事实 ID 稳定性未验证**。隔离原则第 5 条要求只存事实引用 ID，但当前规范化临床事实是否有跨轮次稳定 ID，需要在 T3′ 开工前先查——查不到就得先补 ID，否则审计无法回溯。
