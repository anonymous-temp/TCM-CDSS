## 0. 产品定位与法律边界（集成前必读）

本系统是**建议性**（advisory only）中医临床决策支持工具，不是处方系统。

- 所有输出均为**候选建议**，必须由医生逐项确认后才能进入院内处方流程；
- 系统**永不**输出可直接执行的最终处方：`writeBackPolicy.finalPrescriptionReleaseAllowed` 恒为 `false`，
  `autoWriteDiagnosis` / `autoWritePrescription` 恒为 `false`；
- 每条结论都可追溯到患者事实、确定性规则命中或知识库/证据条目，否则显式标注"证据不足/待检索"；
- 安全层为**确定性**（非模型判定），处置采用**提示不拦截**（advise）语义：红旗、危急体征、
  信息完整度、就诊目标等判定照常执行并全部呈现，但不阻断流程——命中时照常返回完整辨证与
  候选方药，并在可见正文**最前**置入安全警示横幅（见 §4.5）。集成方必须把该横幅原样展示给
  医生，且不得在横幅未解除时把候选内容自动写入处方系统；
- 运维可通过环境变量 `CDSS_GATE_DISPOSITION=block` 切回旧的 fail-closed 拦截行为（整机开关，
  不需要改代码或重建镜像；默认值为 `advise`）。

集成方在 UI 上必须保留：医生逐项采纳入口、风险提示展示、以及"需药师复核"标识。

## 1. 接入与鉴权

### 1.1 鉴权方式

所有 `/api/*` 接口均需鉴权（`/api/auth/access` 本身除外），二选一：

| 方式 | 请求头 | 适用对象 |
|---|---|---|
| 专用 token 头 | `x-cdss-api-token: <API_TOKEN>` | 服务端到服务端集成（推荐） |
| Bearer | `Authorization: Bearer <API_TOKEN>` | 同上 |

Token 由我方单独提供（不在本文档内）。

| 状态 | 触发条件 | 响应体 |
|---|---|---|
| `401` | 未携带 token 或 token 错误 | `{"error":"Unauthorized"}` |
| `429` | 同一来源未鉴权请求失败 20 次 / 10 分钟，锁定 10 分钟 | `{"error":"Too many unauthorized API requests"}`，带 `Retry-After` 头 |
| `503` | 服务端 `CDSS_API_TOKEN` 未配置或短于 16 字符 | `{"error":"CDSS_API_TOKEN must be configured with at least 16 characters before exposing API endpoints"}` |

### 1.2 浏览器登录（仅 UI 场景）

`POST /api/auth/access`（无需预先鉴权）

**入参**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | 是 | 访问口令，最长 512 字符（超长部分截断）。请求体上限 4 KB |

**出参**

| 场景 | 状态 | 响应体 |
|---|---|---|
| 成功 | `200` | `{"ok":true}`，并种下 httpOnly Cookie `tcm_cdss_ui_access`（12 小时有效） |
| 鉴权关闭（开发环境） | `200` | `{"ok":true,"authRequired":false}` |
| 口令错误 | `401` | `{"ok":false,"error":"访问口令不正确"}` |
| 失败过多 | `429` | `{"ok":false,"error":"访问尝试过多，请稍后再试"}`，带 `Retry-After` 头；10 分钟内失败 8 次锁定 10 分钟 |
| 服务端未配置 token | `503` | `{"ok":false,"error":"CDSS_API_TOKEN is not configured"}` |

API 集成**不需要**走这一步。

### 1.3 Cookie 会话的跨站防护（仅影响浏览器直连）

以 Cookie（而非 token 头）鉴权的**变更类**请求（POST/PUT/PATCH/DELETE）附加同源校验：

| 状态 | 触发条件 |
|---|---|
| `403 {"error":"Forbidden"}` | `Origin` 与站点不同源；或 `Sec-Fetch-Site` 非 `same-origin`/`none`；或两个头都缺失 |
| `415 {"error":"Unsupported Media Type"}` | `Content-Type` 既非 `application/json` 也非 `multipart/form-data` |

携带 `x-cdss-api-token` / `Bearer` 的服务端调用**不受**本节影响。

### 1.4 限流

| 维度 | 限制 | 说明 |
|---|---|---|
| 模型调用类接口 | 默认 60 次 / 10 分钟（`CDSS_MODEL_RATE_LIMIT_PER_10_MIN`，可配置区间 [10, 2000]，超范围钳到边界） | 按会话/API 租户身份计数。命中路由：`collect`、`question`、`question/interpret`、`diagnose`、`prescribe`、`assess`、`red-flags`、`post-prescription-risk`、`his-scheme`（共 9 条，均为 POST） |
| 未鉴权 API 请求 | 20 次失败 / 10 分钟后锁定 10 分钟 | 见 §1.1 |
| 登录失败 | 8 次 / 10 分钟后锁定 10 分钟 | 见 §1.2 |
| `model-health?check=1` | 6 次 / 10 分钟 | 真实模型探测的独立配额 |

超限返回 `429`，均带 `Retry-After` 头；模型调用类另带 `X-RateLimit-Limit` / `X-RateLimit-Remaining` 头，
响应体 `{"error":"Model invocation rate limit exceeded for this session or API tenant"}`。

限流按调用方身份计数（API token 租户 / UI 会话），是**进程内计数、单实例假设**；生产部署位于
终止 TLS 的反向代理之后，以代理透传的真实来源为准。水平扩容会使实际限额成倍放大，扩容前需联系我方调整。

### 1.5 请求体限制与通用 4xx

统一 JSON。除下表特例外，单请求体上限 **1 MB**：

| 接口 | 请求体上限 |
|---|---|
| 业务接口（caseState 类）默认 | 1 MB（1,000,000 字节） |
| `collect` | ≈5.6 MB（含 base64 舌象图片） |
| `snapshot` | 3 MB（明文快照上限 2 MB） |
| `auth/access` | 4 KB |
| `tcm-knowledge/search` | 30 KB |
| `tcm-knowledge/herb-function` | 2 KB |

| 状态 | 触发条件 | 响应体 |
|---|---|---|
| `413` | 超过上限 | `{"error":"Request body too large; limit is <N> bytes"}` |
| `400` | 非法 JSON | `{"error":"Invalid JSON body"}` |
| `400` | 缺 `caseState` | `{"error":"caseState required"}` |
| `400` | `caseState` 不是对象 | `{"error":"caseState must be an object"}` |

## 2. 核心数据结构

### 2.0 请求体总形态

除健康检查、知识库检索、登录、快照外，所有业务接口的请求体统一为：

```json
{ "caseState": { /* CaseState，见 2.1 */ } }
```

> ### ⚠️ 集成第一必读：`caseState.id` 必须由调用方提供且全程不变
>
> M03/M04 的结构化结果带**服务端 HMAC 签名**，签名绑定 `caseState.id` + 就诊号
> （`hisRecord.caseId`，缺省时等于 `caseState.id`）+ 脱敏后的临床输入哈希；M04 签名额外绑定
> 所引用 M03 合同的哈希。签名密钥属于部署环境。
>
> - 请求体**不带 `id`** 时，服务端每次会生成新的临时 id，M03 阶段签进签名的 id 与 M04 阶段重新
>   生成的 id 不一致，M04 必然返回 `409 辨病辨证结果缺少有效签名`；
> - 因此：**在 M02 之前生成一个稳定 id（建议用就诊号，如 `enc-20260803-0001`），并在同一病例的
>   全部阶段调用中原样携带**；
> - 同理，签名与**部署环境密钥**绑定：测试环境生成的 M03 结果不能拿到生产环境继续调 M04；
> - M03/M04 之间修改会进入"临床输入哈希"的病历字段（主诉/病史/四诊/体征等）同样会使签名失效——
>   需要补充信息时，先改病历、重跑 M03，再进 M04。

### 2.1 CaseState 全字段详表

#### 2.1.1 顶层字段

| `vitals` | object | 建议 | 生命体征。常用键：`temperature`/`pulse`/`respiration`/`bloodPressure`（别名 `T`/`P`/`HR`/`R`/`RR`/`BP` 等亦被识别）、`detail`。`hisRecord.fields.vitals*` 优先生效；顶层与 HIS 不一致时服务端记录 `sourceConflicts` 并触发补录提示 |

#### 2.1.3 completeness（信息完整度）

| 字段 | 类型 | 说明 |
|---|---|---|
| `level` | `"A"｜"B"｜"C"` | **服务端按四维分数重算并覆盖提交值**：`redFlag≥0.7` 且其余三维 `≥0.6` ⇒ C；任一维 `<0.3` ⇒ A；否则 B |
| `redFlag` | number 0–1 | 红旗信息充分度（门槛最高的维度） |
| `infoGain` | number 0–1 | 信息增益 |
| `managementImpact` | number 0–1 | 处置影响 |
| `answerability` | number 0–1 | 可回答性 |

completeness 等级用于表达置信范围：非 C 级仍可跑 M03（有限信息推理），但 M04 剂量级放行要求 C 级

### 3.1 语义红旗预检

`POST /api/diagnosis/red-flags`（鉴权必需；计入模型限流）

**功能**：在正式推理前完成语义红旗筛查，返回红旗事实与安全门快照。

**强烈建议先调用本接口，并把返回的 `clinicalFacts` 放回 caseState 后续传递**——各阶段按
`sourceFingerprint` 内容指纹命中缓存，可避免重复模型调用；不回传时每个阶段都会重跑，一次瞬态
失败即触发该阶段 fail-closed 降级为非剂量输出。

**入参**

| 字段路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseState` | object | 是 | 见 §2.1。本接口最少需要 `id` + 病历内容（`chiefComplaint`/`hisRecord`） |

**出参**（`application/json`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `available` | boolean | 语义预检结果是否可用（= `semanticStatus` 与 `reviewStatus` 均为 `checked` 且有 `attestation` 签名；确定性危急体征短路分支恒为 `true`） |
| `semanticStatus` | `"checked"｜"unavailable"｜"skipped_deterministic_critical_vital"` | `skipped_deterministic_critical_vital`：确定性危急生命体征已触发红旗，语义层跳过（不需要模型即可判定） |
| `clinicalFacts` | object ｜ null | 语义红旗事实（§2.1.4），**原样回传** |
| `safetyGate` | object | 安全门快照（§2.1.5） |
| `latencyMs` | number | 本次处理耗时（毫秒） |

**错误**：仅通用错误（§1.5、§5）。语义层不可用不是错误——`available=false` + `semanticStatus="unavailable"` 正常返回，
此时 `clinicalFacts.unavailableReason` 说明原因，后续阶段会按 fail-closed 口径处理。

**示例**

```bash

  -d '{"caseState":{"id":"enc-20260803-0001","chiefComplaint":"反复胃脘胀痛3月，加重1周",
       "hisRecord":{"caseId":"enc-20260803-0001","rawText":"患者男，45岁。反复胃脘胀痛3月……",
         "fields":{"sex":"男","age":"45","zhushu":"反复胃脘胀痛3月，加重1周"}}}}'
```

关键出参片段：

```json
{
  "available": true,
  "semanticStatus": "checked",
  "clinicalFacts": { "redFlags": [], "encounterScope": {"status":"active_current_target","quote":"…"},
                     "sourceFingerprint": "…", "attestation": "…" },
  "safetyGate": { "status": "needs_information", "allowDiagnosis": true, "allowDosePrescription": false,
                  "action": "complete_before_prescription", "missingItems": ["过敏史"], "redFlags": [], "reasons": ["…"] },
  "latencyMs": 3200
```

### 3.2 M01 病历采集 / 舌象识别

`POST /api/diagnosis/collect`（鉴权必需；计入模型限流；请求体上限 ≈5.6 MB）

**功能**：提交病历文本与可选舌象照片。纯文本时为**确定性**响应（不调用模型）；带舌象图片时走
GLM 视觉模型输出舌象描述。

**入参**（注意：本接口不是 `caseState` 包装，是独立请求体）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `userInput` | string | 是 | 病历文本，≤12000 字符 |
| `patientSex` | `"男"｜"女"｜"其他或未明确"` | 是 | 性别/生理状态（服务端 M01 必填契约） |
| `tongueImage` | string | 否 | 舌象照片 data URL：`data:image/(png|jpeg|jpg|webp);base64,...`，二进制 ≤4 MB（base64 ≤5,600,000 字符），文件头需与 MIME 一致 |
| `tongueImageConsent` | boolean | 有图时必填 | `true` = 已取得患者授权将舌照外发分析 |

**出参**：NDJSON 流（§4.1）。

- 纯文本：确定性单帧正文 `"病历信息已采集，正在评估是否需要补充关键问诊。"` + 空结构化 JSON
  sentinel（`{}`），随后 `[END]`；
- 带舌象图片：GLM 视觉流式输出舌象描述文本（用于回填 `caseState.tongueImageDesc` / 手工核对）。

**错误**

| 状态 | 触发 | 响应体 |
|---|---|---|
| `400` | 缺 `userInput` | `{"error":"userInput required"}` |
| `413` | 文本 >12000 字符 | `{"error":"病历文本过长，请压缩至12000字以内后再提交"}` |
| `400` | 图片超限 | `{"error":"舌象图片过大，请压缩至4MB以内"}` |
| `400` | 有图未授权 | `{"error":"舌照外发分析前需确认已取得患者授权。"}` |
| `400` | 性别缺失/非法 | `{"error":"…required…","code":"required_field_missing","field":"sex"}` |
| `400` | 图片格式不符 | `{"error":"舌象图片格式不支持，请上传PNG/JPEG/WebP位图"}` |
| `503` | 视觉服务未配置 | `{"error":"舌照识别服务未配置，请先手动录入舌象后再提交。"}`（**无静默降级**） |

### 3.3 M02 追问生成

`POST /api/diagnosis/question`（鉴权必需；计入模型限流）

**功能**：生成高信息增益追问（**单轮决策**，`maxQuestionRounds` 服务端恒为 1）。追问为**非阻断**：
医生可回答后重跑，也可置 `skipDifferentiationGate=true` 直接进入 M03。

**入参**

| 字段路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseState` | object | 是 | 见 §2.1 |
| `caseState.chiefComplaint` 或 `hisRecord.fields.zhushu` | string | 是 | 缺失时 `422` |
| `caseState.phase` | `"question"` | 是 | 非 `question` 时 `409` |
| `caseState.questionRounds` | number | — | 已 ≥1 时 `409`（本轮追问已结束） |

**出参**：NDJSON 流。最终正文 = 可见追问文本 + sentinel 之间的 **M02 计划 JSON**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | `"tcm-cdss-m02-plan-v1"` | 固定 |
| `decision` | `"ask"｜"proceed"` | 是否需要追问 |
| `rationale` | string | 决策理由 |
| `questions` | array | 追问列表（`decision="proceed"` 时为空） |
| `questions[].id` | string | 问题 id（回答解析时引用） |
| `questions[].question` | string | 问题文本 |
| `questions[].reason` | string | 提问理由（中性化措辞，不预设证型/方药） |
| `questions[].targetField` | 枚举 | 回答落库目标字段：`xianbingshi`、`jiwangshi`、`allergyHistory`、`medicationHistory`、`vitalsDetail`、`tcmFace`、`tcmTongue`、`tcmPulse`、`tcmDetail`、`fuzhuJiancha` |
| `questions[].decisionBranch` | `"triage"｜"differential"｜"syndrome"｜"treatment_safety"` | 决策分支 |
| `questions[].expectedDecisionImpact` | string | 预期决策影响 |
| `questions[].informationGain` | number | 信息增益评分 |
| `questions[].sourceEvidence` | string[] | 病历原文接地引文 |
| `questions[].options` | array | 选项：`{id, label, answer, kind:"clinical_fact"｜"other"｜"unknown", recordValue?, requiresDetail?}`。`unknown`=本次未取得该信息（不写病历）；`other`=取得了信息但预设分支不合适，医生自行输入（写病历） |

**错误**

| 状态 | 响应体 |
|---|---|
| `422` | `{"error":"请先填写主诉，再生成本轮关键追问。"}` |
| `409` | `{"error":"当前流程不在追问阶段，请从现有阶段继续。"}` |
| `409` | `{"error":"本轮追问已结束，请按已提供信息进入辨病辨证。"}` |

模型流异常时服务端回落**病例感知的确定性追问兜底**（仍是合法 M02 计划），不返回错误。

### 3.5 M03 辨病辨证

**功能**：西医诊断倾向 + ICD-10 编码、中医病名、证候诊断、病机链、治法框架、证据链；末尾嵌入

行为要点（advise 处置档）：

- 红旗病例**照常完整辨证**，横幅置顶 + 管理建议把急诊/转诊列为第一优先级；

### 3.6 M04 候选方药

`POST /api/diagnosis/prescribe`（鉴权必需；计入模型限流）

**功能**：基于签名 M03 生成剂量级候选方药（药味/剂量/君臣佐使/病机绑定/功用、煎服法、

**非剂量降级**：正文以 `<!-- CDSS_NON_DOSE_PRESCRIPTION -->` 开头时，表示本次不提供剂量级候选，
原因见正文"处方安全边界"段。advise 默认档下这种情况只剩三类——缺主诉、缺有效 M03 签名结果
（含 M03 为"未形成证候+空病机链"的有限合同）、模型输出截断到无候选可回收——均可通过重试或
补齐调用序列恢复，不是错误。安全/完整度类命中不再走此降级，而是正常出方 + §4.5 安全警示横幅。

**确定性方剂参考页（非剂量降级的增强形态）**：模型输出不可回收但 M03 已锁定受治理经典方时，
非剂量页会携带该方的**确定性参考数据**（"### 方名（出处）" + 药味表：药典剂量区间/特殊煎法 +
毒性/管制味的监管扣除说明）。该表全部来自本地受治理知识库、不含模型生成内容；剂量列为
**药典边界区间而非本例建议量**，用量由医师确定并经审方复核。集成方可原样渲染该 Markdown 表；
它不携带结构化 M04 载荷与签名，不可作为候选采纳，仅供医生参考定量后重新生成。

**质量批注**：正文首段出现"…已完整通过安全核验；…请…核对后再采纳"这类提示时，表示药味、剂量、
配伍禁忌、特殊人群与君臣结构的确定性核验**全部通过**，但独立复核对方义、方药-病机对应关系或
患者信息完整度仍有保留意见。此时处方**可用**，但集成方应当把该段原样展示给医生，不得隐藏。

**原方毒性/管制药味的处理**：所引经典方原组成含毒性、管制或濒危药材（朱砂、雄黄、麝香、轻粉等）
时，系统**不为其编制用量**，该味不进入药味清单，其余药味照常给出剂量；正文会写明"原方含但本次
不编制用量的药味"。这类药材需由医师按监管要求单独开具并经院内审方复核。方义本身落在毒性药味上
的方剂（如安宫牛黄丸），整方仍不进入剂量编译，只保留方名方向。

**用量核验级别**：药味清单中的成分带 `verificationTier` 标注（枚举与含义见 §2.3 herbs 表）。
四类均照常提交灵犀审方。

**锁定方缺剂量基准（advise 档）**：M03 推荐方在本地受治理知识库暂无可执行逐味剂量基准时，
本次候选转为**辨证自拟组方**（`constructionType="self_devised"`，不沿用该方名身份），方名方向
保留在警示横幅中供医生参考。

典型时延 **20–60 秒**。客户端超时建议 **≥180 秒**。

**错误**

| 状态 | 触发 | 响应体 |
|---|---|---|
| `409` | `reasoningDiagnose` 缺失、签名无效或内容被改 | `{"error":"辨病辨证结果缺少有效签名，请重新生成辨病辨证后再进入候选方药。"}` |
| 其余 | 通用错误与流内 `{"error":...}` | §5 |

### 3.7 M05 风险随访

`POST /api/diagnosis/assess`（鉴权必需；计入模型限流）

**功能**：处方后风险汇总与随访计划。汇总本身**完全确定性**（消费灵犀审方结果 + 本地高危药对
规则，不经模型生成正文；仅临床事实回补层在缓存未命中时可能发生模型调用）。

**入参**

| 字段路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseState` | object | 是 | 见 §2.1 |
| `caseState.reasoningPrescribe` | object | **是**（常规链路） | M04 签名结果，**原样回传**；缺失/被改 ⇒ `409 invalid_m04_signature` |
| `caseState.prescription` | string | 是 | M04 可见正文 |
| `caseState.prescriptionRevision` | object | 否 | 医生工作台修订链路：提供 `source="herb_workbench"` 时改为校验 **M03** 签名并按 `candidateIndex` 审所选候选方 |

**出参**：NDJSON 流（确定性，一次性下发）。内容按序为：

1. 审方状态标记 `<!-- TCM_CDSS_RXAUDIT_STATUS:... -->`（§4.7）；
2. 审方关联标记 `<!-- TCM_CDSS_RXAUDIT_CORRELATION:<urlencoded-json> -->`（§4.7）；
3. 审方范围、录入质量提示、灵犀风险分级段（或审方不可用说明 + 本地高危药对独立提示）；
4. 确定性随访计划；
5. 流内另有一帧 `{"type":"followup_timeline","timelineItems":[...]}` 结构化随访时间轴（§4.1），
   条目 `{time, action, indicators[], triggers[]}` 可直接回填 `caseState.followupTimeline`。

审方不可用时 **fail-closed**：正文明确"不能等同于无风险，需医生/药师人工复核"，不会静默放行。

**错误**

| 状态 | `code` | 触发 |
|---|---|---|
| `409` | `invalid_m03_signature` | 工作台修订链路下 M03 签名失效 |
| `409` | `invalid_m04_signature` | 常规链路下 M04 签名缺失/失效/被改 |
| `422` | `invalid_candidate_index` | 所选候选方不存在或无结构化药味 |
| `422` | `invalid_structured_herb` | 药味名称、单一正数剂量（g/克/mg/毫克）、对应病机或功用不完整 |
| `422` | `invalid_edited_prescription_<issue>` | 编辑后的处方未通过语义校验（`issue` 为具体原因码） |

### 3.10 急症排查确认

`POST /api/diagnosis/emergency-clearance`（鉴权必需；不计模型限流）

**功能**：医生完成现场急症排查后取得**签名留痕**。该留痕只对当前红旗事实指纹有效——病历中的
红旗证据变化后自动失效，不能作为全局关闭急症规则的开关。

**入参**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseState` | object | 是 | 当前病例状态（必须实际处于 `red_flag` 安全门状态） |
| `assessmentSummary` | string | 是 | 现场评估/急诊排查记录，脱敏后至少 12 字（上限 1000 字） |

**出参（`200`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `emergencyClearance.redFlagFingerprint` | string | 当前红旗事实指纹 |
| `emergencyClearance.confirmedAt` | string | 确认时间（ISO） |
| `emergencyClearance.assessmentSummary` | string | 脱敏后的评估记录 |
| `emergencyClearance.contractSignature` | string | `"hmac-sha256:"+64hex` 服务端签名 |

将整个对象放入 `caseState.emergencyClearance` 后续回传。

**错误**

| 状态 | `code` | 触发 |
|---|---|---|
| `400` | `invalid_emergency_clearance_request` | 缺 `caseState` 或 `assessmentSummary` |
| `409` | `no_active_emergency_finding` | 当前病历没有可绑定的急危重红旗 |
| `400` | `emergency_assessment_too_short` | 评估记录不足 12 字 |
| `503` | `emergency_clearance_signing_unavailable` | 服务端签名密钥未配置 |

### 3.11 受控术语确认

`POST /api/diagnosis/terminology/confirm`（鉴权必需；不计模型限流）

**功能**：医生显式确认 M03 载荷中 `status="suggested"` 的**主证候**或**主 ICD-10** 术语映射。
确认后返回**重新签名**的 M03 载荷；若 M03 存在 `deferredFormulaSelection`（选方待确认），
一并恢复 `recommendedFormulaNames`。

**入参**

| 字段路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseState` | object | 是 | 携带待确认的签名 `reasoningDiagnose` |
| `mapping.namespace` | `"tcm_syndrome"｜"icd10"` | 是 | 仅这两个命名空间可经本接口确认 |
| `mapping.fieldPath` | string | 是 | 与 `terminologyMappings[]` 中目标条目一致 |
| `mapping.candidateId` | string | 是 | 同上 |

**出参（`200`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `reasoning` | object | 更新并**重新签名**的 M03 载荷（对应条目 `status` 变为 `clinician_confirmed`）。用它替换 `caseState.reasoningDiagnose` |
| `restoredFormulaNames` | string[] | 因确认而恢复的锁定方名（无则为空数组） |
| `prescriptionMustBeRegenerated` | `true` | 恒为 true：确认后**必须重新生成 M04** |

**错误**

| 状态 | `code` | 触发 |
|---|---|---|
| `400` | `invalid_terminology_confirmation_request` | 缺 `caseState` 或 mapping 三元组 |
| `400` | `terminology_confirmation_target_not_allowed` | namespace 不是 `tcm_syndrome`/`icd10`，或 fieldPath 非主字段 |
| `409` | `invalid_m03_signature` | 当前 M03 合同缺失/过期/无效 |
| `409` | `terminology_suggestion_not_current` | 指定映射条目不存在或已非 `suggested` 状态 |

### 3.12 病例快照

`POST /api/diagnosis/snapshot`（鉴权必需；不计模型限流；请求体上限 3 MB，明文快照上限 2 MB）

**功能**：AES-256-GCM 加密/解密病例状态快照。加密**绑定鉴权主体**（部署访问凭据）与调用方
提供的工作区绑定值：换绑定值、换 token 主体或换部署环境都解不开。

**入参**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | `"encrypt"｜"decrypt"` | 是 | 操作 |
| `binding` | string | 是 | 集成方自定义工作区标识经 SHA-256 后的 **64 位十六进制**串（进 AAD） |
| `payload` | any | encrypt 时必填 | 任意病例状态 JSON（序列化后 ≤2 MB） |
| `envelope` | object | decrypt 时必填 | 加密封套，**原样回传**，字段见下 |

**加密封套 `envelope`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | `"tcm-cdss-encrypted-snapshot-v1"` | 固定 |
| `algorithm` | `"A256GCM"` | 固定 |
| `iv` | string | base64（12 字节 → 16 字符） |
| `ciphertext` | string | base64 密文（≤3 MB 字符） |
| `authTag` | string | base64（16 字节 → 24 字符） |
| `updatedAt` | string | ISO 时间 |

**出参**

- encrypt：`{"ok":true,"envelope":{...}}`
- decrypt：`{"ok":true,"payload":{...}}`

**错误**

| 状态 | 响应体 `error` | 触发 |
|---|---|---|
| `503` | `病例快照加密密钥未配置` | 服务端 `CASE_SNAPSHOT_ENCRYPTION_KEY` 缺失/过短 |
| `503` | `病例快照访问凭据未安全配置` | 访问 token <16 字符 |
| `401` | `未授权的病例快照请求` | 鉴权失败 |
| `413` | `病例快照请求超过大小限制` / `病例快照超过大小限制` | 请求体 >3 MB / 明文 >2 MB |
| `400` | `无效的病例快照请求` | action 非法（含空体调用） |
| `400` | `病例快照缺少有效的工作区绑定` | binding 非 64 位十六进制 |
| `400` | `无效的加密病例快照` | envelope 结构非法 |
| `400` | `病例快照校验失败，已拒绝恢复` | 解密/认证失败（含换绑定、换主体、密文被改） |

#### 3.14.2 `GET /api/model-health[?check=1]`（鉴权必需）

- 不带 `check`：`200 {"module":"text-model","status":{provider,providerId,model,configured,transportAllowed,disabledReason},"diagnosis":{…},"audit":{…},"liveCheck":"append ?check=1 to call the configured provider"}`；

  `{"module":"text-model","liveCheck":{ok,…},"clinicalReview":{ok,…}}`；任一失败整体 `502`；

```bash
curl -s "https://82.156.128.153/tcm-cdss/api/diagnosis/health?strict=1" \
  -H "x-cdss-api-token: <API_TOKEN>"
```

## 4. 流式响应契约

### 4.1 NDJSON 帧格式（帧级字段说明）

流式接口（M01 collect、M02 question、M03 diagnose、M04 prescribe、M05 assess）返回
`Content-Type: application/x-ndjson; charset=utf-8`，逐行一个 JSON 对象：

```
{"type":"heartbeat","status":"正在连接模型服务，服务保持响应","processedChars":0}
{"content":"## 本次分析结论\n"}
{"content":"**结论**：肝胃不和证\n"}
{"content":"[END]"}
```

| 帧 | 字段 | 说明 |
|---|---|---|
| 正文帧 | `content: string` | 正文分片，按顺序拼接 |
| 结束帧 | `content: "[END]"` | **流正常结束标记**（字面量，恒为最后一帧） |
| 错误帧 | `error: string` | 错误；此时不应采纳任何已接收内容 |
| 心跳帧 | `type:"heartbeat"`, `status: string`, `processedChars: number` | 约每 5 秒一次，`status` 为人读进度文案（"模型正在进行深度推理"等），`processedChars` 为已处理字符数。**不拼入正文** |
| 随访时间轴帧 | `type:"followup_timeline"`, `timelineItems: [{time, action, indicators: string[], triggers: string[]}]` | 出现在 M05 等确定性响应中，结构化随访时间轴（≤8 条），可直接回填 `caseState.followupTimeline` |

**兼容性约定**：带 `type` 字段且类型不认识的帧**必须忽略**（向前兼容）；客户端必须以 `[END]`
判定完成——未见 `[END]` 即连接中断，视为失败。

### 4.2 进度替换标记

流中可能出现 `<<<CDSS_STREAM_FINAL>>>`。该标记**之前**的内容是过程提示（如"正在校对…"），
**之后**才是最终权威正文。

正确处理：

```js
const marker = "<<<CDSS_STREAM_FINAL>>>";
const idx = fullContent.lastIndexOf(marker);
const visible = idx >= 0 ? fullContent.slice(idx + marker.length) : fullContent;
```

### 4.3 结构化结果提取

M02/M03/M04 的最终正文中嵌入结构化 JSON：

```
<!-- DIAGNOSIS_JSON_START -->
{ "schemaVersion": "tcm-cdss-reasoning-v2", "stage": "diagnose", ... }
<!-- DIAGNOSIS_JSON_END -->
```

- M02 的 sentinel 之间是 M02 计划（`tcm-cdss-m02-plan-v1`，§3.3）；
- M03/M04 的 sentinel 之间是推理载荷（`tcm-cdss-reasoning-v2`，§2.2/§2.3）；
- 提取后作为 `reasoningDiagnose` / `reasoningPrescribe` **原样**回传给下一阶段；
- **不要修改任何字段**——其中含服务端签名，改动即 `409`。

### 4.4 心跳与超时

服务端每 5 秒发送心跳帧保持连接。单次流的服务端限制：连接 90s / 空闲 60s / 总计 180s；
M03 编排总时限默认 180s、M04 默认 120s（均可运维配置，钳制区间 60–180s）；舌象视觉总时限默认 120s。

**客户端建议超时：M03 ≥240s，M04 ≥180s，M05 ≥120s。**

### 4.5 安全警示横幅（必须实现）

命中红旗、危急体征、就诊目标未确认等确定性判定时，M03/M04 的可见正文**最前**会出现：

```
<!-- CDSS_SAFETY_ADVISORY -->
> ⚠️ **安全警示（未解除，请医生优先处置）**
> - 红旗提示：……
> - ……
> - 以下分析与候选方药仅供医生在完成上述风险处置判断的前提下参考，采纳前须经院内审方复核。
```

集成方约定：

1. 用稳定标记 `<!-- CDSS_SAFETY_ADVISORY -->` 检测其存在（标记后到首个 `## ` 标题前的引用块即横幅内容）；
2. 横幅必须以**最高显著级别**原样展示给医生，不得折叠、截断或延后；
3. 横幅存在时，候选内容不得被自动写入院内处方系统——采纳动作必须由医生显式发起；
4. 横幅之后可能还有**质量批注**段落（普通段落，含"已完整通过安全核验……请……再采纳"措辞），
   同样应在结果区显著呈现；
5. 横幅与批注都在首个 `## ` 标题之前——按节抽取渲染的集成方必须单独处理这段前置区，
   否则会把服务端警示静默丢弃。

### 4.6 非剂量降级标记与质量批注

- `<!-- CDSS_NON_DOSE_PRESCRIPTION -->` 出现在 M04 正文最前时，本次为非剂量输出（触发场景与
  确定性方剂参考页见 §3.6）。该页**不携带**结构化 M04 载荷与签名，不可作为候选采纳；
- "信息完整性边界"段（`## 信息完整性边界`）：completeness 非 C 或安全门非 ready 时的有限候选
  声明，列出待确认项——这些未知项不影响医生审阅，但不会被视为已核实事实；
- 质量批注段：见 §3.6。

### 4.7 审方状态与关联标记（M05 流内）

M05 正文最前有两个机读 HTML 注释标记：

```
<!-- TCM_CDSS_RXAUDIT_STATUS:AVAILABLE -->
<!-- TCM_CDSS_RXAUDIT_STATUS:UNAVAILABLE:NO_PRESCRIPTION_ITEMS -->
<!-- TCM_CDSS_RXAUDIT_STATUS:UNAVAILABLE:SERVICE_UNAVAILABLE -->
```

以及 `<!-- TCM_CDSS_RXAUDIT_CORRELATION:<encodeURIComponent(JSON)> -->`，解码后为关联元数据：

| 字段 | 类型 | 说明 |
|---|---|---|
| `provider` | `"lingxi-rxaudit"` | 固定 |
| `providerAvailable` | boolean | 灵犀是否可达 |
| `providerDegraded` / `providerDegradeReason` / `providerReason` | — | 降级信息 |
| `auditId` / `traceId` | string? | 审方单号/追踪号 |
| `candidateIndex` | number? | 所审候选下标 |
| `prescriptionHash` | string? | 处方版本哈希 |
| `auditedAt` | string | 审方时间 |
| `providerAuditResult` / `providerHighestRiskLevel` | 枚举? | 灵犀原始结论 |
| `effectiveAuditResult` / `effectiveHighestRiskLevel` | 枚举 | 生效结论（合并本地规则后） |
| `needManualReview` | boolean | 是否需人工复核 |

## 5. 错误码总表

### 5.1 HTTP 状态 × 场景

| 状态码 | 场景 | 处理建议 |
|---|---|---|
| `400` | 请求体非法 / 缺 `caseState` / 字段级校验失败（各接口特有 `code` 见 §3） | 检查请求体结构 |
| `401` | 未鉴权或 token 错误；登录口令错误 | 检查鉴权头 |
| `403` | 浏览器 Cookie 会话跨站请求（§1.3） | 服务端集成改用 token 头 |
| `408` | `question/interpret` 调用方取消 | 按需重发 |
| `409` | 签名缺失/内容被修改/阶段状态不符（`invalid_m03_signature`、`invalid_m04_signature`、`limited_m03_not_prescribable`、`terminology_suggestion_not_current`、`no_active_emergency_finding`、M02 阶段/轮次不符） | 重新生成上一阶段结果或校正阶段状态 |
| `413` | 请求体/字段超限（各接口上限见 §1.5） | 精简病历文本/压缩图片 |
| `415` | Cookie 会话请求 Content-Type 非法 | 用 `application/json` |
| `422` | 业务前置校验失败（缺主诉、候选/药味结构不完整、审方提交门、M02 计划/回答非法、HIS 写回校验） | 按 `code` 与 `error` 文案补齐数据 |
| `429` | 触发限流（模型调用/未鉴权失败/登录失败/健康探测，见 §1.4） | 按 `Retry-After` 退避重试 |

### 6.3 集成注意事项（必读清单）

1. **不要跳过 M03 直接调 M04**：M04 要求 M03 的签名推理结果，缺失时返回 `409`。
2. **原样回传结构化结果**：任何字段改动都会导致签名校验失败（`409`）；病历字段改动同样会使
   临床输入哈希变化——补充信息后从 M03 重跑。
3. **非剂量输出是正常行为**：安全边界触发时的 fail-closed 降级，UI 应正常展示其中的风险说明与
   补录项，而非报错。
4. **回传 `clinicalFacts`**：避免各阶段重复语义预检，显著降低时延与失败率。
5. **舌象图片**：需服务端开启 GLM 视觉能力；未配置时上传被明确拒绝（`503`），不做静默降级。
6. **单实例限流**：当前限流为进程内计数，水平扩容会使实际限额成倍放大，扩容前需联系我方调整。
7. **时延预期**：完整 M03→M04→M05 链路典型 **1–4 分钟**（M03 并行生成上线后中位约 27s + M04
   19–46s + M05 秒级）。建议集成方采用异步任务 + 前端轮询/推送，而非同步阻塞等待。
8. **忽略未知 NDJSON 帧类型**（§4.1），为后续帧类型扩展留兼容。
9. **警示横幅与前置区**（§4.5）：按节渲染时单独处理首个 `## ` 之前的内容。

## 8. 当前版本能力与已知边界

**已验证**（生产环境 `strictReady=true`）：主模型 DeepSeek V4 Flash 真实调用、独立临床复核、

**已知边界**：

- 少数病例在证候依据不足时输出"未形成可复核证候结论"并降级为非剂量建议——这是 fail-closed 的设计行为；
- 候选方药的药味数与是否锁定经典方受病历信息量影响，同一病例多次运行可能存在差异；
- 系统不提供最终处方放行能力，所有输出须经医生与药师复核；
- 限流为单实例内存计数（§1.4 说明）；
- 本地知识库剂量规则为 2020 版历史基线，现行（2025 版）核验以灵犀审方与药师复核为准（§3.13 status 字段亦如实标注）。
