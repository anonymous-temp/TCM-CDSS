## 二、v2 没看到的一处机制缺陷：四条证据绑定判据从未触发

报告观察到「190 例声明 443 个病位，只有 205 条病位证据明细；129/190 声明多于证据；54 例完全没有明细」，并判断「目前更多是结论后面放了一段证据，不是每个轴分别由哪些患者事实支持」。

**观察正确，机制现已查明**：`diagnosis-stage-contract.ts` 里的证据绑定判据全部被 `resolution === "resolved"` 门控——

```ts
if (locationResolution === "resolved") {
  if (details.length === 0) return "location_resolved_without_basis";
  if (!patientFactSourceQuote(detail.basis, ...)) return "location_resolved_basis_ungrounded";
}
```

而报告实测：**190/190 例全部是 `bounded`，没有一例达到 `resolved`**。

⇒ **这四条判据（病位 ×2、病性 ×2）在生产里一次都没触发过。** 判据写得对、位置也对，但门控条件结构性地达不到，等于不存在。

全文件共五处 `resolution === "resolved"` 门控（1227 证候 / 1249 病位 / 1272 病性 / 1328 组合 / 1884 兼收 bounded）。只有 1884 那处兼收 `bounded`，是唯一会触发的。

这是本仓库反复出现的那类缺陷的又一变体：**不是判据写错，是判据被放在一个永远走不到的分支里**。

## 三、核心归因与对应任务

### A. 分数低的三层原因要分开看

**① 约 4.51 个百分点是格式惩罚，不是临床错误。** 严格召回 66.87% vs 包含召回 89.44%，161/194 例包含召回超 80%，损失来自长短句、拆句、前缀差异。若任务1改用包含口径，总分 19.71% → 24.22%。

**② 病机/证候低分的首要原因是「映射为空」，不是判错。** 病机 150/194 例未映射到任何选项（映射后全错仅 15 例）；证候 171/194 未映射（映射后全错仅 2 例）。**98 例已完整覆盖临床事实，但病机与证候同时为 0。**

这不能靠扩字符串规则刷分——病例126 生成「卫外不固、营卫不和」，金标准「腠理不固、卫阳不固、风邪乘虚入侵」，既有同义/粒度差异，也**确实遗漏了病因层**。

**③ 安全门不是低分主因。** `needs_information` 162 例均分 19.29%，`red_flag` 31 例均分 **21.85%**（更高），完整度 B 176 例 19.42% / C 18 例 22.51%。历史医案普遍缺过敏史、用药史、现代生命体征，大量进 B 级是**预期的 fail-closed**。

### B. 临床推理的真问题：候选有了，收敛错了

这是最重要的一条——**不是想不出正确证候，是选错了主证**：

| 遗漏项 | 其中已出现在鉴别诊断里 |
|---|---|
| 热证 25 例 | **21 例** |
| 阴虚 21 例 | **13 例** |
| 寒证 16 例 | **10 例** |

典型病例106：系统已列出「肝经郁热、阴虚火旺」，最终却选了证据更弱的「心脾两虚、气不摄血」。

**这正是 v2 里 T1′（分层鉴别评分）要解决的问题，现在有了硬证据。** v2 当时的依据是「11 个候选全 score=1」，现在有了临床端的印证：正确答案在列表里，但没有竞争性裁决机制把它选出来。

其余四条推理问题：

- **根本与标证失衡**：偏抓痰/瘀/风等标实，遗漏阴虚、阳虚、命门不足等根本（病例105/85/93）；并有把特异性的阴虚阳虚退化成通用「气虚血虚」的倾向。
- **寒热虚实证据权重不稳**：由一个显眼症状直接套常见证型，不综合舌苔脉病程兼症（病例228/106/196）。
- **病因、病程阶段、当前证候混在一起**（病例101：当前风痰阻窍正确，但丢掉盛夏高热的暑邪病因与演变）。
- **多系统症状整合不足**：擅长逐条解释，弱于建立统一有主次的病机（病例228 只围绕胃脘痛，闭经/白带/舌暗只放进「不确定项」）。

### C. 结构性问题：主证兼证层级根本没建立

- **157/190（82.6%）** 把多个证候/机制全部塞进 `primarySyndrome`
- **180/190（94.7%）** `secondarySyndromes` 为空

契约里 `secondarySyndromes?: string[]` **字段本来就有**（`diagnosis-types.ts:346`），但是可选、且**没有任何判据要求填**。所以模型把「心肾阳虚，水饮凌心，瘀血内停」整串塞进主证——这会继续污染治法主次、方剂匹配和医生理解。

### D. 优先级最高的其实是运维项：独立复核不可用

- `clinicalReview=accepted` 176 例，均分 20.34%
- `clinicalReview=unavailable` **18 例，均分 13.48%**
- 其中 4 例完全 `unresolved`（病例 4、35、148、250）
- 病例 4、148 **超过 180 秒，最长 209.5 秒**

报告的优先级判断我完全同意：**补失败原因码与监控 → 有限重试/跨提供方复核 → 保持超时后 fail-closed，而不是先调术语刷分。**

补充一条报告没提的：跨厂商复核路径（`PRIMARY_CLINICAL_REVIEW_PROVIDER=bailian-qwen`）**代码已实现但从未在生产启用过**，且 prod 的 `BAILIAN_QWEN_API_KEY` 是空字符串。这 18 例正是它存在的理由。

### E. 数据集本身有噪声，不能全算系统错

- 病例150 金标准解释以「根据」截断
- 病例153 原始病历 OCR 残缺，原文写「寒邪外客」，系统判「寒邪束表」医学上合理，即使选项答案是「风邪袭肺」

结果必须分四类：**明确推理错误**（106/228）、**主次或根本遗漏**（105/85/93）、**病程范围不完整**（101）、**同义或金标准噪声**（150/153）。刷分时只应针对前三类。

## 四、新增与调整的任务

| 序 | 任务 | 内容 | 依据 |
|---|---|---|---|
| **T8′** | **独立复核可用性**（最高） | ①失败原因码细化 + 监控；②有限重试与跨提供方复核（bailian-qwen 路径实测启用）；③保持超时后 fail-closed。**不先调术语刷分** | 18/194 unavailable 均分掉 6.86pp；4 例 unresolved；最长 209.5s |
| **T9′** | **主证/兼证层级** | `secondarySyndromes` 从可选改为**有条件必填**：`primarySyndrome` 含多个证候时必须拆分；配套判据 + 提示词成对落地 | 157/190 全塞主证；180/190 兼证为空 |
| **T10′** | **证据绑定判据脱离 resolved 门控** | 病位/病性的 `*_without_basis` 与 `*_basis_ungrounded` 扩展到 `bounded`（先影子记录，不立即驳回） | 四条判据从未触发；190/190 全 bounded |
| **T1′**（升级为最高之一） | 分层鉴别评分 | 原设计不变，但**依据从「score 全为 1」升级为临床证据**：正确候选已在鉴别诊断里却未被选中（热证 21/25、阴虚 13/21、寒证 10/16） | 见 §三B |
| **T12′** | 病因 / 病程阶段 / 当前证候三分字段 | 当前 `primarySyndrome` 一个字段承担三种语义。拆成「当前核心证候」「原始病因」「病程演变」，避免二选一 | 病例101 |
| **T13′** | 解释总结长度与重点 | 生产 198 字 vs 金标准 90 字；字符召回 31.29% / 精确率 13.09%。先做长度约束，再看重点偏移 | ROUGE-L 17.31% |
| **T14′** | 评测口径双轨 | 严格召回与包含召回**同时报**，不用包含口径替换严格口径刷分——4.51pp 是格式差异，要单列不要混入 | §三A① |
| **T15′** | **剩余 89 味功效补录**（进行中） | 联网查证 + 独立复核，含易混品种与炮制品专项（川木通≠木通、关黄柏≠黄柏、煅石膏≠石膏、制草乌≠草乌…） | 库内仍缺 219/695 |

### 顺序调整

v2 原顺序是 T2′基线 → T0′词表分位 → T1′影子排名。现调整为：

1. **T8′ 复核可用性**（运维，独立于框架层，先做——它在拖累所有其他指标）
2. **T2′ 反事实基线**（不变，BTR 指标）
3. **T9′ + T10′**（结构性，改动小、可影子先行）
4. **T1′ 分层鉴别评分**（现在有临床证据支撑）
5. T3′ / T12′ / T13′
6. T4′ / T5′ / T7′ 后置不变

**T0′ 词表分位已完成**（`d55ae1b`）。
