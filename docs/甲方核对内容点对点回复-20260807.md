## 四、本轮同时修复的一类系统性缺陷（贵方未提出，但直接影响上述模块）

排查 4.1「治则未显示」时发现它不是孤例，而是**同一机制的第 6 次复发**：结构化契约里数组字段
一条不合规，整块被清空或被替换成工程占位串，且**不产生任何错误码**——因此既不触发自动修复，
也不进日志、不被门禁发现，只能靠人在生产环境肉眼看出来。

已修复的连坐点中，直接影响贵方「一、接口缺失内容」各项的有：

| 字段 | 一条不合规的后果 |
|---|---|
| 中医外治 | **整个健康调护模块一起消失**（贵方第 7、8 两项互相连坐） |
| 中成药候选 | 8 条里坏 1 条，另外 7 条一起变空，且四路信号全无 |
| 候选方药 | 备选方少一个字段，连同已完全合格的**首选方**、辨证、病机、调护一起作废 |
| 证型鉴别 / 病名鉴别 | 整段清空 |
| 流派适配 | 整块清空 |

另修复 3 处「服务端自产数据撑爆自己的字段上限」——该场景下的语义是**整段清空而非截断**：
逍遥散 8 条、小柴胡汤 7 条条文加减（上限 6）归一后剩 0 条；受控术语映射生产侧上限 24 > 契约 20，
导致**结论越完整的病例反而越拿不到国标术语**。

这一类已从「靠人发现」变为**门禁能拦**：新增 3 道结构性守卫，分别断言
「基准组成原样喂回必须核验通过」「注入 1 条不合规 + N 条合规后必须剩 N 条」
「服务端写入上限必须 ≤ 契约上限（从契约内省取值，不手抄常量）」。三道守卫均已验证「不修就红」。
