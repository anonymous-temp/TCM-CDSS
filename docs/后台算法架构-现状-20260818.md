## 1. 总原则（五条铁律）

1. **advisory only**：系统只出建议。每条结论必须可追溯到患者事实、确定性规则命中或知识库/证据条目，否则显式标注「证据不足/待检索」。
2. **模型永不判安全**：红旗、剂量授权、完整度分级、审方结论全部由确定性代码计算；模型输出的自评（如 completeness.level）一律被服务端重算覆盖。
3. **检测不阻断（owner 2026-08-01）**：`CDSS_GATE_DISPOSITION=advise` 默认档下，红旗/完整度/就诊范围命中照常检测、照常呈现（置顶安全横幅），但流程照走；`block` 是运维回退档。「不阻断」管**处置**，不管**检测**——检测层一条不减。
4. **fail-closed，且「未知≠无风险」**：审方不可用→人工复核锁；缺结构化药味→拒绝提交；语义筛查不可用→记为缺口；`未提及`的过敏史/用药史绝不当阴性。
5. **同一判据只许一份实现**：本仓头号缺陷形状是「同一判据两处各写各的、后来漂移」。修法是收敛为单一导出谓词，不是各处补 if（本文 §11 记录了 2026-08-18 当天按此修掉的七处实例）。

## 3. 代理层（`src/proxy.ts` + `cdss-auth.ts`）

- matcher：`/`、`/diagnosis`、`/api/:path*`。`/api/auth/access` 直接放行；`CDSS_API_TOKEN` 长度 <16 时 API 返 503。
- 双通道认证：`x-cdss-api-token`/Bearer（常量时间比对）或 UI cookie（HMAC）。未认证 API 按身份桶计失败，20 次/10min 锁定 429。
- Cookie 认证的**变更类**请求过 CSRF（Origin/Sec-Fetch-Site/Content-Type）。
- 模型限流只对 `MODEL_API_PATHS` 白名单里的 **POST** 生效（collect/question/interpret/diagnose/prescribe/assess/red-flags/post-prescription-risk/his-scheme），配额 `CDSS_MODEL_RATE_LIMIT_PER_10_MIN`（默认 60，钳到 [10,2000]）。**内存桶、单实例假设**——水平扩容会静默放大配额。
- 限流身份依赖 `CDSS_TRUST_PROXY_HEADERS=true`（可信反代后），这也是 `health?strict=1` 的一个合取项。

例外：`snapshot` 路由内自有鉴权（scope 由服务端凭据派生）；`model-health?check=1` 路由内自建 6 次/10min 桶。

## 4. 路由层与门控顺序

| 路由 | 阶段 | 门控顺序要点 |
|---|---|---|
| `collect` | M01 | 无 caseState、无安全门。userInput ≤12000 字 → 图片 ≤5.6MB + 魔数校验 + `tongueImageConsent` 必须为真才外发 → 性别必填。**无图路径完全确定性**（直接返回空 sentinel NDJSON，不调模型）；有图恒走 GLM 视觉（`buildTongueVisionPrompt` 只收图片，禁止推断年龄/疾病/处方） |

| `question/interpret` | M02 | 「模型提名 + 服务端逐字裁决」：模型只能引用 plan 内 questionId；`groundedQuotes` 必须是医生原话连续子串；`recordValue=null ⇔ 全部事实为 unknown/uncertain`；一次修复轮 |

| `post-prescription-risk` | — | 同 assess 的门控链，返回 JSON；六道 fail-closed 门全部不发外部请求（签名×2 → 候选 → 药味完整性 → 语义合同 → 审方提交门） |

| `red-flags` | — | 确定性危急体征红旗**早退不调模型**；否则回补后全量安全门,返回 JSON |

| `terminology/confirm` | — | 命名空间白名单只有 `tcm_syndrome`/`icd10`（路由与 lib 各有一份同判据，见 §12 债 D10）；确认后清签名、复核置 unavailable、强制 `prescriptionMustBeRegenerated` |

## 5. 确定性安全层（承重墙，`diagnosis-safety.ts` ~5.5k 行）

### 5.1 语料分流（失效方向相反的两份文本）

- `trustedInputText`：HIS 原文 + 字段 + 医生录入的舌/脉/体征/三史 + 用户对话。**显式排除模型衍生的 `state.symptoms`**——防止 M01 把「否认胸痛，但突发晕厥」结构化成 `pain=胸痛` 再喂回红旗判定。红旗判定只走这条。
- `clinicalGroundingText`：在上面基础上加回未被否认的 symptoms，只用于「病历有没有记过某症状」的接地判定。

### 5.2 生命体征：解析、取值、阈值（三档口径）

解析全部先过 `normalizeClinicalText` 全角归一；每个候选值过「主体是患者」（排除家族史/条件句）与「时态为当前」两道过滤。**取值口径统一为「优先复核档异常值」**：T/P/R/SpO2 走 `preferAbnormalNumber`，血压走 `bloodPressureReviewPriority`（危急=3 / 复核档异常=2 / 正常=1，跨源与文本内多读数同用；产科语境下复核档下探到 160/110，语境判据 `hasObstetricBloodPressureContext` 与红旗分支同源——2026-08-18 修复前血压误用危急档做偏好，「118/76，复测190/122」会取 118/76）。

| 项 | 复核档(advisory, 非阻断) | 硬红旗档 | 备注 |
|---|---|---|---|
| BP | ≥180/≥120 或 ≤90/≤50 | `bloodPressureIsCritical`: **≥220 或 ≥130 或 ≤80 或 ≤45** | 产科(妊娠/产褥)独立红旗 **≥160/110**，排除条件引用 `bloodPressureIsCritical` 谓词本身（修复前手抄 180/120 造成 185/118 无红旗真空）；倒置极值另有快通道 |
| T | ≥39 或 <36 | **≥40** / **<35** | 支持「38度9」中文小数 |
| P | 120–149 / 40–49 | **≥150 或 <40** | |
| R | 25–34 | **≥35 或 ≤8** | 低值边界 ≤8 与语义证据下限同口径（修复前 `<8` 差一个等号） |
| SpO2 | 90–91 | **≤89** | |

非法值（如 BP 顺序倒置、T 超生理范围）不当正常也不当危急——产出「请按 X 范围重录」缺口。

### 5.3 红旗词表组织（单一来源 `redflag-triage-lexicon.json` v2，18 类目）

- **硬门类**（带 `hardGateRequires`）：cardiac（急性/当前症状+类目证据）、gi_bleed（活动出血+严重度证据）、gi_alarm（警示征象/肿瘤史+消化症状）、vital_instability（数值阈值）。
- **提示档**（`narrativeFallbackAdvisories`，永不硬门）：syncope、poisoning、sepsis；口语消化道出血**刻意**只走提示档。
- **构词式**：`ABDOMINAL_PAIN_COMPOSITION`（部位×性质×中心词）、`COFFEE_GROUND_EMESIS_COMPOSITION`（禁跨分句）、恶性肿瘤词法守卫 `(?<![防抗致])癌(?!胚|抗原)`。
- **概念分组**：`FOCAL_NEUROLOGIC_CONCEPT_GROUPS` 等被阳性/否定两个方向共用；`NARROWER_THAN_GROUP_CANONICAL` 保证「否认高热」不给「否认发热」背书。
- 治理约束：代码只读表不抄词；`governance.scopeNote` 禁止「急迫词×症状」笛卡尔积。

### 5.4 否定与语境（阳性侧）

统一入口 `hasPatternWithoutNegation`：硬句边界内回看 40 字取最后一个否定词；`但/然而` 转折终止；顿号列举收窄；**逗号紧邻被测词时看词后 24 字**（「无高热，头痛明显」不误杀头痛）；`INTENSITY_MODIFIER_ONLY_SEGMENT` 防「否认呕血、黑便、持续剧烈腹痛」被切成阳性；出血严重度伴随症另有一道**独立的逗号分段紧邻否定**（刻意不用 `isNegatedAt`，防「大便发黑，无头晕乏力」误判活动性出血）。

### 5.5 两根开关轴与独立硬边界（`derivePrescriptionPermission`）

| 轴 | 默认 | 管什么 |
|---|---|---|
| `CDSS_GATE_DISPOSITION` | `advise` | 流程与呈现：红旗后还给不给完整 M03、恢复快照清不清内容、警示 tier 可否导出 |
| `CDSS_REDFLAG_DOSE_AUTHORIZATION` | `withhold` | 单独一件事：红旗未解除时 M04 印不印具体克数。`allow` 是回退档 |

**独立硬边界不受任何开关影响**（2026-08-15 拆轴的动因：旧 advise 档曾让 6 岁儿童+红旗拿到 full_dose）：儿科（`isPediatricPatient`，本地库只有成人剂量区间）、妊娠/哺乳/备孕阳性、高危剂量情形（CKD3-5/心衰/抗凝/免疫抑制等）、语义筛查不可用、缺主诉。关键实现约束：红旗分支**不提前 return 整个函数**，只决定剂量授权，硬边界在其后照常求值。

急症解除（`emergency-clearance`）是全系统唯一能抹掉确定性阳性红旗的路径，凭证 HMAC 签名、绑定 findings、每次读取重验重剥。

### 5.6 展示规则表 `RED_FLAG_FINDING_RULES`

红旗消息 → 卡片 ruleId/解释的唯一映射（顺序敏感的 `find`）。含 obstetric-severe-hypertension（必须排在 acute-neurologic-event 之前——产科消息尾部的「伴头痛」会被抢先归类）与 upper-gi-alarm（二者 2026-08-18 补，此前分别被误归神经卡/回落通用编号）。页面不得自带关键词表。

## 6. 语义临床事实回补层（`clinical-facts.ts` + `clinical-facts-runtime.ts`）

- **additive-only 由消费侧函数保证**：`additiveRedFlagsFromFacts` 等四个函数只产出待追加项；门禁级升级只认 `reviewStatus="checked"`；已 grounded 的 emergency 永不可被复核抹掉；裁决器缺失一律否决降级。
- **护栏 1（schema）**：逐条隔离非法项；只有「非空数组却无一合法」才整份判 null（防非法输出坍缩成权威空集）。**护栏 2（接地）**：quote 必须是原文子串；升级需 ≥2 条独立 grounded quote。
- **attestation**：HMAC 覆盖版本号/指纹/coverage/redFlags 等；`reviewStatus=checked ∧ coverage=full` 才签发；签不出**不降级放行**（整份判 unavailable/signing_unavailable）。缓存 TTL：有 finding 300s / 空结果 150s / 已验签链上探 600s。
- 超长病历投影（首尾各半、12000 字上限）→ `coverage=partial` → 不可签名 → 安全门记 `semantic_screen_unavailable` 缺口。
- 模型拓扑：extract/repair/review/adjudicate 四相位（temperature 0 / max_tokens 1800 / json_object / 相位 8s / 总 25s）；review+adjudicate 同时独立才允许降级裁决。
- `affirmedSymptoms`（抽取相位收集的"已确认症状"，供输出净化层防止把词表外阳性症状写成否认）：**2026-08-18 修复**——复核成功的四条 return 此前把它整段丢弃（复核契约无此字段），默认拓扑下该兜底恒空；现从抽取相位透传，消费端仍做逐字接地。

## 7. 完整度门

`determineCompletenessLevelFromScores`（**唯一实现在 `diagnosis-types.ts`**，2026-08-18 收敛；`diagnosis-parse.determineCompletenessLevel` 与 `diagnosis-safety` 的确定性重算均委托之）：

```
C ⇔ redFlag≥0.7 且其余三维≥0.6      （redFlag 门槛更高: 漏红旗比漏信息危险）
A ⇔ 任一维 <0.3
B ⇔ 其余（含 redFlag∈[0.3,0.7) —— 强制再问一轮）
```

三个重算点全部丢弃模型自评：sentinel 解析（`parseCompleteness`）、反序列化（`normalizeCompleteness`）、`withSafetyGate` 前置的 `deriveOperationalCompleteness`（由 hasChief/hasTongue/hasPulse/叙述细节算分，防止字段清空后陈旧高分继续解锁 M03/M04）。只有 C 级进入完整诊断/处方（advise 档下未达 C 降为 `limited_dose` 而非拦截）。

## 8. 模型与流式层（`diagnosis-api.ts` ~5.4k 行）

### 8.1 NDJSON 契约（所有后端与确定性响应共享）

四种帧：内容 `{"content":"…"}\n`、心跳 `{"type":"heartbeat","status":…,"processedChars":N}\n`、错误 `{"error":"公开文案"}\n`（上游原文不外泄）、终止 `{"content":"[END]"}\n`。最终正文用 `<<<CDSS_STREAM_FINAL>>>` 替换标记一次性覆盖此前的进度行。`markdownNdjsonResponse()` 把确定性 Markdown 包进同一契约。

### 8.2 超时五层 + 心跳

连接 90s → 空闲 60s → 单流总 180s → `STRUCTURED_RUN_TOTAL_TIMEOUT_MS`(180s) → 编排时限（M03 180s / M04 **120s**，两者不同，钳 60–180s；时钟从**路由入口**起算，含 body 解析与临床事实准备）。绝对截止有独立定时器 `forceCloseAtAbsoluteDeadline`（abort 上游"必要不充分"，直接下发兜底页+`[END]`）。心跳 5s 一帧，按 content/reasoning 字节数给三态文案。**仅 reasoning_content 无 content 判错**（「模型仅返回推理过程」），`model-health?check=1` 校验的正是最终正文。

### 8.3 结构化编排（M03/M04 一次请求的时序）

容量闸（`PRIMARY_STRUCTURED_STAGE_MAX_CONCURRENCY` 默认 1，排队计入时限）→ M03 可选并行两半生成+服务端合并（`M03_PARALLEL_GENERATION`，中位 91s→28s）→ 流读三判（malformed/无 DONE/仅推理）→ `wrapStructuredJsonObject`（M03 裸 JSON 补 sentinel；M04 经提案编译器；`applyRestoredGovernedFormulaIdentity` 防「组成达标但方名自拟」整方作废）→ 确定性投影 → 初审复核 → **修复轮 ≤3 层**（主重试/targeted/第三轮，每轮先过 deadline 门 + fixpoint 门）→ finalize（投影+复核+attestation+签名）→ 替换标记下发。

**fixpoint 检测（防同一修复提示无限注入）共五套并存**：合同码账本（同码 ≤2 次）、M03 quarantine 形态逐字节比对、M03 同 guidance、M04 同 guidance/同族归一（可豁免族剥 `candidate_N_` 前缀后同族即判）、finalize 阶段的「≠上次触发码」。跨请求另有 m04-retry 账本（进程内 Symbol 账本，TTL 30min，`contract_rejected` 计数 → 下次 `repairExhaustedOnEntry` + 温度阶梯 0/0.3/0.5/0.7 换彩票）。

## 16. owner 反馈问题（2026-08-18）：根因与解决方案

> 本节回应 owner 当面裁定的七类问题。每条先给代码级根因（不是辩解），再给分档方案；已当场修掉的标注"已修"。

### 16.1 速度慢 / 推理时间长

**一次 M03 的真实时间构成**（各环节上限来自代码常量）：语义事实回补 ≤25s（三次模型调用）‖ 证据检索（EviMed 三源各 12s 超时，与召回/极性/重排并发）→ 主生成（并行两半后中位 28s，改造前 91s）→ 独立复核 ≤35s 链 → 修复轮 0–3 轮（每轮 ≤90s 预算，fixpoint/时限提前止损）→ 签名与投影。M04 总预算 120s；M05 = 审方 30s + 作文 12s；HIS 写回**再审方一次** 30s。容量闸并发=1，排队计入预算。

**根因分档：**
- **R1（感知延迟主因）**：M02/M03/M04 全是缓冲阶段——医生只看到心跳文案，内容最后整段替换（→16.2）。"慢"的体感一半来自这里。
- **R2（串行链）**：回补层跑完才起证据检索（diagnose 路由回补在前）；同一 caseState 在单请求内全量重算安全门 ≥4 次（债 D19）；同一张方在 assess→post-prescription-risk→his-scheme 三条路由重复外呼审方。
- **R3（修复轮尾部）**：首轮合同不过 ⇒ 多一整轮 90s 级修复。首轮通过率没有作为运营指标。
- **R4（prompt 体积）**：上限 60k 字符；仅 prescribe 的 KB 段就 ~19k 字符。token 数直接决定供应商时延（前缀缓存省费用不省吞吐）。

**方案（按投入产出排序）：**
| # | 动作 | 预期收益 |
|---|---|---|
| S1 | 渐进输出（16.2） | 不减总时长，砍掉大部分**感知**等待——第一优先 |
| S2 | 回补与证据/召回全并发（合流点移到 prompt 组装前） | 省 5–15s/例 |
| S3 | 审方结果按 herbHash 短 TTL（60–120s）缓存，三路由三连击不重复外呼 | 省 30s×2/链 |
| S4 | M03 复核语义哈希 rebind 快路径（M04 已有，债 D8 补齐） | 省重复全量比对与重复复核 |
| S5 | prompt 减脂：KB 段按本例命中药味/规则裁剪，19k 常态注入是最大肥肉 | 首 token 与吞吐双降 |
| S6 | 首轮合同通过率进 telemetry 周报，按 top 驳回码修 prompt——每提 10% 首过率 ≈ 砍一段 90s 尾部 | 尾部延迟收敛 |
| S7 | 供应商压测后把容量闸并发从 1 提到 2–4（env 已留 `PRIMARY_STRUCTURED_STAGE_MAX_CONCURRENCY`） | 并发病例不再排队 |

**明确不做**：砍复核、砍安全门、砍修复轮上限——这三样每层都对应真实缺陷史（注册表 149 条套件注释就是清单）。速度从并发、缓存、渐进呈现里拿，不从安全层里拿。

### 16.2 渐进式输出（一个模块生成一个输出一个）

**现状与为何如此**：`bufferedClinicalStage`（M02/M03/M04）不外流原始草稿，因为未过合同的草稿可能含未校验剂量与编造引用——直接上屏违反证据绑定。但代价是医生盯着心跳等全量。

**改造方案（两步，接口协议归本文档管）：**
- **P1 分模块帧**：NDJSON 增加模块帧 `{"module":"m03.western","content":…}`，客户端按模块渐进渲染。M03 天然可拆四段（西医判读/证候/病机链/治法）；并行两半已证明可分开生成——把"合并后一次校验"改为"每半过其**片段合同**即下发到草稿区，签名终稿落地后整体替换"。草稿区带显式「生成中·未定稿」水印；**剂量表、安全 verdict、文献引用三类内容永不进草稿区**（现有 `sanitizeDiagnoseStreamingDraft` 扩展为片段级持留）。
- **P2 阶段间流水线**：M03 签名一落地即预热 M04（候选规划/证据检索先跑），医生点"生成处方"时前置已完成，省 10–20s。

### 16.3 治理话术淹没临床内容（取穴模板等）

**现状实测**：class-template 针刺卡里「未按证型加减/请按寒热虚实增减」最多 4 遍，穴位表只占 1 行。根因：每个渲染部件各自"如实标注"，没有**卡片级**去重；治理徽标（政府发布方案·病种模板·未按证型加减）以正文行呈现。

**已修（本轮）**：穴位行与边界说明的重复指令删除（Markdown+页面双出口），动作指令由方案状态行唯一携带，4 遍→1 遍。

**待办（需 owner 定稿文案）**：
- C1 卡片信息架构反转：**临床内容置顶**（穴位/操作/频次），状态与来源压成一行徽标，免责合并为卡尾一句。
- C2 生成侧收敛：`treatmentContent`（tcm-treatment-capabilities.server）只写增量信息（本例锚点症状/操作参数），状态性话术全部交呈现层——禁止生成侧与呈现侧各写一份（§14-16 残留的那一遍在这里清零）。

### 16.4 食疗/灸法无具体内容

**根因（重要：不是门禁吃掉了内容）**：具体内容只存在于受治理目录 T12（22 条）**已签字**条目；食疗/意疗是 regimen 型项目、目录里没有患者级方案 → fail-closed 渲染成"仅项目评估"。门禁如实呈现了"库里没有"——**内容生产环节缺位**，这正是甲方要求"要写具体内容"与现状的落差所在。

**方案（两条腿）：**
- 短期：复用 M05 作文已验证的模式——模型逐例撰写食疗方/灸法穴位建议，经受治理校验（灸法穴位必须落在受治理穴位词表内；食疗禁忌对照过敏史与病性寒热；禁语表照用），失败回退评估态。标注为「建议·待医师确认」档。
- 中期：扩充 T12 签字条目（中医师工作包流程已在跑，配穴签字清单同一通道），签过字的升「标准方案」档。两档标注分明，医生一眼能分。

### 16.5 知识库是否起作用不可观测

**现状**：KB 注入 prompt（prescribe 段 ~19k 字符）但**无逐例命中记录**；外部证据有 EVID 治理闭环，本地 KB 没有对应物。"知识库有没有用"目前只能靠猜。

**方案**：`cdss-stage-telemetry` 增加逐例知识命中摘要（检索词 → 命中条目 ID → 进入 prompt 的段落 → 最终输出实际引用了哪些）；`health?diagnostics=1` 暴露聚合；回归层加一条 **KB 开/关对照**脚本（同病例两跑 diff）作为作用量的硬证明。与 16.1-S5 的裁剪共用同一份命中数据。

### 16.6 78 岁问妊娠（已修，见 §14-14）

根因与修法见修复清单。补一句定性：那句话是**确定性缺口诱导模型写出来的**，不是模型自由发挥——同类"看起来像模型犯傻"的输出，排查顺序应当先查缺口清单/提示词注入，再查模型。

### 16.7 追问（M02）基本没作用

**现状**：机制齐（信息增益分/低值题词表/已答轴过滤/独立复核）但**价值未度量**——没有任何指标回答"这轮追问改变了什么"。单轮上限下泛化题挤占名额的问题一直靠词表打补丁。

**方案**：
- 度量先行：记录 M02 答案落库前后 completeness 四维分与 M03 结论 diff，产出"追问价值"周报——没有这个数，改题库都是盲改。
- 跳过闸：预计信息增益低于阈值直接 `decision=proceed`（把"没用的追问"变成"不追问"，而不是问一个凑数的）。
- 缺口绑定：追问目标必须绑定当前 `missingItemCodes` 条目而非开放生成——缺口清单没了就无题可问，与安全门共用同一份"还缺什么"的判据（单一判据原则）。

### 16.8 "封装个大模型做工作流就完了，搞这么复杂"

诚实回答：复杂度的绝大部分层各自对应一次真实线上缺陷（149 条套件的注释即清单——十九畏被一行 severity 过滤隐藏、复核 attestation 算出来即丢、`.catch()` 吞掉修复触发器…每条都是先出过事再立的层）。但"层有来历"不等于"层的价值可见"。收敛路线：
1. 同判据双写清零（§15 D 系列逐条销）；
2. 同请求重复计算合并（安全门单次求值缓存、审方 herbHash 缓存——与提速 S3/S4 是同一件事）；
3. 逐例可观测（16.5 同一机制推广到每个门禁层：这一层这一例拦了什么/放了什么）——**让复杂度自己证明价值，证明不了的层进裁撤评审**。

## 17. 硬门与模型的分工边界（owner 2026-08-18 第二问）：判据分类学、词表不可穷尽与收敛路线

> 问题原文：「硬规则硬拦截门禁门闸是不是可以少一些，多引导模型来做？无法穷尽的词表怎么办？发现一个问题要解决一类问题。」本节是带外部实证的正面回答。

### 17.1 结论先行

**能少的不是"门"，是"门里的正则"。** 把安全体系拆成三件不同的事：

```
检测（在开放语言里找信号）→ 归类（把信号落到有限类目）→ 处置（对类目执行政策）
     ↑ 模型应该多做的            ↑ 受控类目词表（有限、可签字）      ↑ 必须保持确定性的
```

- **处置永远确定性**。这不是本仓的偏执，是业界口径：guardrails 是 enforcement、prompt 只是 instruction——enforcement 必须跑在模型外面、"劝不动"（[ClickHouse: LLM guardrails in production](https://clickhouse.com/resources/engineering/llm-guardrails)、[NeMo Guardrails](https://mlops.community/taming-llms-with-nemo-guardrails/)）。临床系统的公开实现同构：确定性分析 + 语义检索 + 模型推理 + 确定性 SafetyVerifier 的分层混合是标准形态，不是"封装个大模型"也不是"全上规则"（[Medi-Gemma](https://arxiv.org/pdf/2607.04907)、[AnemiaCare 确定性 LLM 框架](https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2025.1728320/full)、[CLIN-LLM](https://arxiv.org/pdf/2510.22609)、[CareGuardAI](https://arxiv.org/pdf/2604.26959)）。
- **检测应该更多交给模型**。开放语言空间里词表天生输——这正是 owner 指出的"词表无法穷尽"。现状的真问题不是门太多，而是**检测层长成了处置层的形状**（表面形正则硬编码），于是每漏一个说法补一条正则，词表军备竞赛永无终点（STATUS 日志里 2026-08-13 一天补的口语卒中/消化道出血/咖啡样呕吐物就是这个循环的样本）。
- **流程通畅**主要卡在时延与呈现（§16.1/16.2），不在门的数量：advise 档已把绝大多数"拦截"改成"标注"，真正的硬停只剩五处（17.4）。

### 17.2 判据分类学（什么留硬、什么给模型）

| 判据性质 | 本仓实例 | 归属 | 理由 |
|---|---|---|---|
| 数值阈值 | 生命体征危急值、药典剂量上下限、年龄档 | **确定性** | 数字解析是闭合问题，模型无增益只添随机性 |
| 有限可枚举集合 | 十八反/十九畏 316 条、监管药名单、命名空间白名单 | **确定性** | 闭集正是词典的主场；这类词表**可以**穷尽 |
| 结构契约 | sentinel/schema/HMAC 签名/幂等/NDJSON | **确定性** | 完整性问题，与语言理解无关 |
| **开放语言检测** | 口语红旗、否定极性、就诊范围、症状确认、术语归一 | **模型为主 + 确定性地板** | 表面形不可穷尽；模型泛化 + 三重护栏（闭集输出/逐字引用接地/单调只加） |
| 处置政策 | 红旗→剂量授权、完整度→阶段门、审方不可用→人工复核 | **确定性** | 政策要可审计、可版本、单调；enforcement 不交给被约束对象 |

关键事实：**"模型为主 + 三重护栏"不是待发明的新东西，本仓已有五个组件长这个形状**——临床事实回补（18 类闭集 + quote 接地 + additive-only）、极性增补（POLARITY_NEGATION_ASSIST）、就诊范围（encounterScope + attestation）、M02 答案解释（模型提名 + 服务端逐字裁决）、受控术语归一（闭集双次一致）。要做的是把这个模式**升格为开放语言检测的默认路径**，并停止为开放语言写新正则。

### 17.3 词表不可穷尽：三层结构 + 冻结令

**结构**：表面形（unbounded，交模型）→ 类目（bounded：18 类红旗 / 证候闭集 / 治法闭集，受治理可签字）→ 处置（确定性）。词表换角色：**不再当检测器，改当类目锚点样例库**——喂语义层 prompt 做 few-shot 锚点、喂回归套件做类边界评测；检测靠模型泛化，词表只回答"这个类目的边界长什么样"。

**为什么不全上模型（也回答"规则会不会白留"）**：否定检测的公开实测——LLM 略胜规则（Llama 3.3 acc 0.967 略超规则基线；微调模型 0.962 > GPT-4o 0.901；NegEx 族 F1 0.84–0.89），但**每句慢约千倍**（5.9s vs 0.005s）（[放射报告否定 LLM 研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC12092861/)、[Assertion Detection 2025](https://arxiv.org/abs/2503.17425)、[德语临床否定 LLM vs 规则](https://ebooks.iospress.nl/doi/10.3233/SHTI251374)）。速度是 owner 的另一条投诉——确定性否定启发式**不删**：它是零成本、零时延的地板；模型极性层管地板够不着的尾部。同理所有"地板正则"：留，但停止增殖。

**中间层增强（中期）**：受控术语归一现有链路是"精确匹配 miss → 模型双次一致选择"；在中间插一层**临床嵌入候选预筛**（SAPBERT/CODER 类概念嵌入）。公开实测：检索增强的模型映射到受控词表，比纯词典/纯嵌入 F1 高 9–16 点（[CDE-Mapper](https://arxiv.org/pdf/2505.04365)、[多阶段生物医学概念归一](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12527512/)、[SNOMED×LLM 综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC11494256/)）。本仓"不上向量库"的既有结论针对的是方剂检索（瓶颈在重排）；类目锚点是几百条量级，进程内余弦即可，不引库。

**冻结令（已写入 AGENTS.md/CLAUDE.md 开发约定）**：开放语言类的新漏检，默认修法是「类目样例 + 整类 parity 回归 +（必要时）语义层 prompt 版本迭代」；新增表面形正则必须说明"为什么类目样例解决不了"。允许的例外只有三种：数值、闭集、构词式守卫（如 `(?<![防抗致])癌`——那是词法学不是词表）。

### 17.4 真正还在的硬停（与"能不能软"逐条）

| 硬停 | 能否软化 | 理由 |
|---|---|---|
| M03 签名缺失 → 409 | 否 | 完整性/防篡改，软了整条信任链作废 |
| 审方缺结构化药味 → 拒提交 | 否 | 喂给审方的数据完整性；软化=拿不完整处方骗一个 PASS |
| 红旗未解除 → 剂量持留 | **已是开关轴** | `CDSS_REDFLAG_DOSE_AUTHORIZATION=allow` 一键回退，owner 随时可切 |
| 儿科/妊娠阳性 → 剂量拦截 | 否 | 监管边界 + 本地库只有成人剂量区间 |
| block 档整套拦截 | 已软 | 默认 advise，block 仅作运维回退 |

其余所有"门"（完整度、就诊范围、质量类合同码）在默认配置下都已是**标注型**——检测照跑、流程照走、医生看得见。「为了安全弄了一堆门禁结果有用的没输出」的真实成因不是这些门，是 §16.3（话术淹没内容）与 §16.4（治理目录没内容可下发）——那两个修的是内容生产与呈现，不需要拆安全层。

### 17.5 「发现一个问题解决一类问题」制度化：miss-pipeline

现状这条已经在做（口语 parity 套件就是模板），但靠人自觉。定为流程：

```
线上漏检/误报 → 判层归因（数值地板漏？语义层漏？类目缺？呈现层丢？）
  → 产出物固定为三件套：类目样例（进语义层锚点库）+ 整类 parity 回归（含反例集防误报扩张）+ 归因记录
  → 禁止的产出物：一条新的表面形正则（除非命中 17.3 的三种例外）
```

判层归因是关键新增：此前所有漏检默认记在"确定性层缺词"账上，于是修法必然是补词。先问"语义层为什么也没接住"（模型没见过类目样例？还是 grounding 把它剥了？），修语义层才是修一类。

### 17.6 收敛路线（分阶段，各带回退与验收）

- **Stage A（立即）**：表面形正则冻结（约定已落）；语义层抽取 prompt 吃词表类目样例（`CLINICAL_FACTS_PROMPT_VERSION` 已支持版本化，**需 live 评测后上线**，离线套件测不出模型行为变化）；漏检一律走 miss-pipeline。验收：正则词表零增长 + 语义层检出率不降。
- **Stage B**：语义层从 backstop 升**主检**——确定性层降为地板（数值 + 构词式 + 闭集），门禁级升级仍要求 `reviewStatus=checked` + 逐字接地 + 单调只加（护栏一条不减）；嵌入候选预筛插入受控归一链。回退：`CDSS_CLINICAL_FACTS_BACKSTOP` 已有开关语义反转为"降级回地板"。验收：对照集上主检增量检出 > 地板独有检出，误报率不升。
- **Stage C**：检测质量周报（语义层 vs 地板的增量检出/独有检出/误报三栏），用数据开出**地板正则裁撤名单**——正则只出不进；每裁一条留 parity 回归防回潮。

### 17.7 覆盖度自查：按本方案整改，问题是否"全解决"（诚实清单）

**结论：机制层面的问题本方案闭环了；有四类东西方案本身解决不了，不要预期"改完就全好"。**

| owner 问题 | 覆盖度 | 说明 |
|---|---|---|
| 78 岁问妊娠 | ✅ 已修并钉类 | 年龄档 + 人口学类边界测试 |
| 话术淹没内容 | 🟡 已修大头，尾款待办 | 4 遍→1 遍已上；信息架构反转(C1)与生成侧收敛(C2)需 owner 定稿文案后实施 |
| 一次性输出 | 📐 方案闭环，未实施 | P1 模块帧 + P2 阶段预热是工程项目（协议+客户端+片段合同），做完才算数 |
| 速度 | 🟡 方案闭环，但有物理下限 | S1–S7 全做完，**感知**延迟大降、总时长仍有模型推理本身的下限（M03 主生成中位 28s 砍不掉）；别预期"秒出" |
| 词表穷不尽 | 📐 机制解决，效果待验 | 冻结令+语义主检终结军备竞赛的**机制**；实际召回质量取决于 Stage A 的 prompt 改造 live 评测——离线测不出，没验之前不许上 |
| 食疗/灸法没内容 | 📐 通道解决，内容靠生产 | 架构只能把"建议档/标准档"两条通道打通；标准档要有中医师持续签字供给，建议档要 live 评测把关质量——**内容生产是运营问题不是架构问题** |
| KB 是否起作用 | 📐 给了测量手段 | 可观测性建成后才能回答；且可能回答出"部分 KB 段没用"——那会引出新一轮裁剪工作，不是终点 |
| 追问没作用 | 📐 机制闭环，质量靠迭代 | 跳过闸消灭"凑数追问"是立竿见影的；"问出最聪明的那个问题"是模型质量问题，靠 16.7 的度量回路持续迭代 |
| 硬门太多 | ✅ 已澄清 | 默认配置下只剩 5 处硬停且各有存在理由/回退轴；再软是政策决定不是架构问题 |
| 布局交互 | ❌ 不在本方案内 | 后端只管输出密度与渐进协议两个半边；UI 需单独立项走查 |

**方案管不了的四类（残余风险，须另行面对）：**
1. **模型底子**：全部护栏与流程优化都不提升 V4 Flash 本身的辨证水平——诊疗质量的天花板在模型+prompt+知识供给，管道修得再好也只是不糟蹋它。单供应商单账户仍是全链单点（2026-08-13 的 402 全链瘫痪已实测过一次）。
2. **评测基础设施先于一切**：Stage A/C、追问度量、KB 对照都依赖"能被信任的评测"——而黄金基线长期红、红的大半是噪声（2026-08 实测 245 失败里 233 条是环境变量）。**先把基线修干净，否则所有"效果待验"的项都验不了。**
3. **执行量**：§16+§17 合计约十项工程，不会一周做完。建议顺序（按 owner 可见收益）：① 渐进输出 P1 ＋ 话术 C1/C2 ＋ 审方缓存 S3（一周内医生体感明显变化）→ ② 基线修复 + Stage A live 评测 → ③ 追问跳过闸 + KB 可观测 → ④ Stage B 升主检。
4. **既有债务清单（§15 D1–D20）与本方案正交**：三套审方风险正则各写各的、M04 缺上游故障文案这些确证问题不会因为本方案自动消失，仍需逐条销。
