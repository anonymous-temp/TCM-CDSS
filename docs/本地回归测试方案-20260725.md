## 0. 三分钟速通（只想知道有没有坏）

```bash
npm run verify:release
```

这一条等于 `typecheck && lint && test:deterministic(48 套件) && build`。**全绿就说明没有回归。**
耗时约 3–5 分钟，不需要服务器、不需要密钥、不联网。

红了看是哪一段红：typecheck/lint 是代码问题，套件名会直接打印，build 红通常是数据文件问题。

## 第一层：确定性回归（无服务器、无密钥、无网络）

### 1.1 全量

```bash
npm run test:deterministic
```

**期望终态**：`{"suites":48,"failures":0}`，约 23 秒。

⚠️ runner 是 **fail-fast**：任何一个套件非零退出就停，后面的套件根本不会跑。所以看到
`{"script":"test:xxx","status":1}` 时，**修完要重跑全量**，不能只跑那一个。

### 1.2 按改动面挑着跑（改完某块时的快速验证）

| 你改了什么 | 跑这个 | 钉住的东西 |
|---|---|---|
| 安全层 / 红旗 / 剂量门禁 | `npm run test:safety-mutations`<br>`npm run test:safety-pediatric` | 红旗判定变异矩阵、儿科门禁 |
| 检索 / 方剂候选 / 排序 | `npm run test:formula-provenance`<br>`npm run test:syndrome-hypothesis` | 328 条方源断言；证候假设方向正确性 + 三条安全边界 |
| 证型标签 / 药味裁定 / 目录 | `npm run test:clinical-governance-tables` | 12 张治理表哈希、裁定逐条落地、按方裁定不退化成全局 |
| M03/M04 结构化契约 | `npm run test:stage-contract`<br>`npm run test:stream-safety` | sentinel 边界、结构化修复 |
| 前端展示 | `npm run test:diagnosis-display` | 展示一致性（注意：源码字符串断言，见 §4） |

| 审方 | `npm run test:rxaudit-contract`<br>`npm run test:rxaudit-payload` | 归一契约、载荷契约 |

## 第二层：数据资产核对（跑脚本看数，不是测试）

这些不是 pass/fail，是**看数字对不对**。每次治理数据入库后跑一遍。

```bash
npx jiti scripts/report-formula-clinical-reach.mjs
```

**当前基线（本轮结束时）**：

```
受控方剂总数   2680      可被检索到 2680
可被身份锁锁定 1530      可编译剂量 1308
★ 全链路可达   948 (35.4%)
仅差证型标签   360       仅差剂量可编译 582
展示了却永远锁不住 1150   组成含缺字药名 144
```

**怎么看**：
- `全链路可达` 只能涨不能跌。跌了说明有治理数据丢了。
- `仅差证型标签` 是投入产出比最高的缺口——每补一条裁定，这个数减一、全链路加一。
- `展示了却永远锁不住 1150` 对医生是负价值（选中即被剥离），是下一阶段该压的数。
- `组成含缺字药名 144` 是抽取缺陷（黄芪→「黄」），不是治理进度。

```bash
npm run build:tcm-governance-tables
```
重建治理表。**它是 fail-closed 的**——本轮就被它挡下三次真问题（目录上限截断挤掉真武汤、
假方名混入、裁定指向不存在的方）。它报错**不要绕过**，那是它在干活。

## 第三层：Live HTTP 回归（需要服务器 + 密钥）

### 3.1 前置

```bash
npm run dev
```
另开一个终端：

```bash
BASE_URL=http://localhost:3000 npm run regress:tcm-cdss > regress.log 2>&1; echo "EXIT=$?"
```

**⚠️ 三个坑，我自己全踩了一遍：**

**① 不要用管道接 `npm run`。** `npm run regress:tcm-cdss | tail -30` 的退出码是 `tail` 的，
恒为 0——回归实际失败了你也看不出来。要么像上面那样重定向后单独取 `$?`，要么看输出末尾的
`"failures": N`。这条最容易骗过人，因为屏幕上明明打印了失败详情，退出码却是 0。

**② 服务端与回归脚本的鉴权配置必须一致。** 本仓 `.env.local` 里是
`CDSS_REQUIRE_API_AUTH=false` + `CDSS_API_TOKEN=<有值>`：服务端不鉴权，而回归脚本按
「有 token ⇒ 应返回 401」断言，于是 4 条鉴权绕过测试必然红——根因是配置错配，不是产品缺陷。
跑鉴权相关断言时要让服务端也开鉴权：

```bash
CDSS_REQUIRE_API_AUTH=true npx next dev -p 3011
# 先确认：curl -o /dev/null -w "%{http_code}" http://localhost:3011/api/diagnosis/health  应为 401
```

**③ 耗时约 15 分钟**，其中 his-scheme 会遍历整个病例集（每例 2–3 秒）。中途没有输出是正常的，
不要以为卡死了。可用 `preview_logs` 或服务端日志看 200 流水确认在动。

### 3.2 黄金基线

`regress:tcm-cdss` 是**最重要的一条**：100+ 请求，断言红旗处理、否定式既往史、安全网误报规避、
处方后风险、KB 检索、边界输入、鉴权引导。输出 JSON 摘要，任何失败 exit 1。

**改过诊断流水线或安全层，前后各跑一次。**

### 3.3 其余 live 脚本（按需）

| 命令 | 用途 | 额外前置 |
|---|---|---|
| `npm run regress:live-red-flags` | 红旗矩阵 | 模型密钥 |
| `npm run regress:live-m03-review` | M03 独立复核 | 模型密钥 |
| `npm run regress:live-m04-named` | M04 命名方锁定 | 模型密钥 |
| `npm run regress:live-rxaudit` | 灵犀审方 | `RXAI_AUDIT_*` |
| `npm run regress:live-evidence` | 证据检索 | `EVIMED_*` |

## 第四层：手工验收（自动化测不了的）

### 4.1 三个黄金病例（检索方向）

在 `/diagnosis` 依次录入，看 M03 给出的候选方**治疗方向**对不对（不是看某一首方是否精确命中）：

| 病例输入 | 期望方向 | 不该出现在首位 |
|---|---|---|
| 反复失眠，入睡困难，伴心悸、神疲食少、便溏 | 归脾汤/人参归脾丸（补益心脾） | — |
| 失眠多梦，急躁易怒，口苦目赤，头痛便秘 | 泻青丸/当归龙荟丸/龙胆泻肝汤（清肝泻火） | **二至丸**（滋补肝肾之阴，方向相反） |
| 恶寒发热，头痛无汗，鼻塞流清涕 | 桂枝汤/麻黄汤/葛根汤（解表散寒） | — |
| 腰痛3个月，遇冷加重，腰膝酸软 | 右归丸/附子汤（温阳） | **左归丸**（滋阴，方向相反） |

这四例已进 `test:syndrome-hypothesis`，但**手工再走一遍**能看到模型最终怎么用这个短名单——
测试只验候选，验不了模型的取舍。

### 4.2 降级态不能长得像故障（本轮前端修复的验收点）

| 场景 | 期望 | 曾经的问题 |
|---|---|---|
| 突发胃痛 3 小时 | 黄色「临床优先关注」卡 + M04 三段式说明「为什么不能推方」 | 显示红色「未完成 + 重新生成」，而那个按钮点了必然再败 |
| 仅输入「失眠」 | 追问卡 + 有限信息推理，不出红色错误 | 同上 |
| 任何红旗病例带化验值（如"血红蛋白 58 g/L"） | 三段式非剂量结论 | **越危急越容易被渲染成系统故障**（剂量词全文扫描误判） |

**重点看**：M04 区域出现红色⚠️「本阶段未完成」时，那是真故障；出现三段式「标准→差距→动作」
才是预期内降级。这两者现在数据上分得开了。

### 4.3 结论与评分不能自相矛盾

- 证型显示「依据不足以形成稳定结论」时，右上综合支撑度**不得**显示「辨证充分 100%」
  （现在会显示「辨证未成立」并压到 69 分以下）。

### 4.4 经典条文出处（本轮新增，重点验收）

M04 候选方卡里应出现可折叠的**「经典条文出处（N 条）」**面板：

- 点开后每条显示：书名·篇名、层级标签（经典/通行/经验）、**条文原文摘录**、证据ID
- 条文里的剂量应显示为 `[具体剂量或操作已隔离]` —— 这是刻意的，古代剂量不可直接换算
- 面板标题旁必须写着「按方名检索所得……不代表适用于本例」

**这一项此前完全不可见**：222,338 条古籍语料只在服务端解析后随流下发，前端一行都没读。

顺带验收安全分级：随便找一个含毒剧药的古方（如至宝丹、苏合香丸），条文摘录里**不应出现**
砒霜/水银/轻粉/铅丹/斑蝥/蟾酥/马钱子这类禁用或重金属物质。

### 4.5 布局

1440×900 下看诊断结论卡：**西医诊断倾向栏不得竖排**（每行 1–2 个字）。
xl 以上已改为单栏，若又出现竖排说明栅格被改回去了。

## 第五层：部署前必查

```bash
curl "http://localhost:3000/api/diagnosis/health?strict=1"
```
返回 `strictReady:false` 会 **503**，Docker healthcheck 会挡住部署。它 AND 了模型、临床复核、
证据、舌象视觉（若启用）、审方、快照加密、推理签名、临床事实、TCM 治疗配置、**限流身份**。

```bash
curl "http://localhost:3000/api/model-health?check=1"
```
做真实模型调用，校验的是**最终 content** 而不是 reasoning——只返回推理过程的 provider 会在这里红。

### 内存

修好 tcmoc 加载后，首个 M04 请求会同步加载 277,465 条证据，常驻约 **1.6GB**。
`docker-compose.yml` **没有设内存上限**——部署前请确认容器内存 ≥ 3GB，否则表现为处方阶段整体失败。
