## P0 — 发布阻断(本轮新增)

### P0-3 · `health?strict=1` 返回 `strictReady=false`,Docker 健康检查会失败
- 实测:`{"ready":true, "strictReady":false, "degradedReasons":["tcm_treatment_capabilities_not_configured"]}`
- 按 README "容器健康检查会带内部访问 token 调用 `/tcm-cdss/api/diagnosis/health?strict=1`,只有模型、证据、审方与加密快照配置达到 strictReady=true 才判定健康",**生产部署后容器会被判定不健康**。
- 唯一降级原因是"中医治疗能力(针刀/针灸/推拿等)未配置",这是 M05 可选增强,不是核心流程,作为 strict 阻断条件**过于严格**。
- 修法:把 `tcm_treatment_capabilities` 移出 strict 阻断集合,或降级为 warning。

### P0-4 · `.env.local` 的 `CDSS_REQUIRE_API_AUTH=false` 在 dev server 启动时不稳定生效
- 现象:`.env.local` 设 `CDSS_REQUIRE_API_AUTH=false`,但 `npm run dev` 启动后浏览器访问 `/` 跳 `/login`(curl 同样 401)。**必须 `CDSS_REQUIRE_API_AUTH=false npm run dev` 显式 export 才生效**。
- 重现:重启 dev server → curl GET / → 返回 307 跳 /login;显式 export 后 → 200 OK。
- 影响:① 本地开发体验差;② 若运维误用 `npm run dev` 启动(而不是 systemd 之类显式注入 env),会突然要求登录;③ 测试脚本/CI 容易 401。
- 根因猜测:Next.js 16 + Turbopack 在 `.env.local` 热重载或 worker 隔离上有 bug,某些变量没传到 proxy.ts 运行的 worker。
- 修法:① 在 `package.json` 的 `dev` script 显式注入 `CDSS_REQUIRE_API_AUTH` 默认值;② 或在 cdss-auth.ts 增加 fallback `if (process.env.NODE_ENV === "development" && !process.env.CDSS_REQUIRE_API_AUTH) return false`。

### P0-5 · dev hot-reload 中断推理流程后 UI 状态机不一致
- 现象:lib 文件改动触发 Fast Refresh full reload 时,正在跑的 M02 流程被中断。重新加载后:
  - 主区域显示"重点追问 **未完成** / 页面刷新或关闭中断了正在运行的阶段;已保留病历和已完成结果,可从当前阶段安全重试 / **重试本阶段** 按钮"
  - **但右侧栏仍显示"等待病历信息 / 只需填写主诉即可开始..."**(应该是"重点追问中断"或"重试中")
  - **左侧表单数据(主诉/现病史/既往史/过敏史/用药史)全部清空**——但主区域文案说"已保留病历",前后矛盾
- 影响:虽然生产部署没有 hot-reload,但**说明持久化恢复机制不够完整**——加密快照保存了"流程状态",但没保存"表单输入态"。如果生产环境用 nginx reload / Docker restart,医生会丢失表单。
- 修法:① 表单输入 debounce 后写入加密快照(localStorage);② reload 后从快照 hydrate 表单;③ 右侧栏 status 应反映"重试本阶段"状态而非"等待病历"。

## P1 — 严重(本轮新增)

### P1-7 · 纯确定性安全门漏报 4 类急症(RF03/04/06/08)
- 100 条 unit 测试结果(`scripts/regress-deterministic-safety-100.mjs`):

| 用例 ID | 场景 | 期望 | 实际 | 严重度 |
|---|---|---|---|---|
| RF03 | 过敏休克(喉头阻塞感+BP85/50+SpO2 90) | red_flag | needs_information | 漏报 |
| RF04 | 呕血黑便(呕咖啡样物) | red_flag | needs_information | 漏报 |
| RF06 | 急腹症(板状腹) | red_flag | needs_information | 漏报 |
| RF08 | 产科大出血(孕32周无痛性阴道大出血) | red_flag | needs_information | 漏报 |
| TC18 | 中风后遗症(半年前脑梗) | 无红旗 | 误报"突发剧烈头痛/意识异常" | 误报 |

- **关键缓解**:5/5 失败用例的 `allowDosePrescription=false`,**fail-closed 安全网未破**——医生不会被开方。但**用户体验问题**:真正的急症只标"需要补信息",医生可能误以为补完信息就能继续,而非立即转诊。
- **TC18 误报**:中风后遗症被识别为急性神经急症,docs 类5 "位置式清除边界"反向问题——现病史有"脑梗"但缺"既往/陈旧"标记。
- **真实环境兜底**:red-flags route 强制调 `maybeAttachClinicalFactsBackstop`(LLM 抽取),实测 RF01 在 LLM 层正确触发。但 RF03/04/06/08 是否在 LLM 层补上,本轮未跑完(因 hot-reload 干扰)。需要补做:把这 4 个用例单独 curl 跑真实 red-flags,看 LLM 抽取层是否补上。
- 修法:① 在 `diagnosis-safety.ts` 红旗规则补 "喉头阻塞/喉头水肿" + "呕血/咖啡样物/柏油样便" + "板状腹/反跳痛" + "阴道大出血/产后出血" 关键词;② 中风/脑梗关键词加"既往/陈旧/后遗"豁免。

### P1-8 · 临床事实兜底默认开启与内存记录相反,造成端到端耗时翻倍
- 实测:`src/lib/clinical-facts-runtime.ts:305` `return process.env.CDSS_CLINICAL_FACTS_BACKSTOP !== "false"` —— **默认开启**(只需显式设 `"false"` 才关)。
- 内存 [[p1-clinical-facts-backstop]](4 天前)记录的"默认关闭,仅 `CDSS_CLINICAL_FACTS_BACKSTOP=true` 才启用"已过时。
- 影响:① 每次 red-flags 触发 3 次 LLM 调用(extractor+reviewer+adjudicator),p95 延迟从 1ms(纯确定性)飙升到 4-6s;② 100 条并发能压垮 dev server;③ 端到端 218s(P0-2)的很大一部分来自这里。
- 修法:① 评估是否真要默认开启(extractor+reviewer+adjudicator 共 ~10s,占端到端 ~5%);② 若开启,把 red-flags 路由的 clinical-facts 改为**异步预取**而非阻塞;③ 更新内存记录。

### P1-9 · 加减工作台 13 味药下拉视觉重复(待人工截图确认)
- DOM 实测:`P1·肝气郁结` 块出现 13 次,`君臣佐使` 出现 13 次——正好等于方剂 13 味药。
- 可能性 A(正常):每味药一行 × N 列下拉,snapshot 把 option 文本展开成重复字符串。
- 可能性 B(bug):每味药下拉行渲染了 13 个相同 select。
- 未完成确认:dev hot-reload 持续中断流程,无法稳定截屏。
- 修法:生产环境(无 hot-reload)实测一次,确认是 A 还是 B。

### P1-10 · M02 单选强迫二分已在主报告 P1-1,本轮再确认
- M02 实测追问"情绪以烦躁易怒为主还是忧思抑郁为主"——radio 二选一,无"两者皆有/以X为主"。
- 站在挑剔中医大夫视角:肝郁化火与肝郁脾虚共病极常见,二分会误导辨证。

## P2 — 中等(本轮新增)

### P2-9 · 面象选择 chip 选项不全
- 实测面象选择面板展开后:
  - 面色:面色少华 / 面色萎黄 / 面色淡白 / 面色潮红 / 面色晦暗 / 面色青紫
  - 神态:神清 / 精神倦怠 / 烦躁易怒 / 少气懒言 / 形寒肢冷 / 目赤
  - 形体/局部:形体消瘦 / 形体肥胖 / 目周色暗 / 唇色淡 / 唇色紫暗 / 两颧潮红
- **缺**:面色苍白(气血暴脱/阳虚)、面色红赤(实热)、面色青(寒证/痛证/瘀血)、**正常面色**(无特殊)、面垢(湿热)。
- 站在挑剔中医大夫视角:**没有"正常面色"是个明显疏漏**——医生看一个无特殊面部体征的患者,只能不选,无法显式标注"已查,正常"。
- 修法:每类 chip 加"正常/无特殊"选项 + 补苍白/红赤/青/面垢。

### P2-10 · "执行辅助推理"按钮文案对老中医不友好
- 文案"执行辅助推理"——技术语。老中医不懂"推理"指什么。
- 修法:改"开始辨证"或"生成诊疗建议"。

### P2-11 · "舌诊采集"按钮无 disabled 时也缺说明
- 实测当前 dev 下"舌诊采集"按钮 disabled=false(GLM_API_KEY 已配),title="打开舌诊采集"。
- 但按钮没有任何 hint 说明"需要拍摄环境/角度要求",医生不知道上传什么样的舌照。
- 修法:打开后的 modal 里加拍摄指引(自然光、伸舌自然、对焦舌中)。

### P2-12 · "问诊选择"按钮缺 data-testid
- 实测:其他 3 个选择按钮(面象/舌象/脉象)都有 `data-testid="tcm-*-preset-toggle"`,**问诊选择没有 testid**。
- 影响:自动化测试无法稳定定位,UI 测试覆盖不均。
- 修法:加 `data-testid="tcm-inquiry-preset-toggle"`。

### P2-13 · "新建诊疗"图标按钮虽然在 aria-label 上有 "新建诊疗",但视觉上无文字提示
- 实测:header 左侧只有"+"图标,无文字。医生第一次用不知道是"新建"还是"添加"还是"展开侧栏"。
- 修法:加文字"新建"或 hover tooltip(已有 title 但移动端不显示)。

### P2-14 · "清空并新建"确认 dialog 文案过长
- 实测:"清空当前诊疗?当前本机加密保存的病历草稿和 AI 结果会一起清空。舌照/图像不会被保存;清空后无法从本机恢复,请确认已经写回 HIS 或完成记录。"
- 字数 60+,门诊医生没时间读。
- 修法:精简为"清空当前病例?本机草稿和 AI 结果将一并清空,无法恢复。" + 一个"详情"折叠。

### P2-15 · M02 流程被 hot-reload 中断后,"重试本阶段"按钮无预期效果说明
- 实测:点击"重试本阶段"会重新发起 M02 question 请求(~30s),但按钮附近**无"约需 30 秒"提示**,医生不知道等多久。

### P3-6 · 表单字段无单位提示

## 给"极挑剔中医大夫"的总结陈词

**优点**:
1. 安全网坚固:红旗急症 fail-closed,不会误开方;阴性对照不误报;30 条极性陷阱全过。
2. 辨证推理质量扎实:实测酸枣仁汤合逍遥散加减,君臣佐使、方义、煎服法、节气调护完整,这不是"AI 编的",是真正从《金匮》《局方》接出来的。
3. 证据可溯:每条 patient_fact 都接到原文引用,引用未落地的会被拒绝。
4. PHI 保护:加密快照、不上传图像、serialize 前 sanitize。

**挑剔点**:
1. **太慢**:一个简单失眠病例要走 3-4 分钟,门诊医生看 30 个号根本用不起。最痛。
2. **配置不稳**:dev 启动有时认 `.env.local` 有时不认;strict 健康检查 false;GLM 独立复核没生效——这些是上线前必须修的"地基"。
3. **急诊覆盖盲区**:喉头阻塞感/呕咖啡样物/板状腹/产科大出血在纯确定性层没识别——虽然 LLM 兜底补上了,但 LLM 一旦不可用就是洞。
4. **黑话残留**:"bounded" 等开发标记在流式过程中暴露,"执行辅助推理"对老中医不友好。
5. **面象选项不全**:没有"正常面色",这是中医基本功。
6. **hot-reload 中断后状态不一致**:生产虽然无此问题,但暴露了"表单输入态没持久化"的真 bug。

**最迫切的三件事**:
1. **P0-1**:补 GLM 复核配置(5 分钟,改 .env.local)。
2. **P0-3**:修 strict 健康检查 false(把 tcm_treatment 移出 strict 集合)。
3. **P0-2 + P1-8**:端到端 218s 拆解,clinical-facts backstop 改异步预取,这是耗时的最大单点。
