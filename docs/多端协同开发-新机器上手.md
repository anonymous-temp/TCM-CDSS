# 多端协同：新机器上手清单

仓库：`git@github.com:anonymous-temp/TCM-CDSS.git`（私有）

## 0. 先装 Git LFS —— 漏了这步会静默出错

`src/data/tcm-classic-text-evidence-tcmoc.jsonl`（332MB，222338 条古籍证据）由 LFS 承载。
**没装 LFS 就 clone，拿到的是一个 130 字节的指针文本，而不是语料。**
后果不是报错而是**静默降级**：M03/M04 的经典条文证据检索返回空，页面照常渲染，
只是"证据不足"，很难一眼看出来。

```bash
git lfs install          # 每台机器只需一次
git clone git@github.com:anonymous-temp/TCM-CDSS.git
cd TCM-CDSS
git lfs pull             # 若 clone 时 LFS 未就绪，补拉
```

自检（三项都对才算装好）：

```bash
ls -l src/data/tcm-classic-text-evidence-tcmoc.jsonl        # 应为 347296769 字节，不是 ~130
sha256sum src/data/tcm-classic-text-evidence-tcmoc.jsonl    # 应为 988487b5cfa9f3ba60c3b1b2e5124b3b958c8b57ce92838425c416bd083e888b
head -c 60 src/data/tcm-classic-text-evidence-tcmoc.jsonl   # 应是 {"evidenceId":"TCMOC-… 而不是 version https://git-lfs…
```

## 1. 仓库里**没有**的东西

以下都在 .gitignore 里，新机器要自己准备，否则相应功能跑不起来：

| 缺什么 | 影响 | 怎么办 |
|---|---|---|
| `.env.local` | 全部模型调用、鉴权、加密快照 | 照 `.env.example` 逐项填；密钥找负责人要，**不要贴进任何对话或提交** |
| `中医补充数据/`（2.3G）、`药学基础数据/`（2.3G）、`参考/`（150M） | 只影响**重建**知识库（`build:tcm-knowledge` 等），不影响跑应用 | 生成物已在 `src/data/`，日常开发不需要这些原始数据 |
| 兄弟仓库 `合理用药` | 同上，只在重建知识库时需要 | 需要时再拉 |
| `uploads/` | 客户评测文档，与代码无关 | 不需要 |

日常开发**不需要**那 4.6GB 数据——`src/data/` 里的生成物已经够跑全部功能与全部测试。

## 3. 协同约定

- **直推 main**（当前约定，无保护分支）。推之前**必须**本地跑过
  `npm run verify:release`（typecheck + lint + test:deterministic + build），
  这是发布总闸门；闸门红就不要推。
- 改了 `src/lib/diagnosis-safety.ts`、`src/lib/tcm-knowledge.ts` 等受治理源文件后，
  **必须重跑两个生成器**，否则闸门会报「来源注册表指纹与真实文件分叉」：
  ```bash
  node scripts/build-clinical-governance-static-tables.mjs
  python3 scripts/build-tcm-governance-tables.py
  ```
- 新增 `test:*` npm 脚本后，**必须**同时登记进 `scripts/run-deterministic-regression.mjs`
  的数组，否则它不在闸门里——写了不登记等于没写。
- `src/data/*.json` 是生成物，不要手改；要改改生成器或对应的 `*.source.json`。

## 4. 大文件注意事项

- 不要再往 git 里加 >100MB 的文件（GitHub 硬限，push 会被整体拒绝，
  且历史里留下就必须重写历史才能清掉）。确需大文件走 LFS：
  `git lfs track "路径"` 后再 `git add`。
- 当前 LFS 用量约 332MB。GitHub 免费额度 1GB 存储 + 1GB/月流量，
  **多端反复 clone 会吃流量**——建议各机器保留本地仓库增量 pull，不要反复重新 clone。
