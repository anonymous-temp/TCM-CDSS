## 0. 安装与复现（全局生效）

```bash
# 本区域 GitHub release 下载被限速；改用源码编译（Go 1.26 已自带）
cd open-code-review-main
GOPROXY=https://goproxy.cn,direct CGO_ENABLED=0 go build -trimpath -o /tmp/ocr ./cmd/opencodereview
install -m 0755 /tmp/ocr /opt/homebrew/bin/ocr   # /usr/local/bin 需 sudo，homebrew bin 在 PATH 且可写
ocr --version

# 配置 DeepSeek（与项目同账号）
ocr config set provider deepseek
ocr config set providers.deepseek.api_key <OPENAI_API_KEY>
ocr config set providers.deepseek.model deepseek-v4-pro
ocr llm test   # 连通性自检

# 审查（本项目非 git，用 --path 指定文件）
ocr scan --repo . --path src/lib/cdss-auth.ts,src/proxy.ts,... -b "<业务背景>" --format text
```

注：`ocr scan` 要求单文件 ≤80% 上下文窗（~56K token）。**`diagnosis-safety.ts`（2855 行/~56K token）被自动跳过**——该文件已由项目自带 `regress-deterministic-safety-100.mjs`（95/100）+ 我的功能测试覆盖，但 OCR 无法整文件审，是其工具限制。

## 1. 关键发现（按真实严重度排序）

### 🔴 P0-1 鉴权：客户端 `X-Forwarded-Proto` 可压制 Cookie Secure 标志 ✅
`src/lib/cdss-auth.ts` `isHttpsRequest` 末行：
```ts
return new URL(req.url).protocol === "https:" && !req.headers.has("x-forwarded-proto");
```
直连 HTTPS（未走可信代理）时，**客户端只要在请求里加任意 `x-forwarded-proto` 头**，`isHttpsRequest` 即返回 false → auth cookie 不带 Secure → 后续可能在明文 HTTP 上传输。
- 修法：未走可信代理时直接 `return new URL(req.url).protocol === "https:";`（去掉对客户端头的依赖）。
- 真实严重度：**高**（在文档化的生产拓扑 `CDSS_TRUST_PROXY_HEADERS=true` 下走的是另一分支，不触发；但任何未按文档部署/直连暴露的场景都可被利用）。属纵深防御缺口。

### 🔴 P0-2 鉴权：`Host`/`X-Forwarded-Host` 含 `@` 可伪造 origin ✅
`src/lib/cdss-auth.ts:120` host 校验正则 `/[\s/\\]/` **未拒绝 `@`**。`new URL("https://attacker@evil.com").origin === "https://evil.com"`，可绕过 CSRF 同源校验 / cookie scope。
- 修法：`/[\s/\\@]/`（加 `@`）。1 行。

### 🔴 P0-3 DoS：未走可信代理时全体客户端共享限流桶 ✅
`src/lib/cdss-auth.ts:88` `cdssClientKey`：`CDSS_TRUST_PROXY_HEADERS !== "true"` 时一律返回 `"direct"`。**所有客户端共用一个限流桶**——单个攻击者即可耗尽配额，把所有合法用户锁在登录/M02 之外（`proxy.ts` 20 次失败锁 10 分钟；`auth/access` 8 次锁 10 分钟）。
- 叠加：`proxy.ts` 的限流 `Map` 存在 TOCTOU 竞态 + 过期条目永不清理（内存泄漏）。
- 真实严重度：**高**（同样仅影响未走可信代理的部署；生产应走可信代理）。修法：未走代理时退回 socket peer IP 或显式告警。

### 🟠 P1-1 HMAC 签名非确定性 ✅
`src/lib/reasoning-contract-signature.ts` `canonicalize` 用 `left.localeCompare(right)` 排序键后再算 HMAC payload。`localeCompare` 跨 Node 版本/ICU/locale 可能产出不同顺序 → 签名与验签环境不一致 → M03→M04 契约**误拒或静默放行**。
- 真实严重度：**中**（实际签/验在同一进程同一 locale，跨环境风险低；但属正确性隐患）。修法：改 `<`/`>` 码点比较。

### 🟠 P1-2 fail-open：流读取/审方缺 `catch` ✅
- `src/lib/http-guard.ts:16-30` `readJsonBodyWithLimit`：`try{...}finally{releaseLock}` **无 catch**，`reader.read()` 抛错→unhandled rejection（违反返回 `{ok:false}` 的类型契约）。
- `src/lib/rxaudit.ts` 审方执行同样 try…finally 无 catch。
- 修法：补 catch 返回结构化错误。对"确定性安全承重墙"而言，fail-open 是最不该出现的姿态。

### 🟠 P1-3 ReDoS + 反向字符区间 ✅
`src/lib/evidence-source-validation.ts` 反伪造证据的正则 `[A-Z][A-Z0-9_-]*(?:-[A-Z0-9_-]+)+` 含嵌套量词，长连字符串可触发回溯；另有 `'—'`-`'-'` 反向区间。单请求即可 stall 服务。
- 修法：预编译/锚定正则、限制输入长度、修正字符区间。1-2 行。

### 🟠 P1-4 basePath 误配静默扩大 cookie 范围 ✅
`getCdssBasePath()`：`NEXT_PUBLIC_BASE_PATH` 带尾斜杠/反斜杠/空时返回 `""` → `getCdssCookiePath()` 回退 `/` → **cookie 范围扩到整域**，多应用共享域名时跨应用可见。
- 修法：生产环境对非法 basePath 抛错而非静默回退。

### 🟡 P2 级（合理，已核对）
- `RX_AUDIT_RISK_ORDER` 未 `Object.freeze`（`rxaudit-normalize.ts:6`）——误改会破坏风险排序。✅
- `normalizeLingxiDecision(input)` 无 null 守卫，`input` 为 null 时崩溃。✅
- `rxaudit.ts` 把**精确年龄**连同病历摘要发给外部审方 → 再识别风险；去重 key 把空白标点全剥→不同警告可能碰撞；FNV-1a 32-bit 哈希碰撞阈值低。🔬
- `m04-proposal-compiler.ts:278` 嵌套三元（违反项目 code-quality 规则）；`!= null` 松散相等多处。✅
- `diagnosis-api.ts:1295` 主模型流缺 `reader.releaseLock()`（GLM 流有，主模型流没有，不一致）。✅
- `diagnosis-api.ts:856` `retryCompletePrimaryResponse` 修复提示词拼接多段大文本，可能超 prompt 上限。🔬
- `diagnosis-api.ts:2185` 死代码 `const useVision = true;`。✅
- `sameSecret` 常量时间比较的 JIT 时序泄露（理论，HMAC 定长下风险低）。🔬

## 2. ⚠️ OCR 严重度被高估的项（已降级）

OCR 不掌握数据流，以下被它判为 critical/high，但**实际输入非攻击者可控**，真实严重度更低：

| OCR 判定 | 实际情况 | 真实严重度 |
|---|---|---|
| `m04-proposal-compiler.ts:649` 多处 `JSON.parse` "critical DoS" | 解析的是**模型自身输出**，上游已被 `PRIMARY_TEXT_MAX_OUTPUT_CHARS`(80K) 限制，非用户直传 | 🟡 低（加 size 守卫是好习惯，但非可被外部打的 DoS） |
| `reasoning-contract-signature.ts:256` `JSON.parse` 无 try-catch | 同上，解析模型 sentinel 输出 | 🟡 中（健壮性，非安全） |
| `acupointCare` 始终被置 null "丢弃 provider 数据" | 这是**设计意图**（服务端拥有该字段，prompt 明确 `acupointCare 固定输出 null`） | ❌ 非缺陷（设计如此） |

即：OCR 把"解析模型输出"误判为"解析不可信输入"。真正攻击者可控的输入入口是 **HTTP 请求头/体**（鉴权、host、basePath、请求体大小）——这些（P0-1/2/3、P1-2/3/4）才是真要修的。
