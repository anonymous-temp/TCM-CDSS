# 中医治疗项目医生端输出设计

日期：2026-08-18  
状态：已获用户确认  
适用范围：`中医治疗项目`医生可见区域；食疗、耳穴、灸法及后续同类非药物项目

## 1. 背景与问题

当前页面把内部治理信息直接展示给医生，包括“病种模板 · 未按证型加减”“政府发布方案”“仅项目评估”“由现场医师复核后实施”“操作禁忌与资质”等。与此同时，部分卡片没有给出食疗内容、穴位或频次，导致系统说明多、可执行内容少。

甲方与用户要求医生端只显示核心临床内容：具体做什么、取哪些穴、如何安排频次。内部模板状态、来源等级、资质说明和安全闸门不属于医生端内容，不应上屏。

## 2. 设计目标

1. 医生首屏直接获得具体方案，不阅读系统治理过程。
2. 每张卡必须提供真正的项目内容；只有状态说明或安全套话时整卡隐藏。
3. 后端安全门、来源追溯和模板治理继续执行，但与医生可见内容彻底分层。
4. 食疗、耳穴、灸法使用同一份医生端输出合同，便于测试和扩展。

## 3. 医生端输出合同

医生端每个项目最多显示四类字段：

- `项目名称`：如“食疗与饮食”“耳穴压豆”“灸法”。
- `核心内容`：食疗的具体饮食方案，或非药物治疗的具体操作内容。
- `穴位/部位`：项目涉及穴位时必须给出明确穴位；不适用时省略。
- `频次/复评`：每日或每周频次、单次操作时长、换贴或复评周期。

不得显示以下内容：

- 病种模板、证型模板、未按证型加减、仅项目评估等内部状态。
- 政府发布方案、国家标准/规范、来源权威等级等来源标签。
- 由现场医师确认、资质要求、安全边界、热证排除、烫伤风险等责任转移式话术。
- 内部未命中原因、待终审原因、协议缺口或英文状态码。

## 4. 项目显示规则

### 4.1 食疗与饮食

必须同时包含：

- 至少一条具体饮食行为，例如少量多餐、餐后不平卧、停用明确诱发食物。
- 至少一个可执行食疗示例，例如山药小米粥及建议频次。

只有“食疗只作调护”“结合慢病指导”等套话时，不显示食疗卡。

### 4.2 耳穴压豆

必须同时包含：

- 具体穴位。
- 每日按压次数、单穴时长及换贴周期。

只有项目名称或模板状态时，不显示耳穴卡。

### 4.3 灸法

必须同时包含：

- 具体穴位。
- 每周频次或疗程与复评时间。

只有“进入评估范围”“不形成操作计划”等内容时，不显示灸法卡。

## 5. 数据分层

现有完整治理对象继续保留，作为后台审计与安全控制数据。新增医生端投影层，将治理对象转换为最小展示 DTO：

```ts
type ClinicianTreatmentProject = {
  projectCode: string;
  title: string;
  content: string;
  sitesOrPoints?: string[];
  schedule?: string;
};
```

投影函数只读取已通过治理的具体内容，不读取或拼接模板状态、来源等级、协议缺口和资质字段。投影后无法形成 `content`，或穴位项目缺少 `sitesOrPoints`，或操作项目缺少 `schedule` 时，返回 `null`，医生端不渲染该卡。

## 6. 页面结构

采用已确认的 B 方案：

1. 模块标题为“中医非药物方案”。
2. 项目卡按食疗、耳穴、灸法等顺序展示。
3. 卡片只呈现核心内容、穴位和频次，不设置来源徽标或状态徽标。
4. 不设置“方案依据与安全边界”医生端折叠区；审计信息只保留后台日志和结构化接口。

## 7. 失败与降级行为

- 某项目缺少具体内容：隐藏该项目，不输出“暂无”或模板说明。
- 全部项目均缺少具体内容：隐藏整个“中医非药物方案”模块。
- 后台治理或安全校验失败：保留原有阻断/降级逻辑，但医生端不生成一张仅含阻断原因的项目卡。
- 结构化内容存在但渲染失败：记录错误，不回落到原始 Markdown 或治理对象全文。

## 8. 测试与验收

必须覆盖：

1. 食疗有具体行为与食疗示例时显示。
2. 食疗只有安全套话时隐藏。
3. 耳穴缺穴位、灸法缺穴位或频次时隐藏。
4. 页面全文不存在模板状态、来源徽标、资质与安全边界话术。
5. 历史归档病例经过投影后，医生端仅出现核心内容。
6. 后台结构化治理字段仍完整保留，删除医生端展示不得削弱安全判断或审计追溯。
7. Playwright 截图验证移动端和桌面端均无空卡、无内部状态泄漏、无布局溢出。

## 9. 与其他整改子项目的边界

本设计不直接修改以下问题，它们分别建立独立规格：

- 老年女性妊娠/哺乳提示与特殊人群规则。
- 模块级增量输出、推理耗时与交互反馈。
- M02 追问的信息增益与结果影响验证。
- 知识库命中、决策影响和可观测性。
