# DeepSeek V4.1 Flash 全环节试验设计

用户要求清理旧实例、核验新版，并将全部后台模型切换为 DeepSeek V4.1 Flash 试跑；随后明确确认“舌照也切 DeepSeek”。本设计落实这一已确认范围，不重写诊疗流程。

## 已确认事实与边界

官方 2026-09-10 发布说明和价格页将新型号标识为 `deepseek-flash`，并支持原生视觉。现有账号实测模型列表、JSON 请求、非思考开关及 64×64 无患者图像请求均成功。来源：[发布说明](https://deepseek.com/news/deepseek-v4-1-flash/)、[接口与型号](https://api-docs.deepseek.com/quick_start/pricing/)。

全部文本调用沿用现有 OpenAI-compatible 入口，以显式阶段覆盖指向 `deepseek-flash`；保留服务端 JSON/临床合同，不将 `json_object` 说成严格 JSON Schema。复核继续执行，但同型号只能称独立请求，不能称跨模型复核。知识检索、签名密钥、租户、客户 token、已有医疗风险政策均保持不变；已关闭的外部审方和可选百炼证据重排不重新开启。

## 最小实现

增加一个舌照供应商选择配置 `TONGUE_VISION_PROVIDER`，缺省 `glm` 保持兼容；显式 `primary` 使用现有主模型配置、批准的 HTTPS 端点及其密钥。此次 `primary` 视觉只支持已验证的 `deepseek-flash`，未知/不可用选择返回明确配置错误，不静默换供应商。

图片实际请求、健康探针、配置可用状态和公开 provider/model 展示必须消费同一选择器。保留当前图像提示词、`image_url` 格式、请求取消、超时和 NDJSON 输出契约。旧 `glm` 后端名称可作为内部兼容入口保留，不再误报实际供应商。

用药事件抽取复用统一 `textModelRequestTuning`，明确关闭思考；正常审方关闭时它不应新增调用。其余模型控制沿用既有配置。不得为实现“全部切换”而关闭临床事实、复核或术语辅助功能。

## 验证与发布

先跑旧镜像的全文本隔离试验，再用最小代码适配补齐视觉。通过失败先行的真实函数/传输边界测试、相邻套件、typecheck/lint 和完整确定性回归；候选中检验语义事实、M02、M03/M04、M05、HIS、舌照和实际遥测型号。保留失败与时延读数，不删例或放宽断言。

旧实例清理独立进行：先保留旧静态资源，确认新实例健康、旧实例无流量后删除准确目标，绝不删除共享生产数据卷。正式 Qwen 实例在 DeepSeek 试验期间继续服务；最终切换使用已测试的不可变镜像和不停服流程，客户 token 不变。
