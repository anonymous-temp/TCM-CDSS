# M03 渐进式模块草稿设计

## 背景与目标

当前 M03/M04 在结构合同、独立复核和签名完成前只输出心跳与模块完成提示，医生仍需等待约 60–80 秒才能看到第一段临床内容。本设计落实《后台算法架构-现状-20260818》§16.2 P1：M03 每完成一个可独立理解的模块就输出一个明确标为未定稿的草稿，最终签名结果仍是唯一权威结果。

本包只处理 M03 的四个无剂量模块：西医判断、证候、病机链、治则治法。M04 保持现有进度提示，不把药名、剂量或未经审方的组成放入草稿；M03→M04 预热属于后续 P2，不进入本包。

## 方案比较

1. 维持现有“模块完成提示”。风险最低，但医生仍看不到临床内容，无法解决感知等待。
2. 直接流出模型原始 Markdown/JSON 草稿。首屏最快，但复核与修复可能改写诊断、证候和治法；历史线上问题已经证明同屏出现两个结论不可接受。
3. 服务端验证并投影类型化模块草稿帧。只读取白名单字段，先过片段合同，再由确定性渲染器生成医生可读 Markdown；客户端明确显示“生成中·未定稿”，最终结果到达后整页替换。

采用方案 3。它在不削弱最终合同、复核、签名和安全层的前提下改善感知延迟。

## 协议

NDJSON 增加一种辅助帧：

```json
{
  "type": "module_draft",
  "module": "m03.western",
  "revision": 1,
  "content": "## 西医判断\n……"
}
```

`module` 只允许：

- `m03.western`
- `m03.syndrome`
- `m03.pathogenesis`
- `m03.therapy`

模块帧不拼入最终 `content`，不进入病例快照和签名载荷。客户端仅在当前请求存活期间按模块保存最新 revision。原有 `{"content":"…"}`、心跳、引用帧、随访时间轴和 `[END]` 语义不变。

## 服务端片段合同

`diagnosis-stream-modules.ts` 继续负责不完整 JSON 的顶层片段识别，并新增默认拒绝的模块草稿投影：

- `westernDiagnosis` 必须含非空主诊断名和至少一条支持事实；只渲染诊断倾向、支持事实、限制与鉴别要点，不渲染 guidelineReferences/evidence。
- `overview` 必须含非空主证和依据；只渲染证候与辨证依据，不渲染方名、证据来源或内部解析原因。
- `pathogenesis` 必须至少有一个节点，且每个显示节点均含患者事实、辨证依据、病机与对应治法。
- `therapy` 必须含非空治则或治法；只渲染治则、治法及能与病机节点绑定的子治法。

渲染器只从上述白名单字段生成 Markdown，不转发模型原始字段名。输出再次经过现有医生可见文本净化，并拒绝包含以下内容的草稿：

- 药物剂量或用法频次；
- 红旗/安全 verdict、审方结论；
- DOI、PMID、URL、参考文献或指南引用；
- 内部 reason code、签名、attestation 或模型执行痕迹。

并行 M03 中，西医半一旦完整返回并通过片段合同即可独立输出；中医半按 `overview → pathogenesis → therapy` 的闭合顺序输出。片段未通过合同就不发帧，不能影响最终主链路。

## 客户端呈现

`diagnosis-engine.ts` 解析模块帧并通过独立回调上报，不把模块正文混进最终累计文本。`DiagnosisClient.tsx` 维护仅内存的 M03 模块草稿表：

- 进度日志保留，用于连接、生成、复核状态；
- 已到达的模块按固定临床顺序渲染为独立卡片；
- 卡片顶部统一显示“生成中 · 未定稿”；
- 最终 `STREAM_REPLACE_MARKER` 正文到达或请求结束后清空草稿卡，只展示签名终稿；
- 取消、报错、切换病例时清空草稿，绝不恢复为既往权威结果。

## 错误处理与安全边界

- 未知 module、非法 revision 或空 content 视为非法辅助帧；客户端不展示。
- 服务端片段解析或投影失败只跳过该模块，不中断最终生成。
- 模块草稿没有签名、不能触发 M04、不能写回 HIS、不能导出报告。
- 红旗路径仍由确定性安全门控制；草稿帧不携带安全 verdict，也不改变红旗处置。
- 最终合同、独立复核、修复轮、签名和确定性投影完全保留。

## 测试与验收

1. 单元合同：四个合法模块逐一生成类型化帧；非法/未知/含剂量/引用/安全结论的片段不上流。
2. NDJSON 消费合同：模块帧触发独立回调但不污染最终 content；未知模块与非法形状被拒绝；最终 `[END]` 仍必需。
3. 源码守卫：M03 结构阶段仍是 buffered，最终正文仍通过替换标记唯一落地；M04 不产生含药名剂量的草稿帧。
4. UI 合同：模块卡带“生成中·未定稿”，顺序固定；最终正文出现后模块草稿消失。
5. 回归：`test:stream-modules`、`test:stream-safety`、`test:stage-contract`、typecheck、lint、生产构建和一例真实 M03。

验收成功的核心指标是：真实 M03 在最终签名前至少出现一个可读模块草稿，同时最终签名载荷、医生终稿与现有合同逐字保持同一权威路径。
