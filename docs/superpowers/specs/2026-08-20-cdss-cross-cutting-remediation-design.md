# 中医 CDSS 跨域缺陷收口设计

## 目标与范围

本轮收口当前 `codex/pharmacopoeia-case-regression` 分支上已被源码审查和对抗实测确认的问题，覆盖模型接入、临床安全、多租户、医生可见内容、说明书解析与 M05 出口一致性。三条未能复现的问题不修改生产逻辑，只补防回归用例：最终出口接受模型自撰中医引用、首个正常血压遮蔽后续异常值、病历事实净化吞掉同句后续病机与治法。

成功标准：每项缺陷先有可重复的 RED 测试，再由最小实现转绿；普通与 fresh 确定性闸门均为 166 套零失败；定点线上病例、鉴权、租户隔离、快照兼容和严格健康全部通过；固定客户鉴权 token 只从服务器秘密配置继承，不进入源码、文档或日志。

## 设计一：模型提供方与思考开关

`openai-compatible` 保留为协议层入口，不再被等同为 DeepSeek。模型与端点必须成对校验：DeepSeek 仅允许 DeepSeek 模型与批准端点，Qwen 允许 DashScope/Qwen 模型与批准端点；`bailian-qwen` 继续作为供应商专用入口，两条路径共用请求调优函数且绝不借用彼此的凭据。

`textModelRequestTuning` 对 DeepSeek/Qwen 的 `thinkingEnabled` 缺省统一解释为 `false`，分别明确下发关闭字段。调用方显式 `true` 时才开启。临床复核的独立性由实际端点与模型身份比较，不允许按 provider 名硬编码；健康状态只报告首选复核拓扑，不用任一备用候选冒充首选独立。

## 设计二：临床安全与流式草稿

生命体征规则以单一当前测量选择器为入口。通用重度高血压按 `收缩压>=180 或舒张压>=120` 进入确定性红旗；妊娠/产褥期按 `>=160/110` 进入产科红旗，避免两套阈值之间出现空档。多次测量优先当前、复测和风险更高的有效值。呼吸频率 `<=8` 进入确定性呼吸循环风险。

临床事实复核只可追加或保留首轮已接地的 `affirmedSymptoms`；复核未重复该数组不能静默删除。中医病名引用在前置阶段只绑定服务端国标，扩展病名引用只能由最终受治理证据作用域生成，模型自带引用一律不进入信封。

M03 模块帧只呈现“模块已生成、正在校验”的状态，不提前展示诊断名、证型、病机、治法或任何剂量/疗程。确定性红旗横幅作为流的首个可见临床块；最终签名结果使用替换帧覆盖进度。由此同时消除剂量泄漏、结论漂移和红旗后置。

## 设计三：多租户与迁移

客户 cookie 与请求头同时存在时必须一致；不一致返回 409，只有无 cookie 的 API 调用才可单独使用请求头。模型限流统一调用已存在的客户作用域身份函数，使固定 token 下不同客户拥有独立桶，UI 会话仍保留会话隔离。

快照新写入使用 `tcm-cdss-encrypted-snapshot-v2` 并绑定客户 AAD。解密 v1 时先尝试当前租户 AAD，再尝试升级前 AAD；成功恢复旧快照后标记为 legacy，浏览器下一次保存自动写成 v2。v2 永不回退旧 AAD。

缺少客户标识时默认仍拒绝；新增可选 `CDSS_DEFAULT_CUSTOMER_ID` 仅用于旧调用方迁移，值必须通过现有客户 ID 校验，并在健康状态标注迁移模式。库存迁移脚本增加正式 npm 命令、CLI 参数与部署手册步骤。

## 设计四：药品候选、说明书与中医治疗项目

库存未导入时跳过可得性过滤，候选行为与多租户改造前一致；只有 `inventoryLoaded=true` 时才按在库/缺货过滤。真实无证据与院内无库存使用不同状态及医生文案。

特殊人群风险按原子语义删除：从混合条款中只移除妊娠/哺乳成员，保留肝肾功能不全、儿童、老年、经期等仍适用于患者的限制；删除后若只剩“慎用/禁用”等无主语动作才整条丢弃。

说明书用法解析扩展到外用、贴敷、滴眼/滴鼻、吸入、含服、舌下、灌肠、栓剂、冲服和烊化兑服。所有字段必须逐字来自同一说明书条目；贴敷部位可以并入给药途径，换药间隔进入频次，不推断原文没有的剂量。

治疗项目排程接受“每日/隔日/每周 + 次数”或“每日累计 + 时长”；灸法不再强制出现“周”。医生 DTO 增加经过净化的真实禁忌/必查项和简短实施资质，继续过滤模板状态、来源等级、现场确认和责任转移套话。页面与 Markdown 共用同一投影，HIS 保留完整后台字段。

## 设计五：M05 三出口同源

提取共享的患者级随访作者入口，由 `assess`、`post-prescription-risk`、`his-scheme` 三条路由共同调用。审方结论、风险级别和安全触发条件仍由确定性层拥有；模型只撰写复诊重点、疗效标准、生活管理、维度选择和时间轴。任何模型失败均回落现有模板，不影响审方或写回。

## 测试与发布

每个工作流独立 RED/GREEN 并提交。必须新增：两种 Qwen provider 矩阵与缺省思考参数；混合禁忌顺序变体；空库存与已加载缺货；M03 草稿无临床结论且红旗首帧；185/118、复测血压、R=8、affirmedSymptoms；cookie/header 冲突、跨客户限流、v1/v2 快照；真实目录排程、禁忌展示、外用贴敷；HIS 患者级 M05。

完成后依次执行 typecheck、lint、相关专项、普通 166、fresh 166、production build、依赖审计。本地生成 standalone，服务器只做轻量运行镜像组装；保留上一镜像回滚，切换后验证 commit/digest、固定鉴权、strict health、模型探针、审方探针和定点病例。除非用户再次要求，不恢复已中止的剩余 77 例全量回归。
