# 诊断证据与药品候选展示整改设计

## 1. 目标与依据

本设计覆盖甲方《好医生&灵犀中医核对内容-2026-08-05》与《8.11医学测评》中与诊断、辨病辨证、鉴别、候选药品展示直接相关的要求，并吸收 2026-08-19 复测反馈：

- 中医必须同时返回并展示辨病结果与辨证结果，不能只剩证型。
- 中医辨病、辨证分别显示受治理的规范或循证依据。
- 西医主诊断及鉴别诊断的证据区只显示标准参考文献，不把模型思考、病例复述或“支持……”说明混入文献。
- “本候选不形成疗程医嘱”不得显示给用户。说明书有用法、剂量、频次或疗程就展示相应字段；某字段没有可靠来源就省略该字段。
- 临床推理仍保留在独立的“诊断要点/鉴别要点”区域，不能冒充参考文献，也不能从签名载荷或 HIS 出参中删除。

## 2. 现状根因

1. `overview.tcmDiseaseName`、`tcmDiseaseRationale` 与病名鉴别字段已经存在，但 `TCM_DISEASE_NAME_VISIBLE_TO_CLINICIAN=false` 使医生页面把辨病结果整体隐藏。
2. 西医只有主诊断拥有 `guidelineReferences[]`；鉴别诊断没有逐项受治理引用。中医病名与证候也没有专用引用字段。
3. 当前引用展示把 `appliesTo`、自由文本理由和文献题名混在同一视觉层，读者无法快速区分“临床判断”与“参考文献”。
4. 中成药本地索引已经保存完整 `usage`，例如养脾散明确记录“口服，一次3～5克，一日2～3次，饭前或空腹时服”，规划器却把 `singleDose/frequency/route/course` 全部置空，并用内部边界文案替代真实说明书信息。

## 3. 选定的数据结构

新增统一的 `ClinicalCitation`：

```ts
type ClinicalCitation = {
  evidenceId: string;
  citation: string;
  url?: string;
  doi?: string;
  pmid?: string;
  sourceType: "standard" | "guideline" | "consensus" | "literature";
};
```

在 M03 中新增：

```ts
overview.tcmDiseaseReferences: ClinicalCitation[];
overview.tcmSyndromeReferences: ClinicalCitation[];
westernDiagnosis.differentials[].guidelineReferences: ClinicalCitation[];
```

现有 `westernDiagnosis.primary.guidelineReferences` 归一到同一结构。模型只能提交本轮证据编号；题名、机构、年份、URL、DOI、PMID 与最终 `citation` 由服务端从受治理条目回写。无法反查的引用删除，不回落到模型自撰文献。

## 4. 中医辨病与辨证展示

医生可见诊断卡固定为三项：

1. 西医诊断：规范名称 + ICD-10（能够确定性编码时）。
2. 中医辨病：`overview.tcmDiseaseName`。
3. 中医辨证：`overview.primarySyndrome`，兼证存在时另列。

中医证据分成两组：

- 辨病依据：病名命中受治理病名词表时，至少显示 `GB/T 15657-2021《中医病证分类与代码》`；词表条目沿用 `GB/T 16751.1-2023` 疾病术语时可并列显示。若本轮检索到与该病名直接相关的指南/共识，再追加真实检索引用。
- 辨证依据：证候命中 `SRC-GBT-16751-2-2021` 时显示 `GB/T 16751.2-2021《中医临床诊疗术语 第2部分：证候》`；若有本轮检索到的证候诊疗指南/共识，再追加真实引用。

`tcmDiseaseRationale` 与 `tcmDiagnosticRationale` 放在“辨病要点”和“辨证要点”区，不进入参考文献列表。病名级鉴别继续使用 `tcmDiseaseDifferentials[]`；证候取舍留在辨证区，不能再伪装成病名鉴别。

## 5. 西医主诊断与鉴别诊断证据

- 主诊断卡只显示诊断名、ICD-10 和标准参考文献列表。
- 西医鉴别诊断每一项显示“鉴别病名 + 鉴别要点 + 参考文献”。
- 参考文献列表只接受 `ClinicalCitation.citation`，统一输出题名、责任机构/作者、期刊或发布方、年份以及可用的 DOI/PMID/URL。
- `appliesTo`、`reason`、`distinguishingPoints`、`nextCheck` 不拼入参考文献；它们保留在独立的鉴别要点区。
- 病例事实、症状依据、体征依据和模型置信度不得进入参考文献区域。

## 6. 中成药与西药用法用量展示

服务端从证据条目逐字段解析并绑定：

```ts
route?: string;
singleDose?: string;
frequency?: string;
administrationTiming?: string;
course?: string;
```

规则如下：

- 中成药：本地或外部说明书已提供的字段必须回写；禁止把已有 `usage` 丢弃。
- 西药：仍保持“仅供讨论”的产品定位，但说明书已提供的标准用法字段可以展示为说明书信息，不等同于系统为本例下达处方。
- 疗程：说明书明确给出固定疗程或症状改善后的规范时限时展示；未给固定疗程时不渲染“疗程”行。
- 缺任一字段时直接省略该字段；禁止显示“本候选不形成疗程医嘱”“按说明书”“遵医嘱”“待确认”等内部占位句。
- 用法字段必须与同一 `evidenceId + evidenceFingerprint` 绑定，不能从另一药品或另一规格串入。

## 7. 错误处理与安全边界

- 引用反查失败：删除该条引用，不影响已经成立的诊断结构；诊断卡不得显示伪引用。
- 中医病名或证候未命中受治理词表：显示临床工作结论，但规范依据栏不伪造国标名称，同时将该项纳入术语待确认。
- 药品用法解析不完整：只展示已核验字段；不得猜测缺失剂量或疗程。
- 后台签名载荷、完整说明书、审方输入与 HIS 数据保持完整；本设计只规范医生可见投影和明确新增的结构化字段。

## 8. 验收标准

- 78 岁反酸病例页面同时显示中医病名“吐酸”和证候“脾胃虚弱，湿浊中阻证”。
- 辨病、辨证各至少显示一条可追溯规范依据，且不含病例复述或模型思考。
- 西医反酸显示 ICD-10 `R12.x00x002`；每条参考文献符合标准引用格式。
- 西医鉴别诊断不再把自由推理混入参考文献列表。
- 养脾散显示说明书已有的口服、单次量、频次和服药时机；不显示“本候选不形成疗程医嘱”。
- 说明书无固定疗程的候选不显示疗程行，不出现空栏或占位句。
- M03/M04 签名、HIS 投影、医生页面和下载报告对同一字段给出一致答案。

## 9. 备选方案及取舍

- 方案 A（选定）：结构化引用 + 服务端确定性回写 + 推理/文献分区。可审计、可复用，并能保证多个出口一致。
- 方案 B：只改前端文案和排序。改动小，但接口、HIS 与下载报告仍会继续分叉，拒绝采用。
- 方案 C：让模型直接生成完整参考文献。覆盖快但存在编造与格式漂移风险，违反项目证据边界，拒绝采用。
