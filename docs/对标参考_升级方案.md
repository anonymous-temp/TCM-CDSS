# 对标"南中医·预问诊/智能开方"升级方案

> 目标:把我们的输出升级到参考系统那种「引导式问答 + 病机推理详尽 + 处方成品化」的观感与深度。
> 方法:重读 `参考/` 6 张截图归纳标杆能力,并用 6 个只读 Agent 逐文件核实我方现状(2026-07-14)。
> 与 `docs/整改方案.md` 关系:那份是「去阻断+找回丢失特性」的总账;本份是「对标这个具体参考」的落地清单,**新增**了随症加减、逐脏腑病位、症状群小结、环形进度、监测指标渲染、调候节气、有损往返修复等参考专属项。行号会漂,以函数名/字符串为准。
>
> **状态:已定版(2026-07-14)。产品取舍已锁 —— ①入口保持医生 HIS 工作台,形态不改;②追问保持一次 2-4 题,节奏不改。** 明确不做:患者侧极简入口、一次一问模式、"为本人咨询"身份切换、入口表单重构。这些从范围移除,桶 A/B/C/D 不受影响。

## 0. 核心判断(先看这个,它决定了投入方式)

**我方后端已产出参考约 80% 的实质内容,felt gap 主要是"呈现/连通"而非"能力"。** 证据:

- 病机链 `chain[]`(患者事实→证候→病机→治法,逐节点)、病位/病性辩证、总治则+子治法、西医诊断+鉴别、方义、饮片逐味功用+后下先煎、煎服法、`nonPharma`(膳食/起居/情志/穴位/监测)——**全部已是结构化字段**,多数还是 zod 硬约束(缺了直接 fail-closed 拒绝 M04)。
- 但其中一批**产出了却对医生不可见**:西医鉴别 `differentials[]`、病机 `uncertainties[]`、病位/病性的 `evidence`、`nonPharma.monitoring[]`(监测指标追踪,**M04 必填、全项目零处渲染**)、Markdown 深度表(证候分布/子病机/证据链表,结构化存在时被丢弃)。
- 一批走**有损往返**:中成药/西药卡片是「结构化数组→生成 Markdown 表→`findTableByHeaders` 再抓回」,表头/文案一变就抓空——这就是用户反馈"中成药/西药丢失"的高危单点。
- 一批被**预览打码**:`sanitizePreviewMarkdown` 把"西药/中成药方案"整段替换为占位句、擦除剂量,预览期必然看不到。
- 一批被**黑话遮住成品感**:顶部进度条直接写 `M01采集/M02追问/M03辨证/M04方药/M05随访`;报告里"灵犀统一审方引擎""结构化输出""模型响应完整性提示""服务端知识契约复核"。

**结论**:先"接通 + 去有损 + 清黑话"(桶 A/B/D),我方观感立刻追平甚至超过参考(我们有证据绑定,参考没有);再补少数真缺能力(桶 C,随症加减为首)。入口形态与追问节奏(桶 E)是产品取舍,需你拍板。
