# 中医 CDSS 整改方案（伴随式重构 · 对齐清单）

> 来源：重读 `docs/中医CDSS_ReAct开发架构文档.md`、`docs/中医CDSS_交互流程与数据契约文档.md`、两份审计、`final-clinician-report.md` 恢复的原始规格 + 当前实现逐文件核对。
> 目的：把当前"门控优先"改回 docs 本来的"**伴随式（companion）优先**"，并找回丢失的特性、修 UI、接真实审方。
> 行号会漂，以函数名/字符串为准。

## 0. 总原则（docs §3原则5/6、§5、§6 明文）

1. **只有主诉必填**，其余"用啥填啥"。缺项是否追问，由算法按"**是否影响本次 (a)辨证 / (b)红旗排查 / (c)候选处方安全**"三条件判断，不是一刀切必填（§3原则2、§6.1、§6.3）。年龄/生命体征/检验检查**不作初始必填**。
2. **绝不硬阻断 advisory**。唯一允许硬停的是**确定性安全门**：
   - 急危重红旗 → 转诊/急诊；**M03 仍出风险分析与鉴别**，只停剂量级 M04（companion，非会话终止）。
   - 妊娠/哺乳阳性、儿童无剂量规则、危急生命体征 → 不自动出剂量级医嘱。
   - 其余（完整度不足 / 结构校验失败 / 缺舌脉）→ **一律"照出草稿 + 就地标注 caveat"，流程照走**。
3. 审方（灵犀）**不裁决、不锁流程**：PASS/提醒/人工复核/BLOCK/不可用都只生成**分级风险提示**，不改诊疗阶段、不锁候选方案（§9末、§11条5）。
4. **信息含量/熵驱动追问**：只问高信息量问题；≤1 轮追问；追问是"并列可选补充"，不是前置门。
5. **精准利用有限信息，不追求大而全**：给啥用啥，分析有理有据即可。

## 1. 去阻断清单（把"扣留 advisory"的门改成 companion）

安全门本身已对红旗做对（`evaluateSafetyGate`：红旗时 `allowDiagnosis=true`）。要改的是下列**扣留 advisory** 的点：

| 编号 | 位置 | 现状（阻断） | 改成（伴随） |
|---|---|---|---|
| D1 | `diagnose/route.ts` | 主诉缺失→整份降级模板 | 保留（主诉是唯一必填，可接受） |
| **D2** | `canProceedToM03AfterFollowup` @ `diagnosis-safety.ts:626` | completeness≠C 时强制"先追问≥1轮"才放行 → **点了追问还卡** | 有可辨证信息就出 M03；追问降为并列可选补充，不作前置门 |
| **D3** | `diagnose/route.ts` 传 `truncateFallback` + `STREAM_REPLACE_MARKER` @ `diagnosis-api.ts:~787` | M03 结构 JSON 未闭合 → 用"未完成"整体替换掉模型已写的辨证正文 | **保留可见辨证正文**，仅追加 caveat「结构化校验未通过，以下为草稿供参考，请医生核对」；仅锁剂量级 M04 |
| **P3** | `prescribe/route.ts` completeness≠C | 清空 M04 | ✅ 已改为"有限信息候选"（继续该做法） |
| **P4** | `prescribe/route.ts` `!isStableM03Reasoning` | 缺主证/病机链就整块降级 | 有部分辨证就出候选 + caveat，不整块清 |
| **P5** | `prescribe/route.ts` M04 `truncateFallback` | M04 截断 → 清空 | 保留可见候选 + caveat；剂量级锁定 |
| 保留 | `evaluateSafetyGate` red_flag / `FORCE_PROCEED_HARD_MISSING`(safety.ts:1308) | 红旗→转诊；妊娠/儿童/危急→不出剂量 | ✅ 正确安全硬停，不动 |

**根因单点**：`diagnosis-api.ts` 的 `STREAM_REPLACE_MARKER`——任何结构/完整度失败就整体替换正文。改这一处（保留正文+caveat）是最高杠杆。

## 2. 找回丢失的特性（对照数据契约 §6/§7/§9）

| 特性 | 现状 | 要补 |
|---|---|---|
| **西医诊断** | M03 已在 Markdown 产出，但 **V2 JSON 无字段、`ResultTabsV2` 不渲染**（只有废弃兜底卡有 `summary.westernDiagnosis`） | ①`diagnosis-types.ts` 加 `overview.westernDiagnosis`；②M03 prompt 把它写进 sentinel JSON；③V2 顶部加"西医诊断"板块渲染 |
| **兼证** | 只 Markdown 有；JSON `overview` 只有单 `primarySyndrome` | `overview.secondarySyndromes: string[]`；主证候旁渲染兼证 |
| **调候 / 健康处方（nonPharma）** | 契约有 `nonPharma{diet,lifestyle,emotion,acupointCare,monitoring[]}`，前端"调护随访"也渲染，但 **M03/M04 永远填 null → 空白** | 让 M04（或 M03）**实际产出 nonPharma**（prompt 加槽位）。这就是你说的"调候没了" |
| **中成药 / 西药** | `formula.patentAndWestern` 是 `unknown[]` 占位（无 zod、无字段）；M04 无输出槽位；前端从不渲染 | ①定义 schema；②M04 prompt 加槽位（**证据门槛：无说明书/指南证据不出具体药名剂量**，§9）；③前端"候选方药"下加"中成药/西药"Tab |

### 建议契约字段（可直接抄进 `diagnosis-types.ts`）
```ts
// overview 里新增：
westernDiagnosis?: {
  primary: { name: string; status: "考虑"|"需排除"|"证据不足"; confidence: "高"|"中"|"低"; supportingFacts: string[]; contraryFacts: string[]; };
  differentials: Array<{ name: string; reason: string; nextCheck?: string }>;
} | null;
secondarySyndromes?: string[];   // 兼证

// formula.patentAndWestern 从 unknown[] 改为：
patentAndWestern?: Array<{
  type: "西药" | "中成药";
  name: string; spec?: string; dosageBound?: string; course?: string;
  positioning: "联合治疗" | "替代方案" | "短期对症" | "暂不生成";
  targetProblem: string; relation?: string; riskNote?: string;
  evidence: EvidenceRef;
}> | null;
```
> ⚠️ 灵犀只审 `herbs[]`（中药饮片）。中成药/西药若带剂量，需**单独送审或明确标"需药师复核"**，别默认已审。
