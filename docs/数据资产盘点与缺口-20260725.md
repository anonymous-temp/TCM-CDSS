## 0. 最重要的三条

### ① 【已修复】146,407 条古籍证据在生产环境**从未被读取**

线上（`next build` standalone / Docker 镜像）实测：编译产物里资源引用常量 `e.R(...)` **全篇只出现一次**，指向 44MB 旧语料；292MB 的 tcmoc 语料被打包进镜像却**没有任何代码引用它**。

原因：加载器写成「路径数组 + 循环里 `new URL(变量)`」，Turbopack 只能静态求值字面量实参，追不到循环变量，把整个循环体折叠成同一个资源常量。

两层后果，都不报错：
- 146,407 条 tcmoc 证据线上全失效——P0 那批 701 部古籍入库在生产**零效果**；
- 旧语料被循环读了两遍，55,127 条记录内存翻倍，医生看到**成对重复**的引用，top-12 实际只有 6 条不同证据。

**为什么两周都没发现**：`npm run dev` 下 `new URL` 正常求值，一切正常；`jiti` 单测走的也是源码语义。42 个确定性套件全绿也证明不了线上生效。

> 已修：每语料一条独立字面量 URL。重建后产物含两个不同资源常量，两语料均被读取（55,127 + 146,407 = 201,534）。
> 新增 `test:classic-evidence-bundling` 钉住写法，已验证它在旧写法下会失败。

### ② 【已修复】M03 提示词自己抵消了口语召回层

方剂检索段被拼两次，而**提示词那次不传 recallHint**。口语病例确定性召回为 0，提示词就写「未命中受控经典方主治索引，必须说明未采用经典方」，随后证据段才附上候选——模型先读到前者。

实测「腰杆子疼得直不起来，晚上翻身都费劲，脚发凉」：修复前提示词写"未命中"，修复后直接列出右归丸/右归饮/七味都气丸。

> 这是口语检索此前几乎不生效的直接原因。已修：只拼一次，路由把 hint 传进去。

### ③ 【已修复】治理裁定变成了候选入场券

`curatedBoost` 恰好等于准入线 2 且直接加进 `score`。任何带治理标签的方零证据即可入场（神应养真丹在"周身不适"下自身证据分 1.31 → 加权 3.31 入场）。**治理做得越多，噪声越多。**

> 已修：拆分 `evidenceScore`（准入）/ `score`（排序）。

## 2. 【重要】工程风险：两个未纳入版本控制的必需产物

| 文件 | 大小 | 状态 |
|---|---|---|
| `src/data/tcm-classic-text-evidence-tcmoc.jsonl` | 292MB | **未跟踪、未 ignore**——干净克隆/CI 拿不到它，缺失是**静默的** |
| `中医补充数据/` | 2.3GB | **未跟踪、未被 .dockerignore 排除**——`docker build` 会把 2.3GB 原始语料塞进 build context |

`tcm-classic-evidence.server.ts` 对缺文件是静默 catch（语料本就可选），所以换机部署只会**安静地少一半证据**。本次已让逐语料条数可观测（`classicEvidenceCorpusStatus()`），但**是否入库（Git LFS / 构建期生成 / 镜像层单独挂载）是你的决定**，我没有替你定。

同样值得注意：修好 tcmoc 加载后，首个 M04 请求会同步阻塞约 1s、常驻内存推到 1.5GB 量级。**docker-compose 若无对应 memory limit 调整，这是真实的 OOM 风险。**

## 4. 【新发现】T15 切片器本身丢了一半原文

### 4.1 MIN_CHARS=200 整段丢弃短条目

`tcmoc-evidence-slicer.mjs:92` —— `if (buf.length >= MIN_CHARS) yield`。

144,161 个 `<篇名>` 条目中 **72,747 个（50.5%，791 万字）被整段丢弃**，其中：
- **13,920 个条目的篇名就是方名**（汤/丸/散/丹/膏/饮/煎/酒/锭/饼结尾）
- **10,946 个条内含剂量原文**

最惨的几部：
```
050-名医别录     804 个篇名中 777 个(97%) <200字 → 几乎全丢
101-药性切用     737 中 733(99%)
110-惠直堂经验方  971 中 924(95%)
```

**本草药性条与单验方条正是结构最规整、临床最可用的部分，却 100% 落在丢弃区。**

> 修法是确定性的（短节保留为独立记录，或按 `<目录>` 父章节合并短节），**不需要 LLM**。

### 4.2 9 部书产出 0 条，manifest 谎报 `emptyBooks: []`

实测：输出里只有 **692** 部书，源目录 **701** 个文件。manifest 写 `books: 701, emptyBooks: []`。

零产出的包括：
```
681-赵绍琴临证验案精选上   （温病名家验案）
700-李培生老中医经验集     （伤寒名家）
697-止园医话
615-外经微言   622-诸脉主病诗   533-食疗方
052-孙真人海上方   685-复泰草堂医论选
《吴普本草》《新秀本草》
```

**缺陷被静默吞掉，且任何基于 manifest 的完整性测试都测不出来。**

### 4.3 其余切片器缺陷

- 方名识别只用 T8 目录名 + 目录内 7 个 aliases；独立的 `tcm-formula-aliases.json`（16 条异文）**因取值路径写错被整表丢弃**，12 个别名（肾气丸/复脉汤/葛根芩连汤/苓桂甘枣汤…）从未参与正则。
- `tier` 与 `safetyClass` 对全部 701 部**硬编码为 canon / standard**，包含明显的现代著作。构建期零隔离，唯一防线是运行时正则（实测只滤掉 596/146407 条，其中 286 条带方名）。修好加载后，《本草纲目》泛提及会与《伤寒论》条文同处最高层级。
- **方书批白名单漏掉全部宋唐大型官修方书**——`太平惠民和剂局方` 缺席，而它是中成药与经典名方的第一出处底本。

### 4.4 古籍证据实际对模型的约束力接近于零

证据在医生侧的落点只有一个：M04 提示词里一行「经典证据 `<id>`：`<citation>`；锚点=…；层级=…」。

**原文 excerpt 被计算出来后在这条路径上直接丢弃——古籍正文一个字都没进提示词。** 模型只拿到标识符和出处标签。

另外 `candidate.classicEvidence`（唯一携带 excerpt 的通道）：resolver 固定 `slice(0,12)`，schema 是 `.max(6).optional().catch([])` → **7~12 条一律被 zod 静默清空**；且没有任何 UI 组件读取该字段。

## 6. 模型调用点全景（17 处）

13 处运行时可达 / 3 处仅健康探针 / 1 处死代码。分工详见 `docs/开放自然语言检索架构与LLM分工-20260725.md` §6。

### 几处与文档不符，值得你知道

- **`thinking` 开关代码默认值与 `.env.example` 相反**：代码里 `PRIMARY_TEXT_THINKING_ENABLED` 未设置时为 `true`（`!== "false"`），`.env.example` 写的是 `false`。M02 若未显式设置会开思考模式——而项目已知陷阱正是"只返回 reasoning_content 无 content 视为错误"。**这条默认值差异会放大该故障面。**
- **"独立复核"在默认全 V4-Pro 配置下不是跨模型**：候选链去重后只剩 1 个模型身份，`independentFromGenerator=false`，实际是对同一模型的 2 次无对话状态请求。代码注释与 `.env.example` 已如实说明，但 **AGENTS.md 的"默认取对侧阶段模型做交叉复核"与默认配置不符**。
- **M05 不是"完全确定性"**：CLAUDE.md/AGENTS.md 都写 assess 不调 LLM，但临床事实回补层被 7 个路由调用**包括 M05**；指纹未命中缓存时会触发 extract+review(+adjudicate) 多次模型调用。
- **M04 修复轮的 `reasoning_effort` 硬编码 `"medium"`**，没有任何环境变量能改；`PRIMARY_PRESCRIBE_REASONING_EFFORT` 只作用于首轮。运维按它调参不会影响修复轮。
- **M01 文本路径根本不调模型**（无舌照时直接返回确定性 NDJSON），`"deepseek"` 分支不可达。CLAUDE.md 表格会让人误以为文本也走模型。
- **无 `PRIMARY_COLLECT_MODEL` / `PRIMARY_QUESTION_MODEL`**：AGENTS.md 称 M01/M02 可独立配置，实际不存在；M02 只能跟随 `OPENAI_MODEL`。
- 4 个 `.env.example` 变量无任何消费者（已注明 RESERVED，属如实标注）。
