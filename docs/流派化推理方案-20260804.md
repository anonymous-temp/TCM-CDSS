# 流派化推理方案（2026-08-04）

> 目标：让 CDSS 能按医生选定的**学术流派**调整辨证取向与选方偏好，且**主体推理流程不变**。
> 落法：流派只作用于「提示词取向 + 外围知识配套 + 规则层排序偏置」三处，不新增推理阶段、
> 不改 M01–M05 编排、不触碰确定性安全层。

> **2026-08-28 勘误**：本文旧版把「温补/扶阳」合写为一个方向。实现与对外契约现已拆为
> `warm-tonify`（温补学派）和 `support-yang`（扶阳学派/火神派）；下表合并行只保留作历史记录。

---

## 1. 先回答「现有知识库能支持哪些流派」

判据是**可确定性关联的数据量**，不是"这个流派有名"。逐项实测：

| 流派 | 现有数据锚点 | 可关联方剂数 | 结论 |
|---|---|---|---|
| **经方（伤寒金匮）** | 受治理目录 `provenance` = 《伤寒论》57 +《金匮要略》53；**鉴别图 167 条边**（桂枝汤/麻黄汤、大小柴胡…）出自经方体系 | **110** | ✅ **强支持** |
| **温病** | 已有 `test:warm-disease-rules` 确定性规则套件；卫气营血分期在受治理证候词表中有完整轴（wei/qi/ying/blood_level） | 银翘散、桑菊饮、清营汤等（目录内） | ✅ **强支持** |
| **脾胃（李东垣）** | 受治理病位词 spleen/stomach + 治则词表「补中益气/升阳」；补中益气汤、归脾汤等 | 目录内可检 | ✅ **可支持** |
| **滋阴（丹溪）** | 病性词 yin_deficiency + 治则「滋阴降火」；六味地黄丸、大补阴丸等 | 目录内可检 | ⚠️ **弱支持**（缺流派专属鉴别数据） |
| **温补学派** | 脾肾、命门、阴阳互根与温养补虚；《景岳全书》等 | 目录内可检 | ⚠️ **弱支持**（流派专属鉴别仍需治理） |
| **扶阳学派（火神派）** | 郑钦安传承、重视阳主阴从与姜桂附运用 | 目录内可检 | ⚠️ **弱支持**（毒性药与适应证边界必须独立治理） |
| 孟河 / 岭南 / 海派等地域医派 | **无任何结构化数据锚点**（代码里只有 UI 选项文案） | 0 | ❌ **不做**——没有知识就"模拟流派"只能靠模型编，正是要根除的那类问题 |

**建议首批只做 3 个：经方、温病、脾胃。** 它们各自都有独立的确定性数据面，做出来的差异是**可验证**的，不是话术差异。滋阴与温补列入第二批，待补齐流派专属鉴别数据后再开。

代码现状要一并纠正：`src/lib/tcm-lineages.ts` 里已有 13 张卡片，但 `code` 与 `label` **错位**（`empirical-formula` 显示成"学术流派"、`warm-disease` 显示成"地域医派"），且只有 1 张 `active`。这是既有缺陷，接入前必须先修，否则医生选的和系统认的不是同一个流派。

## 2. 三层落法（从轻到重，全部不改主流程）

### 层一：提示词取向（最轻，效果最直接）

在 M03/M04 prompt 里注入一段**流派取向声明**，只影响"同等证据下优先怎么想"，不改变结论必须有据可循的硬约束。

- 经方：优先六经辨证框架；先辨病位（表/里/半表半里）与病性（寒热虚实），再落方；优先原方原量比例，加减从简。
- 温病：优先卫气营血/三焦分期；重视舌象与热势演变；透热转气、顾护津液。
- 脾胃：优先中焦升降；重视纳运、大便、乏力；甘温除热、升阳益胃。

**边界（必须写进 prompt）**：流派取向**不得**推翻红旗、剂量上限、配伍禁忌与"证据不足即标注"的要求。
`tcm-lineages.ts` 里已有 `LINEAGE_SAFETY_OBEDIENCE` 常量正是干这个的，复用它。

### 层二：外围知识配套（中等，决定"能不能真用上流派知识"）

每个流派挂一份**受治理流派知识包**，M03/M04 检索证据时按流派加权，而不是另起一套检索：

```
src/data/tcm-lineage-knowledge.source.json
  经方  → 锚点：provenance ∈ {伤寒论, 金匮要略}；鉴别图 167 条边全量启用
  温病  → 锚点：warm-disease-rules + 卫气营血证候轴
  脾胃  → 锚点：病位 spleen/stomach + 治则「升阳/补中/益气」词条
```

关键设计：**知识包只做加权，不做过滤**。选了经方不等于禁用时方——否则遇到经方覆盖不到的病就无方可用，那是把流派做成了枷锁。

### 层三：规则层协同（最关键，也最容易做重，要克制）

只做**一件事**：候选排序偏置。

```
finalScore = baseScore × (1 + LINEAGE_AFFINITY_BONUS × lineageMatch)
```

- `lineageMatch` 由**受治理数据**判定（出处/证候轴/治则词命中），不是关键词
- `LINEAGE_AFFINITY_BONUS` 建议 0.2–0.3，量级刻意小于证据分与轴匹配分——流派是**偏好**不是**判据**
- **不做**：不因流派排除任何方、不因流派改变剂量、不因流派跳过任何安全校验

理由：我们刚在中成药通路上确认过，"排除"这个动作只有在有法定依据（说明书禁忌、鉴别图反证）时才站得住。流派是学术取向，不构成排除依据。

## 3. 验收标准（不可验证的差异等于没做）

| 检查项 | 方法 | 通过线 |
|---|---|---|
| 流派可辨别 | 同一病例分别选经方/温病/脾胃，比对 M04 首选方 | 至少 2/3 组出现**有临床解释力**的差异 |
| 流派不越权 | 红旗病例 + 任一流派 | 红旗处置与非流派模式**完全一致** |
| 流派不降质 | 全量金标准回归分别跑三个流派 | recall 与证-方一致性**不低于**默认模式 |
| 数据可溯 | 每条流派加权都能回答"依据哪条受治理数据" | 100% |

第 3 项是重点：流派最大的风险不是"做得不像"，而是**为了像而牺牲正确性**。宁可流派特征弱一点，也不能让选了经方的医生拿到更差的方案。

## 4. 工作量与顺序

| 步骤 | 内容 | 规模 |
|---|---|---|
| 0 | 修 `tcm-lineages.ts` 的 code/label 错位（既有缺陷） | 小 |
| 1 | 建 `tcm-lineage-knowledge.source.json` + 生成器（3 个流派的受治理锚点） | 中 |
| 2 | M03/M04 prompt 注入流派取向段 + 复用 `LINEAGE_SAFETY_OBEDIENCE` | 小 |
| 3 | 召回层加流派亲和度偏置（一个乘数，接在现有排序后） | 小 |
| 4 | 回归套件 `test:lineage-reasoning`（四条验收标准全钉） | 中 |

**主体推理流程零改动**：不新增阶段、不改 NDJSON 契约、不改安全门、不改合同校验。
对甲方页面**零影响**：流派是既有 `lineage` 入参的语义增强，接口形状不变。

---

## 5. 明确不做的事

- ❌ 不做地域医派（孟河/岭南/海派）——无数据锚点，只能靠模型编
- ❌ 不让流派影响剂量、配伍禁忌、红旗、特殊人群门禁
- ❌ 不让流派**排除**候选方
- ❌ 不为流派单开推理链路或新阶段
