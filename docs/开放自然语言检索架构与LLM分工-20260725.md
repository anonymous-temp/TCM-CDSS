# 开放自然语言 → 方剂：检索架构与 LLM 分工

> 2026-07-25。所有数字为本机实测（目录 1796 首受控方，证候词表 2050 条）。
> 回答的问题：**处方与证候一一绑定，而医生输入是开放自然语言，这中间怎么接。**

---

## 0. 先说结论

**你的判断对了一半，但错的那一半更重要。**

对的一半：处方确实与证候绑定。`namedFormulaPositiveSufficiencyIssue` 要求签名主证候与方剂之间存在**受控关系**，否则方名会被剥离、降级为自拟方。这是安全设计，不能动。

错的一半：**M03 之前的检索并不走证候**。它是纯粹的"症状字面串 ↔ 主治原文字面串"重合度打分——1796 首方的主治原文做 2–4 字滑窗倒排，加 39 条手写概念正则。证候标签只在**排序**时用（可锁定的排前面），不参与召回。

所以真实的架构是这样，中间缺了一层：

```
医生自由文本 ──[口语归一]──> 症状词 ──[字面重合]──> 方剂候选 ──> 模型辨证 ──> 证候 ──[受控关系]──> 锁方
                                        ↑                                      ↑
                                    现在在这里                            门禁在这里
                                    （不认识证候）                        （只认证候）
```

**召回按症状选方，锁方按证候验方，两端口径不一致。** 这就是为什么会出现"检索给了 5 个方，模型选了一个，然后被剥离"。

## 1. 现状实测：它到底有多不准

用三个标准病例跑 `retrieveTcmFormulaIndicationCandidates`（M03 前的候选短名单）：

| 病例 | 期望 | 实际 Top 6 | 判定 |
|---|---|---|---|
| 心脾两虚（失眠+心悸+纳呆+便溏） | 归脾汤 | 交泰丸、人参归脾丸、天王补心丹、**归脾汤(第4)**、逍遥散、八珍汤 | 勉强 |
| 肝火扰心（失眠+急躁+口苦+目赤） | 龙胆泻肝汤 | 二至丸、交泰丸、酸枣仁汤、防风通圣散、血府逐瘀汤、炙甘草汤 | **全错** |
| 风寒感冒（恶寒发热+无汗+头痛） | 麻黄汤/桂枝汤 | 葛根汤、香薷散、九味羌活汤、参苏饮、川芎茶调散、再造散 | **全错** |

**肝火扰心那例最能说明问题**：Top 1 是二至丸（肝肾阴虚，滋补），而患者是肝火（实热，需清泻）。**治疗方向完全相反**。原因是二至丸主治里同时出现"口苦""失眠""多梦"三个词——字面重合度最高。

字面重合永远分不清"失眠属心脾两虚"还是"失眠属肝火扰心"，因为**区分它们的信息（便溏 vs 口苦目赤）是一个证候判断，不是一个词**。

## 2. 为什么不能靠"把概念表做全"

现在是 39 条手写正则。你问过"穷举检索概念穷举得完吗"——答案是穷举不完，而且方向就是错的：

- 症状表述是开放的（"睡不着""失眠""不寐""不得眠""夜不能寐""睁眼到天亮"）；
- 但**真正的组合爆炸不在症状侧，在证候侧**。2050 个受控证候，每个由 2–4 个症状轴组合定义，手写规则要覆盖的是组合数而非词数。

所以正确做法不是把词表做全，而是**换一层做匹配**：不匹配"词"，匹配"证候假设"。

## 3. 设计：三层检索，中间补上证候假设层

```
医生自由文本
   │
   ├─ L0 口语归一（flash）        已有，已接线 ✅
   │    口语 → 标准术语 + 古今双写（失眠→失眠/不寐/不得眠）
   │    并集语义：只加检索词，不改病历事实
   │
   ├─ L1 证候假设集（新增，本文核心）
   │    │
   │    ├─ L1a 确定性轴过滤        零模型
   │    │     症状 → 病位/病性轴 → 过滤 2050 证候闭集
   │    │     依据：证候词表 1959 条带 locations、1918 条带 natures
   │    │
   │    └─ L1b 闭集语义排序（flash）
   │          在 L1a 过滤后的候选里选 Top-K
   │          闭集约束：只能选给定 id，选不出就返回空
   │
   ├─ L2 双路召回（并集）
   │    ├─ 症状路：现有字面重合（保留，不动）
   │    └─ 证候路：L1 假设证候 → syndromeToFormulaIds（现成索引，已有）
   │
   └─ L3 合并排序
        两路都命中的排最前（这才是"方证相应"的信号）
        单路命中的保留为鉴别参考
        准入仍只看检索证据分（本次已修：治理加权不再当入场券）
```

### 为什么这个设计是安全的

判据是两条，缺一不可：

1. **并集语义**：L1 的输出只用来**增加**召回路径。flash 挂了 → 证候路为空 → 退回今天的纯症状召回，不多不少。它不能删候选、不能改病历、不能锁方。
2. **失败是降级不是危险**：证候假设错了，最坏结果是多给医生几个不相关的鉴别方；而**锁方门禁完全不看 L1 的假设**，只认 M03 签名后的证候。假设与裁定是两条独立的路。

对照：剂量、药味身份、方名锁定这三处是**替换语义**（模型给的值会替掉正确值），所以那三处一律不许模型参与。这条线是整个系统的安全轴。

## 4. L1a 怎么做（确定性部分，零模型）

证候词表已经带了轴，这是现成的可用资产：

```
TCM-SYNDROME-35EFC6DED4E1  阴证
  locations: ["interior"]
  natures:   ["cold", "deficiency"]
```

建一张 **症状 → 轴** 的确定性映射（这是要新建的唯一数据表），例如：

| 症状词族 | 病位轴 | 病性轴 |
|---|---|---|
| 便溏、纳呆、腹胀、神疲 | spleen | deficiency |
| 口苦、目赤、急躁易怒、胁痛 | liver | heat, excess |
| 畏寒肢冷、腰膝酸软、夜尿多 | kidney | cold, deficiency |
| 恶寒发热、无汗、脉浮紧 | exterior | cold, excess |

命中轴后，从 2050 个证候里过滤出**轴一致**的子集。肝火扰心那例：`liver + heat + excess` → 候选收缩到几十个，二至丸对应的"肝肾阴虚"（`deficiency`）直接出局——**这是纯确定性的，不需要模型**。

> 注意 `governance.scopeNote` 已声明 locations/natures 是"项目规则派生候选，不等同于标准定义"。所以它们只能用于**召回过滤**，不能用于诊断结论。这与本设计一致。

## 5. L1b 怎么做（flash 部分）

L1a 之后仍有几十个候选，靠轴分不开（"肝火上炎" vs "肝火扰心" vs "肝胆湿热"）。这一步交给 flash，形态与既有的 `syndrome-tag-candidate-mapping.mjs` 完全一致：

- 注入 L1a 过滤后的**闭集**（id + 名称），最多 40 条；
- 模型只能返回给定 id，返回集外 id 一律丢弃；
- 返回空是合法输出（"候选不覆盖"），不惩罚；
- 6s 超时，失败返回空集 → 退回 L1a 的轴过滤结果。
- 有效结果只能把既有 L1a 假设分数上调 0–20%，不得删除候选或取得诊断/锁方权限。

当前实现位于 `src/lib/syndrome-hypothesis-rerank.server.ts`。真实
`deepseek-v4-flash` 连续 5 例探针全部在 1.843–2.321s 返回 8 个有效闭集结果；关闭扩展思考、
限制 Top 8 和 500 tokens，避免模型把短 JSON 预算耗在推理内容。超时、空正文、非法 JSON、
候选外 ID、重复 ID 和越界分数均回退/隔离。

### 分工的判据（不是按"重要性"，按语义）

> **替换语义用 pro，并集语义用 flash。**
>
> - 模型输出会**替掉**一个本该正确的值（诊断、方名、剂量、复核结论）→ pro，且必须有确定性校验兜底。
> - 模型输出只是**多加一条**检索路径 / 多加一个候选 / 多删一个不当追问 → flash，失败即降级。

按这条线，L1b 明确属于 flash：它加的是召回路径，不是结论。

### 需要新增的环境变量

现有的 `CONTROLLED_TERMINOLOGY_MODEL`（默认 `deepseek-v4-flash`）覆盖所有 flash 辅助层，
L1b 直接复用，**不需要新增模型变量或凭据**。仅增加运维开关
`SYNDROME_HYPOTHESIS_RERANK`，默认开启，显式设为 `false` 时完整回退 L1a。

以下两个既有开关现已补进 `.env.example` / `docker-compose.yml`，默认开启且可由运维显式关闭：
- `FORMULA_RECALL_NORMALIZATION`
- `POLARITY_NEGATION_ASSIST`
- `SYNDROME_HYPOTHESIS_RERANK`

## 8. 已知会限制上限的两个数据事实

**① 75.8% 的受控证候一首方都没有。** 2050 条非表头证候中 1554 条零方。一旦 M03 签出这些证候，`retrieveTcmFormulaCandidatesForReasoning` 返回空，M04 只能自拟方。L1b 再准也解决不了——它能把假设收敛到正确证候，但那个证候下没有方。

**② 证候→方分布被粗词占据。** 497 个有方的证候，均值 4.31 首、中位数 2 首；Top 10 里 9 个是"风寒/气虚/湿热"这类单因素粗词（风寒挂 58 首）。命中粗词灌进几十首无鉴别力的方，命中精细证候常常只有 1–2 首。

这两条决定了：**证候路召回的天花板取决于方-证关系表的治理进度，不取决于算法。** 241 条裁定入库后全链路可达从 30.2% 升到 43.7%，就是这条路径的直接证据。

## 10. 一条不能越过的线

L1 全链路（L1a + L1b）产出的是**假设**，只进检索。

医生看到的证候、方名、剂量，仍然只能来自：
- M03 模型在完整病历上的辨证 → 经确定性契约校验 → 经独立复核 → 签名；
- 方名锁定 → `positiveSufficiency`（签名证候与方剂的受控关系）；
- 剂量 → M04 独立编译 → 处方后审方。

**检索可以猜，结论不可以猜。** 这条线不因为检索做得更好而放松。
