## 一、先厘清一件事：我们不训练模型，"污染"的定义不一样

对训练模型的团队，污染 = **测试数据进了训练集**，边界在数据文件。

我们不训练模型。我们的"学习"发生在**人写规则、人补词表、人调提示词**的时候。所以：

> **污染的边界是「谁看过哪条病例」，不是「数据放在哪个文件夹」。**

这条推论很实际——同一份数据，三种用法的污染风险完全不同：

| 用法 | 会不会污染 | 为什么 |
|---|---|---|
| 中医师看着某例写鉴别边 / 调词表 | **会，且永久** | 规则被拟合到该例，它再也不能证明泛化 |
| 只统计标签分布，找覆盖缺口（哪些证型对没有边） | 不会 | 没有人读个案内容去拟合；产出是「缺哪类边」，不是「这例该怎么判」 |
| 跑一遍看我们输出什么，**不据此改规则** | 不会 | 纯观测 |
| 跑一遍发现错了，去看那条病例、定位缺陷 | **会** | 一旦看了，该例就从测试集掉出去 |

所以光有文件夹隔离没用，必须有**流程纪律 + 留痕**。见第四节。

## 二、三种用途的价值与风险，差别很大

| 用途 | 价值 | 风险 | 判断 |
|---|---|---|---|
| **外部记分牌**（第三方口径的分数，给医院看） | 高 | 低 | **做** |
| **覆盖缺口分析**（哪些证型对缺鉴别边） | 高——正是 v2 里 T5′ 缺的那份数据 | 低 | **做** |
| **直接摄入知识库 / 规则库** | 中 | **高**（见下） | **第一阶段不做** |

### 为什么"直接摄入知识库"风险高——三条都是实测的

**① 标准口径差 26 年。** 我们的证候词表是 **GB/T 16751.2-2021**（2060 条完整索引，`sourceRefs: SRC-GBT-16751-2-2021`）；TCM-SD 归一到的是 **GB/T 15657-1995**。直接拿外部标签写进我们的表，等于把两个相隔 26 年的国标混在一起，而且是在**证候身份**这个最不能含糊的维度上。

**② 会破掉我们已有的版权纪律。** 我们对国标定义**只存 SHA-256 指纹、不复制定义原文**（`definitionSha256` + `definitionReproductionPolicy`）。外部评测集的专家标注若整段摄入知识库，等于对别人的数据放弃了我们对国标都在守的纪律。

**③ 证据等级会失真。** 我们 KB 条目的 `basis` 是药典、国标这一级。来自公开评测集的专家标注是**更弱的证据等级**——它是为评测标注的，不是为处方决策核定的。混进去而不分级，`basis` 字段就不再能表达"这条有多硬"，而整个 fail-closed 体系是建立在这个字段可信的前提上的。

**结论**：外部数据可以用来**评测我们**、可以用来**告诉我们缺什么**，但不能**直接成为我们说话的依据**。真要补进知识库，路径只有一条：外部数据 → 指出缺口 → **中医师按药典/国标重新核定** → 以我们自己的证据等级入库。中间那一步不能省。

## 三、可执行方式：复用我们已有的 evaluationOnly 模式

不需要发明新机制。仓库里已有成熟先例：

`tcm-classic-case-eval-corpus.json` / `tcm-modern-case-eval-corpus.json`

```
evaluationOnly: true
runtimeRetrievalAllowed: false
safetyBoundary: "仅保留结构化标签和经逐句过滤的患者事实用于离线/授权回放；
                 删除剂量、方名句、疗效承诺、反现代医学言论和可执行处置。"
commentaryRemoved: true
sourceClaimAudit: { claimedCaseCount: 849, importedDistinctStructuredBlocks: 364,
                    status: "source_material_below_claimed_target",
                    note: "参考包可定位的结构化病例块少于文档宣称数量；不得复制或合成病例凑数。" }
```

且 `src/` 下无人引用，只有评测脚本读——**运行期物理上拿不到**。

那条 `sourceClaimAudit` 尤其要照抄：宣称 849、实际导入 364，**如实记下差额并写明不得凑数**。接外部数据最容易出的问题就是"论文说有 300 例，实际拿到 180 例，报告里还写 300"。

## 四、回归用例分层：按「谁能看」隔离，不按文件夹

这是你要的「标准化回归测试用例集合」的核心设计。

| 层 | 谁能看 | 用途 | 轮换 |
|---|---|---|---|
| **L1 开发可见集** | 中医师、工程师随便看 | 写规则、补鉴别边、定位缺陷、做覆盖缺口分析 | 只进不出 |
| **L2 封存回归集** | **任何人不得据此改规则**；只在闸门里跑并报分 | 持续回归、发布前把关 | 见下 |
| **L3 盲测集** | 只在发版评审/交付验收时跑一次 | 给医院的第三方口径分数 | 不轮换，最小 |

### 关键机制：L2 → L1 单向流动 + 留痕

一旦有人为了修某个缺陷**看了** L2 里的某条病例，它就永久污染了：

1. 该例**立即移出 L2、并入 L1**；
2. 在 `docs/回归用例流转登记.md` 记一行：日期、案号、谁看的、为什么看、修了什么；
3. L2 规模因此**只会缩小**——这是设计意图，不是缺陷。缩到阈值以下就该补新例，而不是把用过的放回去。

没有这条，L2 会在几个月内被悄悄看光，分数还在报，但已经不代表泛化能力了。**这是最容易被绕过、也最该硬性留痕的一条。**

### 分配比例（建议）

外部数据集与我们自采病案，都按同一套分层：

- **L1 : L2 : L3 ≈ 5 : 4 : 1**
- L3 最小但最珍贵——它是唯一能对医院说「这个分数我们自己没调过」的东西。
- 分层要**分层随机 + 按证型/科别/期望类别分层**，不能按文件顺序切，否则 L2 里可能一个红旗病例都没有。

### 修改 T5′　鉴别边覆盖缺口分析

数据来源改为 **L1 开发可见集**（含外部数据集的 L1 部分）。产出仍是中医师工作包，但现在有了真实证型分布支撑「哪些边缺了真的会出错」。

### 修改 T2′　反事实基线

基线病例从 **L2** 抽取并**封存**。基线一旦作为对照发布，其病例不得再用于定位缺陷——否则"改动前 vs 改动后"的对照会被污染。

## 七、一个必须先回答的问题

分层要落地，得先有**病例唯一标识**。当前我们自采的 77 条病案有 `id`，外部数据集有各自的 record ID，但：

- 跨来源的 ID 命名空间没有统一；
- 流转登记表要引用案号，ID 不稳定就无法留痕。

**T7′b 开工前先定 ID 方案**：`<来源>-<原始ID>` 形式，来源用受控枚举。这条和 v2 §八提到的「影子审计事实 ID 稳定性」是同一类问题，建议一起解决。
