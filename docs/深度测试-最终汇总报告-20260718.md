# 中医 CDSS 系统深度测试最终汇总报告(2026-07-18)

> 本报告整合 4 轮深度测试发现:① 配置/流程审查 ② 100 条 redflags 确定性回归 ③ 100 条真实 LLM 推理(85 条有效) ④ 100 条多样化用例(部分完成)。站在**极挑剔中医大夫**视角。
> 4 个分报告:`docs/深度测试报告-20260718.md` / `-补充.md` / `-临床质量评估.md` / 本汇总。
> 不改业务代码,仅新增测试脚本与 fixture。

---

## 0. 一句话结论

**功能跑通,临床质量不可用于真实门诊。**

**核心短板**:
1. **配置层不稳定**:dev 启动 `.env.local` 经常失效,严格健康检查 false,模型对调,GLM 独立复核未配。
2. **临床质量不稳定**:有酸枣仁汤、归脾汤这种专业级处方,但更有大量"山药万能君药"、"既往史当现病史"过度医疗、"得温则减"等关键寒热指征误判。
3. **速度不可用**:单病例端到端 218 秒,门诊医生看 30 个号用不起。
4. **开发黑话泄露**:`bounded` 标记 50+/85 条渲染到 UI。

**最迫切三件事**:① 补 GLM 复核 .env ② 修 strictReady false ③ 临床质量改造(既往史不得作现病史辨证、禁山药万能君药、寒热指征识别)。

## 2. P0 — 发布阻断(8 条)

### P0-1 · M03/M04 模型配置对调 + GLM 独立复核未生效
- **现象**:dev log 显示 M03 实际跑 `deepseek-v4-flash`(应 v4-pro),M04 跑 `deepseek-v4-pro`(应 v4-flash);`clinicalReviewModel.provider=openai-compatible`(应 GLM)
- **根因**:`.env.local` 设了 `PRIMARY_DIAGNOSE_MODEL=v4-pro` 但日志显示对调;`PRIMARY_CLINICAL_REVIEW_PROVIDER=glm` 完全没配,reviewer 走同 provider self-review
- **违反设计**:"generator 不能 self-approve"原则失效
- **影响**:M03/M04 输出没有真正独立复核,质量回归内存里"v4-pro+关思考稳定 5/5"的结论不再成立
- **修法**:补 `.env.local` 的 `PRIMARY_CLINICAL_REVIEW_PROVIDER=glm` + `PRIMARY_CLINICAL_REVIEW_API_KEY` + `PRIMARY_CLINICAL_REVIEW_API_URL` + `PRIMARY_CLINICAL_REVIEW_MODEL=glm-5.1` + `PRIMARY_PRESCRIBE_MODEL=deepseek-v4-flash`

### P0-2 · 端到端响应耗时 218 秒
- **实测**:M01 0.4s + M02 26.6s + M03 86s + M04 105s ≈ **218s**
- **影响**:门诊完全不可用
- **耗时大头**:clinical-facts backstop 默认开启(P0-3),每次 red-flags 触发 3 次 LLM(extractor+reviewer+adjudicator),p95 延迟从 1ms(纯确定性)飙升到 4-6s
- **修法**:① 砍 M02(可选)② M03/M04 早期流式 render ③ 拆 M03 为并行子任务 ④ clinical-facts backstop 改异步预取

### P0-3 · `health?strict=1` 返回 `strictReady=false`
- **实测**:`{"ready":true, "strictReady":false, "degradedReasons":["tcm_treatment_capabilities_not_configured"]}`
- **影响**:Docker 健康检查会失败,**部署阻断**
- **根因**:tcm_treatment(针刀/针灸/推拿等 M05 可选增强)未配置作为 strict 阻断条件过于严格
- **修法**:把 `tcm_treatment_capabilities` 移出 strict 阻断集合

### P0-4 · `.env.local` 的 `CDSS_REQUIRE_API_AUTH=false` 不稳定生效
- **现象**:`.env.local` 设 false,但 `npm run dev` 启动后浏览器/curl 都跳 `/login` 或 401。**必须 `CDSS_REQUIRE_API_AUTH=false npm run dev` 显式 export 才生效**
- **影响**:测试脚本/CI 容易 401;运维误用会突然要求登录
- **根因**:Next.js 16 + Turbopack 在 `.env.local` 热重载或 worker 隔离上有 bug
- **修法**:① package.json `dev` script 显式注入默认值 ② cdss-auth.ts 增加 dev fallback

### P0-5 · dev hot-reload 中断推理流程后 UI 状态机不一致
- **现象**:lib 文件改动触发 full reload 时,正在跑的 M02 流程被中断,UI 显示:
  - 主区域:"重点追问 未完成 / 重试本阶段"
  - **右侧栏:"等待病历信息 / 只需填写主诉..."(矛盾)**
  - **表单数据 React state 全清空**(主区域文案说"已保留病历",但实际空)
- **影响**:生产虽然无 hot-reload,但暴露**表单输入态没持久化**真 bug,nginx reload/Docker restart 后医生丢表单
- **修法**:表单输入 debounce 写入加密快照,reload 后 hydrate

### P0-6 · M03 临床辨证质量不稳定,过度医疗模式
- **现象**(85 条真实推理中发现):
  - **NG01/02/04/06/09**:既往已治愈/恢复期病例被强行辨"脾胃气虚/气虚血瘀"并开方
  - **TC11**:痛经"得温则减+月经后期+舌暗苔白"(典型寒凝血瘀)误辨为"气血亏虚胞络失养"
- **影响**:**患者吃了误辨证的方子可能加重病情**(TC11 寒证误补阴养血)
- **修法**:① prompt 加"现病史=本次门诊当前症状;既往已治愈史不得作为辨证依据" ② M03 sentinel 增加 `isHistoricalOnly` 字段 ③ 寒热关键指征("得温则减/喜温喜按")必须正确识别

### P0-7 · 山药万能君药模式
- **现象**:7+ 条虚证用例都用山药当君药(NG01 心气虚/NG02 中风气虚血瘀/NG04 脾胃气虚/NG06/NG09/SP05 肾气虚/TC11 误辨虚证)
- **中医大夫视角**:山药补脾胃肺肾之气,**力度不够君药级**(经典方中山药多为佐使);治心气虚/肾气虚/中风后遗**力度严重不足**
- **修法**:prompt 加"虚证君药应选参芪术草类力度足够者,山药多为佐使"

### P0-8 · bounded 开发黑话大量泄露到 UI
- **现象**:M03 输出 sentinel JSON 里 `primarySyndromeResolution: "bounded"` 等,**全部渲染到 UI**。85 条真实推理中 **50+ 条有 bounded**
- **影响**:违反"清黑话"要求(桶 D);中医大夫/患者看不懂"bounded"是什么
- **修法**:`diagnosis-stream-safety.ts` 的 `sanitizeDiagnoseStreamingDraft` 加 `bounded/resolved/partial` 清洗规则

## 3. P1 — 严重(13 条)

### P1-1 · M02 追问单选强迫二分
"患者近期情绪以烦躁易怒为主,还是以忧思抑郁为主?"二选一 radio。临床烦躁+抑郁混合常见,二分会丢信息。

### P1-2 · clinical-facts 回归测试失败
`scripts/test-clinical-facts.mjs`:`extractor: 独立LLM复核可纠正首轮处置层级` 失败。影响 P1 临床事实兜底核心能力的回归保障。

### P1-3 · tcm-treatment-projects 回归失败
`scripts/test:tcm-treatments`:`negated differentials cannot create a treatment indication` 失败。心神不宁失眠+否认颈椎病,系统却推荐针刀到 P1,且 needle_knife 不应该匹配心神不宁。

### P1-4 · UI 加减工作台 13 味药下拉视觉重复(待人工截图确认)
DOM 实测:`P1·肝气郁结` 块出现 13 次,`君臣佐使` 也出现 13 次。可能是 snapshot 展开所有 option 文本造成的"假象",但需截图确认。

### P1-5 · "综合支撑度 69%" 与 "判断把握度:低" 双口径并存
两个不同口径的"把握度"指标同时显示,数字/文字不一致(69% 似中等,但"低"是低),医生不知道信哪个。docs 类2 标 ✅2a/2b/2d 已修,但这 pair 未归一。

### P1-6 · M02 重复说明 + 状态机延迟清场
"本轮关键追问" 卡片顶部"可点选实际回答..." 与下方"需补充的信息 / 本轮集中核实..." **重复说明**;M04 已 200 完成后,UI 仍长期显示"已耗时 207s · 仍在生成"。

### P1-7 · 纯确定性安全门漏报 4 类急症
100 条 unit 测试(scripts/regress-deterministic-safety-100.mjs)结果:
- RF03 过敏休克(喉头阻塞感)— 漏报
- RF04 呕血黑便(呕咖啡样物) — 漏报
- RF06 急腹症(板状腹) — 漏报
- RF08 产科大出血(孕32周无痛性阴道大出血) — 漏报
- **fail-closed 安全网仍成立**(allowDose=false),但医生可能误以为补完信息就能继续
- TC18 中风后遗症误报为急性神经急症(docs 类5 反向问题)

### P1-8 · clinical-facts backstop 默认开启与内存记录相反
`src/lib/clinical-facts-runtime.ts:305` `return process.env.CDSS_CLINICAL_FACTS_BACKSTOP !== "false"` —— **默认开启**。内存(4 天前)记录的"默认关闭"已过时。导致每次 red-flags 触发 3 次 LLM 调用,端到端耗时翻倍。

### P1-9 · M04 成功率仅 48%
100 条真实推理中 M04 仅 41/85 成功(48%)。失败原因:
- 红旗急症正确 fail-closed 短路(10 条):正确
- 多数 SP/AL 病例被门控阻断:部分合理,部分过保守
- TC02/03/05/09/10/12/14/15/17 等 9 条专科无方:模型/合同问题

### P1-10 · 经典名方命中率仅 2%
100 条只观察到 2 条经典名方(TC08 酸枣仁汤、AL10 归脾汤)。其余 23 条都是"自拟方"(`formulaSelectionMode: "self_devised"`),无学术依据。

### P1-11 · 边界输入(BO04 XSS/BO05 SQL)未清洗就进辨证
- BO04 主诉"头痛`<script>alert(1)</script>`" → M03 辨"头痛 气血不足证" + M04 开方 8 味 — **XSS 字符没被清洗就进辨证**
- BO05 主诉"胃痛'; DROP TABLE--" → M03 辨"胃脘痛 脾胃虚弱" + M04 开方 4 味 — **SQL 注入字符进入**

### P1-12 · M02 失眠病例未问完 OSA 直接拦 M04(已修但有边界)
- 内存 [[m03-config-and-deep-quality]] 记录"失眠病例开方前要过 OSA 筛查"已实现
- 但实测发现边界:如果医生在问诊补充里写"否认打鼾/呼吸暂停/日间嗜睡;血压正常",极性接地校验通过;但如果词与患者症状撞极性会拒整份 M03
- 修法:OSA 阴性项只用与本辨证无关的专属词

### P1-13 · next dev 在长时间负载下崩溃
- 100 条推理跑 ~50 min 后 dev server 崩溃,后 30 条全 FETCH_ERROR
- 影响:生产部署需确认能扛并发;CI/性能测试需考虑这点

## 10. 给用户的最终诚实总结

**问:推理的症候、疾病、诊断、病机等等的都对吗?**

> **能治病的少**。25 条结构化处方里:**4 条经典名方级**(能治病),**8-10 条方向对但力度不够**(山药君系列,等于安慰剂),**5+ 条过度医疗**(NG 系列),**1 条可能加重病情**(TC11 寒证误补阴养血)。

**问:质量都高吗?**
> **不高**。当前质量在中医大夫视角**不可用于真实门诊**。建议**不要直接上线**,先按本报告 P0/P1 改造后再灰度。

**最迫切三件事**:① 补 GLM 复核配置 ② 修 strictReady false ③ 临床质量改造(既往史禁作现病史、禁山药万能君药、寒热指征识别)。
