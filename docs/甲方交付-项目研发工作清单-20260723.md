# 灵犀中医 CDSS 项目研发工作清单

**文档用途：** 项目阶段性交付、研发成果汇总、甲方验收对照  
**统计截止：** 2026 年 7 月 23 日  
**项目名称：** 中医临床决策支持系统（tcm-cdss）  
**当前形态：** 面向门诊场景的中医辅助诊疗“副驾驶”，采用 M01-M05 线性工作流

## 二、既往研发阶段与主要成果

### 1. 产品基础能力建设

- 完成 Next.js 16、React 19、TypeScript strict 的前后端一体化工程。
- 完成门诊中医 CDSS 工作台、登录页、报告区和 M01-M05 流程编排。
- 完成病例在浏览器端的持久化、草稿恢复与服务端加密快照。
- 完成 DeepSeek 主文本模型接入；舌象视觉采用独立、显式开启的 GLM 视觉能力。
- 完成本地中医药知识库、证据上下文和灵犀审方接口接入。
- 完成 Docker standalone 镜像、子路径部署、健康检查和回滚方案。

### 2. 临床安全与架构整改

- 建立确定性红旗和危急生命体征安全门，模型不能取消既有安全结论。
- 建立诊断与剂量处方的分级权限；风险未解除、信息不足或审方不可用时自动降级。
- 建立临床事实语义回补层，采用 schema、逐字引用、主体、极性、时态和签名校验。
- 修复否定式既往史、定性儿科、口语体温、腹膜刺激征、稳定慢病与急性事件混淆等整类问题。
- 建立 M03/M04 结构化输出 sentinel、有限修复、独立复核、签名和总时限机制。
- 建立处方后审方 fail-closed 机制：BLOCK、结构缺失、服务不可用均转人工复核。
- 建立 PHI 与准标识符脱敏、登录/API 鉴权、CSRF 来源校验和模型调用限流。

### 3. 临床质量与中医专业能力整改

- 规范西医诊断、中医病名、证候、病位、病性、病机、治则治法的结构化合同。
- 修复西医依据病历复述、既往史被当成现症、病机本标错位、寒热虚实冲突等问题。
- 强化经典方来源、方证关系、君臣佐使、方义差异、煎服法和随证加减输出。
- 建立 M03 到 M04 的治疗链锁定，处方必须对应已签名且可执行的诊断与病机节点。
- 建立中医非药物治疗项目能力与风险等级，默认均为建议性质并要求医生复核。
- 建立中成药本地候选索引和证据约束，禁止无来源的剂量与硬性治疗结论。

### 4. 数据治理与“十二表”建设

- 建立证候、病性、病位、治则治法、检查语境、红旗分诊、工程术语七类词表。
- 建立方剂治理目录、饮片身份目录、必填策略矩阵、医生可见输出合同和非药物治疗证据目录。
- 建立数据表统一 manifest、来源登记、schema、SHA-256 和规模统计。
- 将运行时词条逐步从散落代码迁移到可构建、可校验、可回扫的数据资产。
- 对饮片别名采用安全优先消歧：精确命中、唯一高置信、唯一映射依次放行，歧义时保持锁定。

### 5. 深度测试、评审与回归建设

- 完成全系统架构审查、流程审计、安全评审、临床质量评估和五大领域专项测试。
- 建立 100+ Live HTTP 黄金回归入口和基层门诊 50 例专项合同。
- 建立安全变异矩阵、临床事实、结构化合同、处方权限、审方合同、证据防伪等确定性套件。
- 对发现的问题按“发现一个问题，防住一个类别”扩展回归，避免只修单条样例。
- 形成问题清单、根因分类、整改方案、复现指引、发布阻断项和部署手册。

## 七、当前实现边界与后续规划说明

以下内容不应在本次交付中表述为“已经上线的现成功能”：

1. `docs/` 中描述的 LangGraph/ReAct、多智能体、统一 `/api/tcm-cdss/run` 和 SSE 架构属于目标设计；当前正式实现仍是前端编排的 M01-M05 线性流程、Markdown + NDJSON 输出。
2. 当前项目没有业务数据库；病例以浏览器本地状态和服务端加密快照为主。多机构、多人协同、集中审计数据库属于后续建设范围。
3. 系统不自动形成法定诊断、正式处方、药师审方结论或电子签章，不承担医生/药师法定责任。
4. 舌象视觉、外部证据和灵犀审方均依赖外部配置；未启用或不可用时系统按既定规则拒绝、降级或转人工，不承诺离线等价能力。
5. 知识库和十二张治理表已具备工程化基础，但仍需随国家标准、药典、医院目录、甲方知识资产和真实病例持续维护。
6. 生产环境的容量、稳定性、外部服务 SLA、容灾和等保/院内合规结论，必须以甲方实际基础设施和专项评估为准。
