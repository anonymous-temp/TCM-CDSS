## 一、先回答那个路线问题：规则 / 提示词 / 知识图谱，选哪个

**都不选——因为这不是三选一，我们已经在跑第三种的完整形态了。**

实测（`tcm-differentiation-rules.json`）：

| 已有 | 内容 |
|---|---|
| `rules` | **126 条**鉴别规则，每条带 `triggerTerms` / `question` / `resolves` / `discriminates` / `dimensions`（表里·寒热·津液）/ `informationGain` / `priority` / `sourceRefs` |
| `sixChannelDimensions` | 太阳·少阳·阳明·太阴·少阴·厥阴 |
| `warmDiseaseDimensions` | 卫气营血 |
| `sixChannelFormulaRules` / `combinedDiseaseRules` / `treatmentOrderRules` / `tonguePulseConflictRules` | 六经方证、合病并病、治疗次第、舌脉冲突 |

样例规则 `T13-WATERSHED-11`：`有汗/无汗，脉缓/脉紧` → `resolves: [太阳中风, 太阳伤寒]`。

**这就是你说的「相邻证/相邻方鉴别边」，它已经在库里了。** 带出处、带信息增益、由中医师核定过。

M03 提示词里也已经有**七阶段辨证约束**（`buildM03SevenStageContext`）：病位→整体状态→寒热→虚实→病机链→方证鉴别→治法，且第 6 阶段明写「对拟锁定方至少列一个相邻方、相反证据及能改变选择的核实点」。

结构化字段也已经有：`locationDifferentiation` / `natureDifferentiation`（含 `rootDeficiency`/`branchExcess`）/ `chain`（患者事实→证候依据→子病机→治法）/ `uncertainties` / 候选方的 `distinguishingPoints` + `nextCheck`，每个都带 `resolution` 与 `evidence`。

所以**不是从零开始，甚至不是从一半开始**。

### 那「会不会太死板」怎么解

关键在于给规则划一条界：

> **规则不判「是什么」，只判「够不够」。**

| 层 | 负责 | 为什么归它 |
|---|---|---|
| 受治理数据（我们的 KG） | 有哪些框架、哪些鉴别边、每条边的决定性分叉、出处 | 有限、可枚举、须中医师核定、须可追溯 |
| 确定性判据 | **够不够**：框架适不适用、决定性信息齐不齐、敢不敢锁证锁方 | 可判定，且直接关系安全 |
| 模型 | **是什么**：判哪一经、哪个证、哪张方、怎么加减 | 不可枚举，需要综合权衡——这正是模型该干的 |
| 合同校验 | 说了的必须有据：写了「太阳伤寒」就得查「无汗」是不是阳性 | 我们的既有强项，扩展到框架维度即可 |

规则**从不否定**辨证结论。证据不足时它只做一件事：把结论降级为「待追问」，并指出该问哪一条边。这就是不死板的来源——它管的是敢不敢下结论，不是下什么结论。

### 「植入 prompt 产生不了预期作用」这个担心是对的，但已有对策

七阶段约束现在就在提示词里。光靠提示词确实不可靠——**我们的做法一直是「提示词提要求 + 合同校验兑现」**。`m03SemanticIssue` 已经在校验：病位有没有锚定主症、患者事实有没有出处、治法有没有绑到病机节点。本次审查抓到的 `location_chief_symptom_anchor_missing` 就是这类判据在工作。

所以新增框架维度时，**必须提示词与判据成对落地**，只加提示词等于没加。

## 二、实测出来的三个真问题

### 问题 1：候选方收敛完全失效（最高优先级）

`evaluateFormulaCandidates` 的打分是 `score = matchedTerms.length`——纯计数。

实测「发热恶寒无汗身痛脉浮紧」（典型太阳伤寒）：

```
得分 > 0 的方剂 11 个，分数分布 {"1": 11}   ← 全部 score=1
麻黄汤 第 6 名（靠字典序），命中词只有 [无汗]
```

三个后果：

1. **决定性特征与偶然特征同权**。「无汗」对麻黄汤是定义性的，「恶寒」几乎所有表证都有，但都记 1 分。
2. **反向证据不扣分**。桂枝汤的定义性特征是「汗出」，在无汗病例里它应当被**排除**，而不只是不得分。
3. **并列后退化为字典序**。模型拿到的是一份平铺列表，正确答案埋在中间、且没有任何信号说明它更可能。

**但方向性是好的**——这点要说清楚，别把它一起否定了。反事实实测：

| | 无汗案 | 汗出案（只改这一个变量） |
|---|---|---|
| 麻黄汤 | 第 6 名 | **未进候选** |
| 桂枝汤 | **未进候选** | 第 3 名 |

翻转一个变量，两张方确实互换了方向。**你要的那个能力已经存在，缺的是让它收敛。**

### 问题 2：辨证框架适用性没有成为输出字段

六经、卫气营血、三焦、八纲在治理表里都有（分别落在 13/4/21/2 张表），但 M03 的结构化输出里**没有一个字段表达「本例该用哪个框架、够不够用」**。

后果正是你担心的那个：模型可以把六经、卫气营血、脏腑各写一遍，看着全面，实际没有主次，也无从校验。

这是本方案唯一**真正缺失的一级对象**。

### 问题 3：没有反事实回归

现有回归都是「给定病例 → 断言输出」。没有一条测「改一个变量 → 输出必须随之改变」。

问题 1 那种缺陷，**任何一条反事实测试都会当场抓到**——这也是今天审查里那个「正则顶层 `|` 未分组」bug 的同族根因：判据只在一个方向上被验证过。

## 三、迭代任务

按「先修已有的，再加新的」排序。每条都给了验收口径。

### T1　候选方打分加权 + 反向证据扣分　【最高，改动最小】

**做什么**
- `formulaNodes` 的 `supportTerms` 分档：`decisive`（定义性，如麻黄汤的无汗、桂枝汤的汗出）/ `supporting`（支持性）/ `shared`（表证通有，几乎不携带信息）。
- 新增 `excludeTerms`：命中即**扣分或直接出局**（桂枝汤 × 无汗）。
- 打分改为加权和，并列时按 `informationGain` 而不是字典序。

**为什么先做这条**：改动局限在一个函数 + 一张治理表，却直接决定模型看到的候选序是有信号还是噪声。

**验收**：无汗案里麻黄汤进前 2 且分数严格高于其余；桂枝汤不进候选。汗出案对称成立。分数分布不得再是单一值。

**风险**：分档要中医师核定，不能我定。先由我按现有 `resolves` 边自动生成**候选分档**，再交中医师终审——不经终审不进硬判据，只作排序提示。

---

### T2　反事实回归：单变量翻转　【最高，基建已有】

**做什么**
在 `regress-robustness-live.mjs` 上加一层扰动：同一份病历，只改一个决定性变量，跑两遍，比较 `primarySyndrome` / `overallMethod` / 主方。

第一批变量取自已有鉴别边的 `resolves`（126 条里挑高信息增益的）：
- 汗出 ↔ 无汗（太阳中风 ↔ 太阳伤寒）
- 脉浮缓 ↔ 脉浮紧
- 口渴喜冷饮 ↔ 口不渴喜热饮（热证 ↔ 寒证）
- 舌红少苔 ↔ 舌淡胖有齿痕（阴虚 ↔ 阳虚）
- 便秘腹满拒按 ↔ 便溏喜温喜按（实 ↔ 虚）

**判据分三档**，避免把「模型换了个同义证名」误判成缺陷：
- **必须变**：证型的对应轴（寒/热、虚/实、表/里）必须翻转；
- **必须不变**：与该变量无关的维度（如病位）不应无故改变；
- **只记录**：主方变了但方向一致（如麻黄汤→大青龙汤），人工复核。

**验收**：第一批 5 组变量 ×3 次重复，翻转率与稳定率成表落盘。这本身就是给医院看的能力证明。

**为什么它排这么前**：它是**唯一**能持续抓住 T1 那类缺陷的手段，而且不改产品代码、零上线风险。

---

### T3　辨证框架适用性字段　【真正的新增，但先做半步】

**做什么**——在 M03 结构化输出里加一级对象：

```
syndromeFrameworks: [{
  framework: "八纲" | "六经" | "脏腑" | "气血津液" | "卫气营血" | "三焦",
  applicability: "applicable" | "supporting" | "not_applicable" | "insufficient",
  role: "primary" | "auxiliary" | null,
  positiveEvidence: string[],      // 本例阳性依据（须可在病历原文定位）
  contraryEvidence: string[],      // 相反证据
  missingDecisive: string[],       // 缺失的决定性信息 → 直接喂给 M02 追问
  allowsSyndromeLock: boolean      // 本框架下敢不敢锁证
}]
```

**先做半步，不做完整框架内推理。** 第一步只要求模型填「适用性 + 主辅 + 依据 + 缺失项 + 敢不敢锁证」，**不要求**它在每个框架内部完成完整判断。

理由：这半步已经能兑现最大的那个价值——**防止把六个框架全写一遍而没有主次**——而且它是可确定性校验的：

- 写了「卫气营血 = applicable」但病历没有温热病病程证据 → 判 `framework_evidence_missing`；
- 有且仅有一个 `role: primary`，否则 `framework_primary_ambiguous`；
- `allowsSyndromeLock = false` 却锁了证 → 沿用既有 `resolution` 降级路径。

框架内部的八纲/六经细判留到 T5，等 T2 的数据积累出来再定阈值。

**验收**：新增合同判据 + 套件，三条断言（证据缺失、主框架唯一、锁证一致性）各有正反例；负向自检必须红。

---

### T4　框架适用性 ↔ 追问闭环

**做什么**：`missingDecisive` 直接成为 M02 追问的来源，并与既有 `rankedDifferentiationRules` 合流去重——同一条边不能问两遍。

**验收**：太阳病样本在「汗出情况未记录」时，M02 追问必须包含该边的问题，且 M03 不得锁证锁方。这正是你举的第三行表格。

---

### T5　鉴别边覆盖率盘点 + 中医师补边

**做什么**：统计 126 条边覆盖了哪些证型对，找出高频但无边的相邻证对，形成中医师工作包。

**为什么排最后**：补边是**人**的工作量，得先有 T2 的数据说明「哪些边缺了真的会出错」，否则容易补了一堆用不上的。

## 四、关于那篇文章：能借鉴什么、不能借鉴什么

原文：**天医（Tianyi）**，`arXiv:2505.13156`，期刊版 *Information Fusion* 126, 103663（DOI `10.1016/j.inffus.2025.103663`）。南京中医药大学。注意不叫「天一」；中文语境里「天一/TianYi」还指向天河灵枢、岐黄问道等**不同物**。

**原文里没有的（不要当成可借鉴的现成实现）**——全文 PDF 检索 `eight princip / bagang / six meridian / zang / viscera / wei qi ying / triple burner / sanjiao` **命中 0 次**：

- **没有**显式建模八纲/六经/脏腑/卫气营血/三焦。证候在天医里只是知识图谱的一类节点 + 一个待预测标签。
- **没有**奖励模型 / 规则校验 / 一致性校验。对齐只有 KTO 偏好样本，负样本由 Llama-3.1-8B 生成。

（以上经独立复核：三个来源均对照原文核验——arXiv 摘要页、本地抽取的 PDF 首页、PMC 全文。）

**所以本方案的 T3/T4 不是「借鉴天医」，是我们自己要发明的。** 没有现成实现可参照，也没人替我们踩过坑——这是排期时必须知道的。

**真正对口的两个参照**（比天医贴近）：
- **TCMEval-SDT**，*Scientific Data* 12, 437 (2025)，DOI `10.1038/s41597-025-04772-9`——辨证**思维过程**评测集，正是「不只监督最终证型」；
- **arXiv:2512.02816**——辨证论治评测基准。

这两个我会在做 T2 判据时重点读，看它们的评测维度能不能直接复用。

## 四·补　调研补充：有先例的、没先例的、可直接拿来用的

调研 8 路全部完成、逐条经原文核验。以下只写**读到原文**的，读不到的在末尾单列。

### 1. T1 的打分设计有已发表先例——而且报了收益数字

**CHD-SEDD LLM**（《中国实验方剂学杂志》2025;31(19):1-10，doi 10.13422/j.cnki.syfj）是本次调研里框架层最硬的一篇，机制与 T1 几乎同形：

> 依据《冠心病心绞痛证候要素诊断标准》，设计「症状解析—证候要素评分—证候组合」三级链式推理框架，并将辨证规则编码为结构化 Prompt 模板。
> 「首先对每个证候要素设置初始化评分因子 α = 0（如气虚要素的胸闷痛症状计 4 分、乏力计 3 分），通过症状匹配动态更新 α 值；继而依据 α ≥ 8 分的阈值标准完成单一要素诊断；最终按照『气虚+血瘀→气虚血瘀证』的组合规则生成证型结论。」

即：**症状→证候要素是带权重的可计算映射，要素→证候是显式组合规则**——正是 T1 要把 `score = 匹配词条数` 换掉的那个东西。该文报告**逻辑冲突率 37% → 4%**。

注意边界：它是**专病**（冠心病心绞痛，8 要素 6 证候），不是通用八纲/六经。机制可借，覆盖面要我们自己铺。

### 2. T2 的指标设计可直接抄——但中医领域没人做过

**中医领域的单变量反事实评测：没查到任何一篇。** 中英文多轮检索（含「反事实」「扰动」「汗出/无汗」`counterfactual` `minimal pair` `symptom flip`）均无命中。**这不等于没人做过**，只能说公开可检索来源里没查到（CNKI/万方本次工具访问不到，建议补检）。

最接近的三种形态各差一层：
- **TCM-5CEval**（arXiv:2511.13169）扰的是**选项顺序**不是临床变量；
- **DyReMe**（arXiv:2510.09275，西医）注入混杂因素但**金标准不变**——是抗干扰测试，不是反事实（反事实要求金标准随之改变）；
- **DCB**（Expert Systems with Applications 2026）据检索片段称注入六类误诊陷阱，但**403 未读到原文，不据此排期**。

**可直接借鉴的指标（非中医，但原文读到了）**：
- **MamaBench**（arXiv:2607.14385）：217 对、434 条专家病例，配对原则是「**改动最少的参数使诊断发生改变**」——与 T2 的设计逐字一致。指标 **Bias Trap Rate (BTR)** = 「在基础病例答对的前提下、反事实病例答错的条件概率」。核心结论：**base accuracy 比 robust accuracy 高估 16–28 个百分点**。
- **CSS**（arXiv:2605.30590）：沿五个维度突变肿瘤 MDT 病例。

**对 T2 的直接影响**：指标改用 BTR（条件概率），而不是我原方案里的「翻转率」——BTR 能把「本来就答错」和「基础对、反事实错」分开，后者才是真问题。那个 16–28pp 的数字也正是说服医院做这项测试的理由。

### 3. 两个可直接拿来用的公开评测集

- **TCMEval-SDT**（*Scientific Data* 12, 437 (2025)，DOI 10.1038/s41597-025-04772-9，**CC-BY 4.0**）：300 例，专家标注，把辨证思路显式拆成四步——`(1) clinical information extraction (2) pathogenesis reasoning (3) syndrome reasoning (4) explanatory summary`，每例带 病机 与 解释性总结 独立字段。**许可证允许我们直接用作外部评测集**，用来对照我们自己的 `chain`（患者事实→证候依据→子病机→治法）。
- **TCMEval-PA**（*Scientific Data* 2025，DOI 10.1038/s41597-025-06387-6）：**中药处方审核**评测集，328 题。直接对口我们的审方层，可用来给医院出一个第三方口径的分数。

新增任务 **T6**：把这两个集接进评测流水线（只读、不进产品路径）。

### 4. 一个横向定位

**TCM-SD**（arXiv:2203.10839）把证型当**扁平多分类标签**处理，只做标签归一化（GB/T15657-1995）。**TCM-BEST4SDT**（arXiv:2512.02816）有「方-证相符」奖励模型，是本次读到的唯一一个。

也就是说：把辨证做成**结构化多层对象**（病位/病性/病机链/治法绑定/方证鉴别）而不是扁平标签，我们现在的形态在公开工作里是偏前的。T3 的框架适用性字段没有现成实现可抄，这一点上一版已经写了，调研完更确定。
