## 一、随访时间轴改为模型驱动（贵方反馈）

**现象**　结构化随访时间轴（`followup_timeline`）四栏里三栏是写死的：时间点第二条恒为
「治疗期间随时」，随访动作是两条固定字符串，触发条件主体是一句固定话术。不同证型的病例
拿到的时间轴逐字相同，只有观察项略有差别。

**根因**　该结构自建成起就只有观察项接了模型输出，其余三栏是模板常量。

**改法**　由 M05 撰写层按本例证候 / 病机 / 治法 / 处方整条生成（2–4 条）。三条边界不变：
第一条时间点恒等于正文「首次复诊时间」；处方后审方得出的安全触发条件**只增不减**并入第一条；
红旗 / 无结构化剂量 / 硬剂量边界三条降级路径完全不走模型。模型不可用或校验不通过时逐字回落原模板。

**实测**（两个证型完全不同的真实医案，同一版本同一接口）

| | 崩漏 · 脾虚气不摄血兼瘀滞 | 白癜风 · 气血不和、瘀滞肌肤 |
|---|---|---|
| 第二个时间点 | 下次月经来潮时 | 服药14天后 |
| 第三个时间点 | 连续调理3个月经周期后 | 疗程结束时 |
| 触发条件举例 | 出现头晕心慌、气短等气血暴脱征象 | 白斑迅速扩大或新发增多 |

套话命中 0、触发条件噪声 0、两例之间无一条共用动作。

**过程中另修两条既有缺陷**
- 接地净化器打碎了时间轴 sentinel 的 JSON（`"time":"服药3天后复诊"` 被改写成
  `"time":病历已记录咳嗽阳性` 并截断数组），整帧因此静默消失。时间轴 sentinel 属前瞻内容，
  不参与病历接地净化；M03 的 sentinel 照旧净化。
- 安全触发条件的措辞：「出现抗凝者增加出血风险。时提前复诊」是句病句（尾部标点未剥、
  「出现」被二次包裹）。

## 二、西医诊断依据：同一条印两遍、字段标题被当成依据（贵方反馈）

**现象**（贵方原样贴回）
```
症状依据  突发剧烈头痛伴呕吐1小时（来源：主诉）
          神清，表情痛苦（来源：面色及其他四诊）      ← 与体征依据重复
          其他四诊/问诊补充：畏光                    ← 字段标题被当成依据内容
          1小时前活动中突然出现…（来源：现病史）      ← 与第一条是同一件事
体征依据  神清，表情痛苦（来源：面色及其他四诊）      ← 同一条印了两遍
```

**根因（三条，各不相同）**
1. 分类在服务端算得完全正确，是**医生页面**把全量支持依据当成「症状依据」传进分组投影，
   于是每条体征依据都被印两遍。
2. 病历传输格式的段落标题（「其他四诊/问诊补充：」）被模型抄进了依据内容。
3. 主诉与现病史描述同一临床事件时的粗细两版没有合并。

**改法**　① 症状依据只能取分类后的症状子集；② 复用既有的传输前缀登记表剥掉段落标题
（不新写第二份词表）；③ 同事件折叠，保留信息更全的那条（贵方裁定「合并」）。
折叠判据刻意不引入症状词表——用的是两条与病历结构本身有关的事实：主诉按定义是现病史的浓缩、
二字片段重叠；短条带着长条没有的数值时不折（避免丢掉「38.5℃」这类具体数）。

## 三、既往史 / 用药史被印成「症状依据」（我方线上实测发现）

**现象**　第二条修完后再用同一份真实病历实测，抱怨的三条都消失了，但同一屏出现新的错分：
```
症状依据  突发剧烈头痛伴呕吐1小时 / 高血压病史5年，规律服药 / 氨氯地平 5mg 每日一次 / 畏光
```
后两条一条既往史、一条用药史，都不是症状。

**根因**　字段映射表把 `past_history` / `medication_history` / `allergy_history`
一律映射成「症状」。另外医生页面调用分类函数时**没有传入来源判据**，导致按落点字段兜底分类
在该出口整个失效——凡模型未标注的条目一律掉进症状依据，生命体征也一样。

**改法**　新增第五个分栏「**病史依据**」。这三个字段按定义记录的就是此次发病之前的事实，
不可能是现症或本次查体所见，**字段的落点即结论，模型标注不得覆盖**（现病史里可以记录体征，
那一侧仍以模型判定优先）。按贵方 0810「有啥列啥」的口径，该栏无内容时不出现。

## 四、事实来源被一律标成「（来源：现病史）」（我方线上实测发现）

**现象**　第三条修完后载荷分组已正确，但可见正文那一屏仍写着
「高血压病史5年，规律服药（来源：现病史）」「178/102mmHg（来源：现病史）」。

**根因（两层）**
1. **把「猜」当成「读」。** HIS 直传时，病历接地正文里 HIS 字段的值是**不带段落标题**的裸行，
   解析器把每一条无标题的行**断言成「现病史」**。同一条既往史于是既以裸行出现、又以
   `既往史：…` 出现，而归属判定先到先得，裸行排在前面。
2. **同一个问题有两份各写各的答案。** 来源标注取最短原文、症状/体征分组另用「取第一条」，
   于是一条事实可以一边标着「来源：既往史」、一边被分进「症状依据」。

**改法**　给每条来源标记是「读出来的」还是「猜出来的」，后者只作兜底、永不压过前者
（首行恒为主诉是接口契约位置，仍算读出来的）。两处判据收敛成唯一谓词。
服务端出口另接上受治理字段路径这一路，与医生页面同源——HIS 直传时正文里一条带标题的行都没有，
光靠行结构永远认不出字段。

**实测最终形态**
```
**症状依据**：突发剧烈头痛伴呕吐1小时（来源：主诉）；畏光（来源：现病史）
**体征依据**：神清，表情痛苦（来源：面色及其他四诊）；178/102mmHg（来源：生命体征）
**病史依据**：高血压病史5年，规律服药（来源：既往史）；氨氯地平（剂量以审定处方为准） 每日一次（来源：当前用药）
```

## 五、贵方连续两轮看到的接口文档是旧的（我方复盘发现）

**现象**　贵方对接人两轮复核都报「对外接口文档 M05 仍写成 `time / action / indication: string`」，
而我方两次核对源文档都是新字段。

**根因**　接口文档有两份：源文档，以及由生成器产出、**人工导入飞书云文档**的导入版。
贵方读的是后者。我方改完源文档没有重跑生成器，且该产物不在版本控制内——
于是源文档改多少次，飞书上那份都不会变。

**改法**　立闸门。判据刻意**不是**「这个字段对不对」（那只覆盖这一次），而是
「**交付副本是不是源文档的当前产物**」：重跑一次生成器与仓库里的产物逐字节比对，
任何文档改动没同步到交付副本都会红，并直接提示重跑哪个脚本。

> **需贵方配合的一步**：飞书云文档上那份是当初人工导入的快照，我方无法远程更新。
> 请用最新的导入版重新导入一次（飞书新建文档 → 右上角「···」→「导入」→ 选择 .md 文件）。

## 六、上一条立的闸门每提交一次就红一次（我方自测发现）

**现象**　第五条的闸门上线当天即在无关改动上报红。

**根因**　生成器往文件头盖了一枚「源码版本：<代码提交号>」的溯源戳，闸门拿整份产物逐字节比对，
于是**任何**提交都会让它红。

**为什么必须修**　一道在与被保护对象无关的原因上常态化报红的闸门，只会被绕过或删掉，
比没有这道闸门更糟。比对前把这枚溯源戳归一化，判据回到「技术内容是不是当前产物」，
另加一条自检钉住归一化不得越界改写正文。
