## P0 — 发布阻断

### P0-1 · M03/M04 模型配置与独立 GLM 复核未生效
- 现象(dev log):
  - M03 stage=`diagnose`,实际模型 `deepseek-v4-flash`,reviewer=`deepseek-v4-flash/preferred` → invalid contract → `m03DiagnosticReviewStatus: 'unavailable'`
  - M04 stage=`prescribe`,实际模型 `deepseek-v4-pro`(本应 M03 用),reviewer=`deepseek-v4-pro/cross_model_fallback` → invalid contract → `m04ClinicalReviewStatus: 'unavailable'`
- 期望(`.env.example` 与内存 [[m03-config-and-deep-quality]]):M03=`deepseek-v4-pro`,M04=`deepseek-v4-flash`,独立复核=GLM-5.1
- 实际:`.env.local` 设了 `PRIMARY_DIAGNOSE_MODEL=deepseek-v4-pro`,但 M03 跑的是 v4-flash(M04 反而跑 v4-pro);**完全没设** `PRIMARY_CLINICAL_REVIEW_PROVIDER=glm`、`PRIMARY_CLINICAL_REVIEW_API_KEY`、`PRIMARY_CLINICAL_REVIEW_API_URL`、`PRIMARY_CLINICAL_REVIEW_MODEL`、`PRIMARY_PRESCRIBE_MODEL`。
- 根因线索:`preferredClinicalReviewModelConfig`(`diagnosis-api.ts:288`)在 provider 默认为 `"primary"` 时走 `model = PRIMARY_CLINICAL_REVIEW_MODEL || primary.model`,所以 M03 reviewer = v4-flash、M04 reviewer = v4-pro,**与 generator 同 provider self-review**,违反"generator 不能 self-approve"的设计原则。
- 影响:①安全网失效:M03/M04 输出没有真正独立的复核;②质量回退:内存里"v4-pro+关思考稳定 5/5"的结论不再成立;③速度:M03+M04 各跑 ~100s。
- **修法**:`.env.local` 补 `PRIMARY_CLINICAL_REVIEW_PROVIDER=glm` + `PRIMARY_CLINICAL_REVIEW_MODEL=glm-5.1` + `PRIMARY_CLINICAL_REVIEW_API_KEY` + `PRIMARY_CLINICAL_REVIEW_API_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions`,并核查 `.env.development.local` 没覆盖;重启 dev 再验证 dev log 中 `m03/m04ClinicalReviewer: 'GLM/glm-5.1'`。
- 同时验证 M03 模型对调 bug:`.env.local` 设 `PRIMARY_DIAGNOSE_MODEL=v4-pro`,但 log 显示 diagnose 用 v4-flash、prescribe 用 v4-pro。需检查 `modelForStructuredStage`(`diagnosis-api.ts:252`)的 stage 入参是否在某条 hot path 被传错。

### P0-2 · 端到端响应耗时 3 分 50 秒,门诊不可用
- 实测良性失眠病例:M01 0.4s + M02 26.6s + M03 86s + M04 105s ≈ **218s**,UI 上"已耗时 207s · 仍在生成"提示。
- 即便配 P0-1 修好,内存里"M03 5/5 v4-pro 稳定"仍需 ~60s,加上 M02+M04 还是接近 2 分钟,**门诊医生等不起**。
- 选项(用户决策):
  - ① 砍掉 M02 追问(患者填全 → 直接 M03);② M03/M04 早期流式 render 但延迟输出最终 sentinel(医生边看边等);③ 切更快的 v4-flash-but-better 模型;④ 拆 M03 → 西医诊断 + 中医辨证两个并行子任务。
- 现在的"伴随式文案"("正在组织证候、病机与治法…")是好方向,但文案进度更新不够细,医生不知道还要等多久。

## P1 — 严重

### P1-1 · M02 追问单选强迫二分
- 现象:"患者近期情绪以烦躁易怒为主,还是以忧思抑郁为主?"二选一 radio。
- 问题:临床实际烦躁+抑郁混合常见(尤其是更年期/焦虑抑郁共病),强迫二分会丢信息。
- 修法:改多选 + "其他"自由文本,或加"两者皆有,以X为主"选项。已存在的"其他(医生补充)"是兜底但 UX 不优。

### P1-2 · clinical-facts 回归测试失败:独立 LLM 复核用例
- 命令:`npm run test:clinical-facts`,失败用例:`extractor: 独立LLM复核可纠正首轮处置层级且仍受逐字引用契约约束`(`scripts/test-clinical-facts.mjs:264`)。
- 期望:`independentReviewCalls === 2 && reviewStatus === "checked" && redFlags[0].urgency === "emergency"`。
- 影响:P1 临床事实兜底核心能力(独立 LLM 复核纠正首轮 urgency)的回归保障失效;一旦未来改 extractor 容易回归而不报警。
- 修法:定位 `extractClinicalFacts`(`clinical-facts.ts`)的 `independentReview` phase 路径,看 review phase 是否真的被触发 2 次以及 reviewStatus 的归一逻辑。

### P1-3 · tcm-treatment-projects 回归失败:needle_knife 误匹配
- 命令:`npm run test:tcm-treatments`,失败用例:`negated differentials cannot create a treatment indication`(`scripts/test-tcm-treatment-projects.mjs:288`)。
- 场景:心神不宁失眠 + **否认颈椎病**的 differential,外部 caller 选 `needle_knife → P1`,期望 `compileTcmTreatmentRecommendations` 返回 `[]`。
- 实际:返回 1 项 `needle_knife targetRef=P1`。
- 影响:针刀(经筋痹阻适应症)会出现在心神不宁失眠病例的推荐里,既不符中医辨证,也有过度医疗风险。
- 修法:`compileTcmTreatmentRecommendations` 应基于 `deriveTcmTreatmentCaseIndicationTags`(已正确识别 musculoskeletal_pain 不出现)过滤 indication 不符的 projectCode×targetRef 组合,而非信任 caller 输入。

### P1-4 · UI 加减工作台视觉重复(待截图确认是真 bug 还是设计)
- 现象:`P1·肝气郁结...` 块在 DOM 中出现 **13 次**,`君臣佐使` 也出现 **13 次**,正好等于方剂 13 味药的数量。
- 可能性 A:每味药一行 × N 列下拉(君臣佐使 / P1-P4 / 顾护中焦 / 调和诸药 / 引经载药 / 制约峻烈),snapshot 把所有 option 文本展开导致看着重复——这是**正常设计**。
- 可能性 B:每味药下拉行确实渲染了 13 个相同 select——这是**真 bug**。
- 修法:在浏览器里直接看截图(本次因 dev hot-reload 卡 modal 未完成);若 B,定位 `药味加减工作台` 渲染逻辑(在 `DiagnosisClient.tsx` ~3100 行附近),修重复 map。

### P1-5 · "综合支撑度 69%" 与 "判断把握度:低" 双口径并存
- 现象:UI 顶部"辨证充分度 / 综合支撑度 69%"(绿/黄条);M03 正文"中医诊断 / 判断把握度:低"。
- 问题:两个不同口径的"把握度"指标同时显示,数字/文字不一致(69% 似中等,但"低"是低),医生不知道信哪个。docs/全系统深度评审 类2 标 ✅2a/2b/2d 已修,但这 pair 未归一。
- 修法:统一单一来源——要么综合支撑度(数字)直接决定"把握度:低/中/高"文字,要么去掉一个。

### P1-6 · M02 重复说明 + 状态机延迟清场
- 现象 1:M02 卡片顶部"本轮关键追问 / 可点选实际回答..." 与下方"需补充的信息 / 本轮集中核实最影响判断的几项信息..." **重复说明同一件事**。
- 现象 2:M04 已 200 完成后,UI 仍长期显示"已耗时 207s · 仍在生成,请勿重复提交"(状态机延迟清场);医生以为还在生成。
- 修法:① 删第二段说明;② 后端 stream 结束(`[END]`)后前端立即清"仍在生成"状态。

## P2 — 中等

### P2-1 · "bounded" 开发黑话在流式过程中暴露给医生
- 现象:M03 流式过程中可见"主证候:心肝血虚,心神失养,兼肝气郁结**(bounded)**"——括号里的 `bounded` 是 sentinel/修复流程的开发黑话。
- 影响:虽然最终归档后被清洗(`sanitizeDiagnoseStreamingDraft`),但医生在流式过程中会看到,影响专业感。
- 修法:在流式 chunk 进入 DOM 前先过 `sanitizeDiagnoseStreamingDraft`(看是否已作用,或仅作用于最终 sentinel);或扩展 sanitize 规则增加 `(bounded)` 等开发标记。

### P2-2 · 性别/年龄字段填不进
- 现象:`evaluate` 设置 `input[placeholder="性别"]` / `[placeholder="年龄"]` 均返回 ok:false。
- 影响:自动化测试无法填这两项;真实用户如果用键盘输入也可能不触发 React onChange(待人工验证)。
- 修法:定位这两个字段的实际控件类型(可能不是 `<input>` 而是 `<select>` / 自定义组件),给 evaluate 用对的 setter;若是 UI bug,真实用户也会受影响。

### P2-3 · 顶部"中医辅助诊疗报告" + "报告"按钮在无数据时仍可见
- 现象:初始状态(还没点推理)右侧栏顶部有"报告"按钮,但没有任何报告数据。
- 影响:医生可能误以为有报告可看,点击后无效果。
- 修法:数据为空时隐藏"报告"按钮,或加 tooltip"完成推理后可下载"。

### P2-4 · 报告页堆叠成单卷,无 tab/折叠
- 现象:M01~M05 完整内容堆在一个长卷里,12k+ 字符,医生很难快速定位"我想看 M03 病机"或"看 M04 处方"。
- 修法:左侧 5 阶段导航(病历采集/重点追问/辨病辨证/候选方药/审方随访)应可点击跳锚点或切换右侧 panel 的 active tab。

### P2-5 · 节气调护已激活(积极发现)
- 现象:M05 输出"节气调护(小暑前后)暑湿困脾..."动态算出当前节气。
- 来源:内存 [[benchmark-nanzhongyi-upgrade]] 标"桶 C 调候/节气(现死代码 `buildAssessPrompt:738`)"为待办,现已激活。**这是对标南中医方案的实质进展**。

### P2-6 · "已保存 19:07" 频繁刷新(噪声)
- 现象:顶部状态条频繁显示"已保存 19:07",每次自动快照触发更新。
- 影响:医生可能误以为系统不稳定/反复出错。
- 修法:节流(至少 30s 更新一次)或改为"最近保存于 X 分钟前"。

### P2-7 · 处方工作台"标记为编辑后候选方案"语义不清
- 现象:加减工作台底部按钮"标记为编辑后候选方案"。
- 问题:医生不知道点了会怎样(标记后还能改吗?会同步 HIS 吗?)。
- 修法:改为"保存为本例修改方案"或加 tooltip。

### P2-8 · 甲方 OD-TCM 阈值与本地 KB 不完全一致(记录)
- 实测对比(`scripts/test-customer-tcm-dose-parity.mjs`,8/8 通过):

| 药味 | 本地药典 | 甲方内部 | 差异 |
|---|---|---|---|
| 半夏 | 9g | 9g | 一致 |
| 附子 | **15g** | **9g** | 本地宽 6g |
| 麻黄 | **10g** | **6g** | 本地宽 4g |
| 细辛 | 3g | 3g | 一致 |
| 甘草 | **10g** | **9g** | 本地宽 1g |
| 制川乌 | 3g | 3g | 一致 |
| 马钱子 | **0.6g** | **0.9g** | 本地严 0.3g |

- 影响:所有甲方测试用例的超量值(15/20/12/9/20/10/3g)**都能被本地识别为超量**(本地严或等价);但**边界值病例**(如麻黄 8g)会有分歧——本地允许、甲方会报。
- 修法:与甲方对齐阈值来源(若以药典为准,记录差异说明;若以甲方院内规范为准,需要替换本地 KB)。

## P3 — 体验

### P3-1 · 表单字段无快捷"否认"按钮
- 现象:既往史/过敏史/用药史等只有 placeholder"否认过敏 / 具体药物...",医生要手动敲"否认"。

- 现象:M05 "节气调护(小暑前后)"是好的,但有些缩写如"PSG"、"GAD-7"、"PHQ-9"无 tooltip。
- 修法:专业缩写加 `<abbr>` 解释。

### P3-4 · "舌诊采集"按钮一直 disabled
- 现象:`disabled: true`,可能因为没配 GLM 视觉;但 UI 上仍显示。
- 修法:功能未启用时直接隐藏,或加 tooltip"需配置 GLM Vision"。
