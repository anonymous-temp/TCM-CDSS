# 中医 CDSS 全系统深度设计评审 — 问题类别与整改建议

> 方法：6 维度并行深度评审（流程与状态机 / 信息呈现 / 推理路径与证据可溯 / 确定性算法 / 提示词与证据防伪 / 数据模型与解析）+ 综合归类。7 个隔离子智能体、0 报错、约 38 条原始发现 → 归纳为 9 个问题类别。
> 说明：行号为评审时快照，改动后会漂移，**定位以函数名为准**。标 `⚠待实测` 的项在动手前需先构造用例复现确认（历史经验：静态审计会有误判，尤其安全层）。

## 0. 整体评估

系统在**架构分层**（薄路由 + lib、确定性安全门、fail-closed 意图、reasoningV2 结构化 schema）上已相当成熟，多数近期修复方向正确。**但整体可信度被一个贯穿性短板拖住**：

> **大量确定性门控、风险分级与展示，仍以"对模型渲染文本的正则/关键词解析"和"位置式判断"为真源**，叠加红旗清除 fail-open、证据反伪造仅靠提示词、M03→M04 覆盖截断、PHI 未脱敏落盘——使得"确定性安全层"在若干关键边界上**并未真正确定**。

**发布前必须把"结构化真源 + 确定性后处理校验"落到门控、安全、证据这三条主链上。**

**这就是"发现一个问题解决一类问题"的核心**：类 1/2/3/4/7 都是"确定性逻辑耦合模型渲染文本"的分身；系统性解法是**一律以 `reasoningV2` 结构化字段 + 结构化审方裁决为唯一真源，正则仅作收窄兜底 + 路由收尾做确定性校验**。

## 3. 建议整改顺序

1. **类5 红旗 fail-open**（先实测复现"急性胸痛+陈旧性正常心电图"用例，确认为真漏再修）+ 数值型生命体征假阳性硬阻断。
2. **类6 跳过的假结果与空转**：受限/不可执行 M03 经 skip 不得产占位卡；软门按钮仅在真正能推进时暴露。
3. **类3 证据确定性反伪造校验**：方括号ID/来源与注入白名单比对，未命中降级"证据不足/待检索"。
