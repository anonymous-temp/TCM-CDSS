## 0. 产品定位与法律边界（集成前必读）

本系统是**建议性**（advisory only）中医临床决策支持工具，不是处方系统。

- 所有输出均为**候选建议**，必须由医生逐项确认后才能进入院内处方流程；
- 系统**永不**输出可直接执行的最终处方：`writeBackPolicy.finalPrescriptionReleaseAllowed` 恒为 `false`；
- 每条结论都可追溯到患者事实、确定性规则命中或知识库条目，否则显式标注"证据不足/待检索"；
- 安全层为**确定性**（非模型判定），处置采用**提示不拦截**（advise）语义：红旗、危急体征、
  信息完整度、就诊目标等判定照常执行并全部呈现，但不阻断流程——命中时照常返回完整辨证与
  候选方药，并在可见正文**最前**置入安全警示横幅（见 §4.5）。集成方必须把该横幅原样展示给
  医生，且不得在横幅未解除时把候选内容自动写入处方系统；
- 运维可通过环境变量 `CDSS_GATE_DISPOSITION=block` 切回旧的 fail-closed 拦截行为（整机开关，
  不需要改代码或重建镜像）。

集成方在 UI 上必须保留：医生逐项采纳入口、风险提示展示、以及"需药师复核"标识。

## 1. 接入与鉴权

### 1.1 鉴权方式

所有 `/api/*` 接口均需鉴权，二选一：

| 方式 | 请求头 |
|---|---|
| 专用 token 头 | `x-cdss-api-token: <API_TOKEN>` |
| Bearer | `Authorization: Bearer <API_TOKEN>` |

Token 由我方单独提供（不在本文档内）。

未携带或错误时返回 `401`，响应体 `{"error":"..."}`。

### 1.2 浏览器登录（仅 UI 场景）

`POST /api/auth/access`

```json
{ "token": "<API_TOKEN>" }
```

成功后种下 httpOnly Cookie `tcm_cdss_ui_access`，用于页面访问。API 集成**不需要**走这一步。

- 成功：`200 {"ok":true}`
- 口令错误：`401 {"ok":false,"error":"访问口令不正确"}`
- 频繁失败：10 分钟内失败 8 次锁定

### 1.3 限流

| 维度 | 限制 |
|---|---|
| 模型调用类接口 | 默认 60 次 / 10 分钟（`CDSS_MODEL_RATE_LIMIT_PER_10_MIN`，下限 10） |
| 登录失败 | 8 次 / 10 分钟后锁定 10 分钟 |

超限返回 `429`。限流按调用方身份计数；生产部署位于反向代理之后，以代理透传的真实来源为准。

### 1.4 请求体限制

统一 JSON，单请求体上限 **1 MB**。超限返回 `413`；非法 JSON 或缺 `caseState` 返回 `400`。

## 2. 核心数据结构：CaseState

除健康检查外，所有业务接口的请求体统一为：

```json
{ "caseState": { /* CaseState */ } }
```

### 2.1 最小可用字段

> ### ⚠️ 集成第一必读：`caseState.id` 必须由调用方提供且全程不变
>
> M03/M04 的结构化结果带**服务端 HMAC 签名**，签名绑定 `caseState.id` + 就诊号 + 临床输入哈希。
>
> - 请求体**不带 `id`** 时，服务端每次会生成新的临时 id，M03 阶段签进签名的 id 与 M04 阶段重新
>   生成的 id 不一致，M04 必然返回 `409 辨病辨证结果缺少有效签名`；
> - 因此：**在 M02 之前生成一个稳定 id（建议用就诊号，如 `enc-20260731-0001`），并在同一病例的
>   全部阶段调用中原样携带**；
> - 同理，签名与**部署环境密钥**绑定：测试环境生成的 M03 结果不能拿到生产环境继续调 M04。

```json
{
  "caseState": {
    "id": "enc-20260731-0001",
    "phase": "diagnose",
    "chiefComplaint": "反复胃脘胀痛3月，加重1周",
    "hisRecord": {
      "source": "manual",
      "encounterId": "EH-20260731-0001",
      "rawText": "患者男，45岁。反复胃脘胀痛3月……",
      "fields": {
        "zhushu": "反复胃脘胀痛3月，加重1周",
        "xianbingshi": "3月前因情志不遂出现胃脘胀痛……",
        "jiwangshi": "否认高血压、糖尿病",
        "guomingshi": "否认药物食物过敏",
        "yongyaoshi": "近1周自服奥美拉唑20mg qd",
        "tizheng": "T 36.5℃ P 78次/分 R 18次/分 BP 122/78mmHg"
      },
      "collectedAt": "2026-07-31T09:00:00.000Z"
    },
    "tongue": "舌淡红，苔薄白",
    "pulse": "脉弦",
    "faceNote": "面色如常",
    "completeness": { "level": "C", "redFlag": 0.85, "infoGain": 0.9, "managementImpact": 0.9, "answerability": 0.9 },
    "conversation": [],
    "questionRounds": 1,
    "maxQuestionRounds": 2
  }
}
```

### 2.2 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **必填且全程不变**。签名绑定项，缺失会导致 M04 返回 `409`。建议用就诊号 |
| `phase` | string | `question` / `diagnose` / `prescribe` / `assess`，与调用的阶段一致 |
| `chiefComplaint` | string | **必填**。缺失时系统硬停并返回补录提示 |
| `hisRecord.rawText` | string | 病历原文，安全层与事实核验的权威来源 |
| `hisRecord.fields` | object | 结构化字段（主诉/现病史/既往史/过敏史/用药史/体征等），与 rawText 并列为权威来源 |
| `tongue` / `pulse` / `faceNote` | string | 舌/脉/面象。医生表单录入优先于模型推断 |
| `completeness` | object | 信息完整度自评。**服务端会重算并覆盖**，仅 C 级进入完整诊断与处方 |
| `conversation` | array | `{role:"user"\|"assistant", content:string}`，M02 追问上下文 |
| `clinicalFacts` | object | 语义红旗预检结果，见 3.1。**建议按 3.1 回传以复用缓存** |
| `reasoningDiagnose` | object | M03 签名推理结果，调用 M04 时**必须**回传 |
| `reasoningPrescribe` | object | M04 签名推理结果，调用 M05 时**必须**回传 |
| `diagnosis` / `prescription` | string | 上一阶段的可见正文，随对应 reasoning 一并回传 |

> **重要**：M03/M04 的结构化结果带有服务端签名，与本次病例和辨证结果绑定。回传时必须**原样**传回，任何修改都会导致签名校验失败并返回 `409`。

## 3. 接口清单

### 3.0 调用顺序

```
[可选] POST /api/diagnosis/red-flags      语义红旗预检（结果随 caseState 复用）
[可选] POST /api/diagnosis/question       M02 生成追问
       POST /api/diagnosis/diagnose       M03 辨病辨证        （必需）
       POST /api/diagnosis/prescribe      M04 候选方药        （需 M03 结果）
       POST /api/diagnosis/assess         M05 风险随访        （需 M04 结果）
       POST /api/diagnosis/his-scheme     结构化交付载荷      （推荐：HIS 集成入口）
```

**HIS 集成建议**：前四步按需调用，最终用 `his-scheme` 取结构化 JSON 渲染，避免自行解析 Markdown。

---

### 3.1 语义红旗预检

`POST /api/diagnosis/red-flags`

在正式推理前完成语义红旗筛查。**强烈建议先调用本接口，并把返回的 `clinicalFacts` 放回 caseState 后续传递**——各阶段按内容指纹命中缓存，可避免重复模型调用；不回传时每个阶段都会重跑，一次瞬态失败即触发全流程 fail-closed 降级为非剂量输出。

**响应**（`application/json`）

```json
{
  "available": true,
  "semanticStatus": "checked",
  "clinicalFacts": { "redFlags": [], "attestation": "...", "sourceFingerprint": "..." },
  "safetyGate": {
    "status": "ready",
    "allowDiagnosis": true,
    "allowDosePrescription": true,
    "action": "proceed",
    "missingItems": [],
    "redFlags": [],
    "reasons": []
  },
  "latencyMs": 3200
}
```

| `safetyGate.status` | 含义 |
|---|---|
| `ready` | 可进入完整诊断与剂量级处方 |
| `needs_information` | 可诊断，但需补录信息；处方降级为非剂量 |
| `red_flag` | 命中急危重红旗，仅输出分流建议，不生成处方 |

### 3.2 M02 追问生成

`POST /api/diagnosis/question`

**响应**：NDJSON 流（见 4.1）

生成高信息增益追问。追问为**非阻断**：医生可回答后重跑，也可直接进入 M03。

---

### 3.3 M03 辨病辨证

`POST /api/diagnosis/diagnose`

**响应**：NDJSON 流，正文为 Markdown，末尾嵌入结构化 JSON（见 4.2）

输出：西医诊断倾向 + ICD-10 编码、中医病名、证候诊断、病机链、治法框架、证据链。

典型时延 **20–60 秒**（含结构化校验、受控术语标注与独立临床复核；复核驳回触发修复轮的病例可达
90–120 秒）。请将客户端超时设为 **≥240 秒**。

> **服务端并行生成（2026-08-02 起）**：M03 内部拆为「中医半」（证候/病机/治法）与「西医半」
> （西医诊断/管理建议）两路并行生成，服务端确定性合并后走完整契约校验、独立复核与签名——
> 对外接口契约、流式格式与结构化载荷**完全不变**，集成方无需任何改动。流式过程中会先看到
> 各模块的结论标题行，最终由替换标记（§4.2）下发权威全文。运维可用
> `M03_PARALLEL_GENERATION=false` 整机回退到单发全量生成。

### 3.4 M04 候选方药

`POST /api/diagnosis/prescribe`

请求体的 `caseState` 必须携带 M03 返回的 `reasoningDiagnose` 与 `diagnosis`。

**响应**：NDJSON 流，含药味清单（药名/剂量/君臣佐使/病机绑定/功用）、煎服法、中成药与西药方案、用药风险提示。

典型时延 **20–60 秒**。

**非剂量降级**：正文以 `<!-- CDSS_NON_DOSE_PRESCRIPTION -->` 开头时，表示本次不提供剂量级候选，原因见正文"处方安全边界"段。advise 默认档下这种情况只剩三类：缺主诉、缺有效 M03 签名结果、模型输出截断到无候选可回收——均可通过重试或补齐调用序列恢复，不是错误。安全/完整度类命中不再走此降级，而是正常出方 + §4.5 安全警示横幅。

**确定性方剂参考页（非剂量降级的增强形态）**：模型输出不可回收但 M03 已锁定受治理经典方时，
非剂量页会携带该方的**确定性参考数据**（"### 方名（出处）" + 药味表：药典剂量区间/特殊煎法 +
毒性/管制味的监管扣除说明）。该表全部来自本地受治理知识库、不含模型生成内容；剂量列为
**药典边界区间而非本例建议量**，用量由医师确定并经审方复核。集成方可原样渲染该 Markdown 表；
它不携带结构化 M04 载荷与签名，不可作为候选采纳，仅供医生参考定量后重新生成。

**质量批注**：正文首段出现"…已完整通过安全核验；…请…核对后再采纳"这类提示时，表示药味、剂量、
配伍禁忌、特殊人群与君臣结构的确定性核验**全部通过**，但独立复核对方义、方药-病机对应关系或
患者信息完整度仍有保留意见。此时处方**可用**，但集成方应当把该段原样展示给医生，不得隐藏。

**原方毒性/管制药味的处理**：所引经典方原组成含毒性、管制或濒危药材（朱砂、雄黄、麝香、轻粉等）
时，系统**不为其编制用量**，该味不进入药味清单，其余药味照常给出剂量；正文会写明"原方含但本次
不编制用量的药味"。这类药材需由医师按监管要求单独开具并经院内审方复核。方义本身落在毒性药味上
的方剂（如安宫牛黄丸），整方仍不进入剂量编译，只保留方名方向。

**用量核验级别**：药味清单中的成分带有核验级别标注。`verified` 表示有法定数值边界；
`unverified_dose` 表示本地受治理知识库无法定边界（食材/辅料/药典未收载饮片），**用量由医师确定**，
系统不为其担保剂量；`toxic_regulated` 表示监管轴品种；`identity_pending` 表示药材身份待人工裁定。四类均照常提交灵犀审方。

### 3.5 M05 风险随访

`POST /api/diagnosis/assess`

请求体需携带 M04 返回的 `reasoningPrescribe` 与 `prescription`。

**响应**：NDJSON 流。本阶段汇总**完全确定性**（消费灵犀审方结果，不经模型生成）。

- `409`：候选处方缺少与本病例绑定的有效签名，或签名后内容被修改 → 需重新生成候选方药

### 3.6 HIS 结构化交付载荷（推荐集成入口）

`POST /api/diagnosis/his-scheme`

**响应**：`application/json`，`schemaVersion: "tcm-cdss-his-ai-scheme-v1"`

顶层字段：

| 字段 | 说明 |
|---|---|
| `caseId` / `generatedAt` | 病例标识与生成时间 |
| `status` | 方案状态 |
| `candidateStatus` | `valid` / `limited` / `invalid` |
| `auditStatus` | `pass` / `alert` / `unavailable` / `not_submitted`（灵犀审方结果） |
| `reviewRequired` | 是否必须人工复核 |
| `warningProfile` | 风险等级、动作要求（`display_only`/`acknowledge`/`reason_required`/`non_executable`）、是否可执行、导出模式 |
| `redFlag` | 红旗标签（低风险/需关注/高风险/待评估）与说明 |
| `safetyGate` | 安全门快照 |
| `aiMedicalRecord` | 一诉五史 + 四诊 + 体征 |
| `diagnoses.western` / `.tcmPatterns` / `.mechanism` | 可采纳条目数组 |
| `prescriptions.herbal` | 中药饮片处方（展示用条目） |
| `prescriptions.structuredHerbs` | **结构化药味数组**，见下表 |
| `prescriptions.westernOrPatent` | 西药/中成药方案 |
| `prescriptions.regimen` | 煎服法与疗程 |
| `treatments.tcmProjects` | 非药物中医治疗项目（针灸/推拿等），`adoptable` 恒 `false`，须医生评估 |
| `checks` / `followup` / `riskTips` | 建议检查、随访计划、风险提示 |
| `references` | 证据引用 |
| `writeBackPolicy` | 回写策略，见下 |

**`structuredHerbs[]` 关键字段**

| 字段 | 说明 |
|---|---|
| `itemNo` | 序号 |
| `name` / `processing` | 药名 / 炮制规格 |
| `dose` | 剂量（如 `9g`） |
| `role` | 君/臣/佐/使 |
| `targetKind` / `targetRef` | 病机节点绑定（`pathogenesis_node` + `P1`）或方内结构（`formula_structure`） |
| `verificationTier` | `verified` / `unverified_dose` / `identity_pending` / `toxic_regulated` |
| `warningLevel` | 该药味风险等级 |
| `doseSource` | `governed_boundary` / `classical_source` / `none` |

**`writeBackPolicy`**

| 字段 | 恒定值/含义 |
|---|---|
| `allowSingleItemAdoption` | 是否允许逐项采纳 |
| `allowOneClickAdoption` | 是否允许一键全采纳 |
| `doctorReviewRequired` | 医生复核必需 |
| `pharmacistReviewRequired` | 药师复核必需 |
| `warningConfirmationMode` | `none` / `checkbox` / `checkbox_and_reason` / `blocked` |
| `finalPrescriptionReleaseAllowed` | **恒为 `false`** —— 系统不放行最终处方 |

**约束**：当 `candidateStatus` 为 `limited`/`invalid`，或存在未确认的就诊目标时，返回的是**不含剂量**的诊断型方案。

### 3.8 病例快照

`POST /api/diagnosis/snapshot`

AES-256-GCM 加密的病例状态快照，鉴权绑定快照所有者。**请求体契约**（此前文档未写明，集成方按空体调用会得到 400「无效的病例快照请求」）：

```jsonc
// 加密：payload 为任意病例状态 JSON；binding 为集成方自定义的工作区标识经 SHA-256 后的 64 位十六进制串
{ "action": "encrypt", "binding": "<64-hex>", "payload": { /* caseState */ } }
// → { "ok": true, "envelope": { "schemaVersion": "tcm-cdss-encrypted-snapshot-v1", "algorithm": "A256GCM", "iv": "...", "ciphertext": "...", "authTag": "...", "updatedAt": "..." } }

// 解密：原样回传 envelope；binding 必须与加密时一致（绑定进 AAD，换绑定/换 token 主体解不开）
{ "action": "decrypt", "binding": "<64-hex>", "envelope": { /* 上面的 envelope */ } }
// → { "ok": true, "payload": { /* 原病例状态 */ } }
```

### 3.10 健康检查

| 接口 | 说明 |
|---|---|
| `GET /api/diagnosis/health` | 基础状态 |
| `GET /api/diagnosis/health?strict=1` | **发布就绪门禁**。`strictReady=false` 时返回 `503` |
| `GET /api/model-health` | 模型配置状态 |
| `GET /api/model-health?check=1` | **真实模型调用**探测 |

`health?strict=1` 聚合校验：主模型 + 临床复核 + 证据检索 + 舌象视觉 + 审方 + 快照加密 + 推理签名 + 临床事实 + 中医治疗配置 + 限流身份。任一不就绪即 `strictReady=false`。

生产环境健康检查示例：

```bash
curl -s "https://82.156.128.153/tcm-cdss/api/diagnosis/health?strict=1" \
  -H "x-cdss-api-token: <API_TOKEN>"
```

## 4. 流式响应契约

### 4.1 NDJSON 格式

M02–M05 阶段接口返回 `application/x-ndjson`，逐行 JSON：

```
{"content":"## 本次分析结论\n"}
{"content":"**结论**：肝胃不和证\n"}
{"content":"[END]"}
```

| 行类型 | 含义 |
|---|---|
| `{"content":"..."}` | 正文分片，按顺序拼接 |
| `{"content":"[END]"}` | **流正常结束标记** |
| `{"error":"..."}` | 错误；此时不应采纳任何已接收内容 |

客户端必须以 `[END]` 判定完成。未见 `[END]` 即连接中断，视为失败。

### 4.2 进度替换标记

流中可能出现 `<<<CDSS_STREAM_FINAL>>>`。该标记**之前**的内容是过程提示（如"正在校对…"），**之后**才是最终正文。

正确处理：

```js
const marker = "<<<CDSS_STREAM_FINAL>>>";
const idx = fullContent.lastIndexOf(marker);
const visible = idx >= 0 ? fullContent.slice(idx + marker.length) : fullContent;
```

### 4.3 结构化结果提取

M03/M04 的最终正文中嵌入结构化 JSON：

```
<!-- DIAGNOSIS_JSON_START -->
{ "schemaVersion": "tcm-cdss-reasoning-v2", "stage": "diagnose", ... }
<!-- DIAGNOSIS_JSON_END -->
```

提取该对象后：
- 作为 `reasoningDiagnose` / `reasoningPrescribe` **原样**回传给下一阶段；
- 不要修改任何字段——其中含服务端签名。

### 4.4 心跳与超时

服务端每 5 秒发送心跳保持连接。单次流的服务端限制：连接 90s / 空闲 60s / 总计 180s；M03 编排总时限 180s、M04 为 120s。

**客户端建议超时：M03 ≥240s，M04 ≥180s，M05 ≥120s。**

### 4.5 安全警示横幅（必须实现）

命中红旗、危急体征、就诊目标未确认等确定性判定时，M03/M04 的可见正文**最前**会出现：

```
<!-- CDSS_SAFETY_ADVISORY -->
> ⚠️ **安全警示（未解除，请医生优先处置）**
> - 红旗提示：……
> - ……
> - 以下分析与候选方药仅供医生在完成上述风险处置判断的前提下参考，采纳前须经院内审方复核。
```

集成方约定：

1. 用稳定标记 `<!-- CDSS_SAFETY_ADVISORY -->` 检测其存在（标记后到首个 `## ` 标题前的引用块即横幅内容）；
2. 横幅必须以**最高显著级别**原样展示给医生，不得折叠、截断或延后；
3. 横幅存在时，候选内容不得被自动写入院内处方系统——采纳动作必须由医生显式发起；
4. 横幅之后可能还有**质量批注**段落（普通段落，含"已完整通过安全核验……请……再采纳"措辞），
   同样应在结果区显著呈现；
5. 横幅与批注都在首个 `## ` 标题之前——按节抽取渲染的集成方必须单独处理这段前置区，
   否则会把服务端警示静默丢弃。

## 5. 错误码

| 状态码 | 含义 | 处理建议 |
|---|---|---|
| `400` | 请求体非法 / 缺 `caseState` | 检查请求体结构 |
| `401` | 未鉴权或 token 错误 | 检查鉴权头 |
| `409` | 签名缺失或内容被修改 | 重新生成上一阶段结果 |
| `413` | 请求体超 1 MB | 精简病历文本 |
| `429` | 触发限流 | 退避重试 |
| `503` | `strict=1` 下未达发布就绪 | 检查依赖项配置 |
| 流内 `{"error":...}` | 模型或上游异常 | 不采纳已接收内容，重试 |

## 7. 集成注意事项

1. **不要跳过 M03 直接调 M04**：M04 要求 M03 的签名推理结果，缺失时返回非剂量降级输出。
2. **原样回传结构化结果**：任何字段改动都会导致签名校验失败（`409`）。
3. **非剂量输出是正常行为**：安全边界触发时的 fail-closed 降级，UI 应正常展示其中的风险说明与补录项，而非报错。
4. **回传 `clinicalFacts`**：避免各阶段重复语义预检，显著降低时延与失败率。
5. **舌象图片**：需服务端开启 GLM 视觉能力；未开启时上传会被明确拒绝，不做静默降级。
6. **单实例限流**：当前限流为进程内计数，水平扩容会使实际限额成倍放大，扩容前需联系我方调整。
7. **时延预期**：完整 M03→M04→M05 链路典型 **2–4 分钟**。建议集成方采用异步任务 + 前端轮询/推送，而非同步阻塞等待。

- 系统不提供最终处方放行能力，所有输出须经医生与药师复核。
