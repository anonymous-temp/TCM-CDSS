# 灵犀中医 CDSS 诊疗推理思路与数据支撑全景

> 版本：2026-07-27
> 阅读对象：临床专家与产品团队。本文用诊疗语言讲清三件事：① 系统看一个病人时是怎么一步步思考的；② 每一步背后有哪些权威数据在支撑、如何被用到；③ 一个真实病例在系统里如何走完全程。

---

## 一、先说明四个专业标注的出处

辨病辨证结果中，每个子病机旁边可能带一个角色标注（始动 / 传变 / 兼夹 / 因果）。这四个词都有专业出处，不是自造词：

| 标注 | 含义 | 出处 |
|---|---|---|
| 始动 | 启动整条疾病演变链的第一个环节 | 现代中医病机学研究的通用表述「始动环节」，如《中国中医药报》及慢性心衰病机研究文献中「以气虚为始动环节」 |
| 传变 | 由前一环节演变、传化而来的后继病机 | 经典术语。《内经》即有「病机与传变」专论，《伤寒论》六经传变、温病卫气营血传变是辨证论治核心概念 |
| 兼夹 | 与主病机并列存在的兼夹病机（如夹湿、夹痰） | 经典术语。中医诊断学「兼夹证/兼夹病机」，《病机十三条》理论将兼夹病机列为独立条目 |
| 因果 | 与主环节构成明确因果关系的环节 | 通用逻辑词，非中医专有名词 |

需要坦诚说明的一点：单个词都有出处，但「用这四类来标注病机链」这套用法，是我们为了让计算机能读懂病机结构而做的归纳设计，不是某本教材的既有分类。系统同时约束模型：只在时序或传变关系确有临床意义时才标注，不允许为凑标签而标。

## 二、总体思路：系统是怎么"看病"的

系统不是让一个模型从头说到尾，而是模仿临床医生的诊疗路径，分五步推进，全程有四道安全护栏：

```
  ① 病历采集        ② 针对性追问       ③ 辨病辨证           ④ 候选方药          ⑤ 审方随访
  病情录入与整理 →  只问能改变判断 →  西医诊断+中医证候 →  从权威方剂目录  →  风险汇总与
  舌象照片识别      的关键问题        +病机拆解+治法        中选方定量          随访规划

  ─────────────────────────── 四道全程护栏 ───────────────────────────
  护栏一 安全红线：生命体征危急值与急危重信号由系统规则直接判定，不交给模型
  护栏二 事实底线：模型的补充发现只能"追加提醒"，永远不能"撤销"已确认的阳性发现
  护栏三 证据支撑：本地知识库+经典文献+外部循证证据，在各环节为推理提供依据
  护栏四 结果防伪：辨证、处方、审方三段结果与当前病例绑定签名，防止张冠李戴
```

贯穿全程的五条铁律：

1. **安全的事不归模型管**。危急值、急危重、能不能出剂量，全部由确定性规则判定。
2. **系统只做建议，决策权永远在医生**。每一条结论必须能追溯到患者事实、明确规则或知识库条目；做不到的，显式告诉医生"证据不足"，绝不硬编。
3. **宁可降级，绝不猜测**。审方服务不可用、剂量依据缺失、结果不完整时，系统自动降级为"不带剂量的建议"，绝不把"不知道"当"没问题"。
4. **"没问过"不等于"没有"**。过敏史、用药史等未提及的项目按"未知"处理，绝不当作"已否认"参与推理——这是临床AI最容易犯、我们明确禁掉的错误。
5. **说的每个字都要有出处**。方从权威目录里选，量在权威边界内定，禁止编造文献引用。

## 三、一个真实病例走全程

用一例线上真实病例串讲（取自系统实际界面）：

> **陆某，女，24 岁。** 主诉：咳嗽 3+ 天。3 天前淋雨后出现咳嗽，咳声重，气急，咽痒，咳白稀痰，伴鼻塞、流清涕、头痛、肢体酸痛、恶寒发热、无汗，纳眠可，二便正常。既往无特殊病史，无药物食物过敏史，无用药史。体温 37℃，脉搏 80，呼吸 18，血压 110/78。神清，面色红润。舌淡苔薄白，脉浮紧。医生流派偏好：脾胃学派。

这是一个典型的风寒袭肺案。选它串讲，是因为简单病例最能看清系统每一步到底做了什么。

---

## 四、第一步：病历采集

**做什么**：把医生录入的主诉、现病史、既往史、过敏史、用药史、生命体征和四诊信息整理成规范病历，并完成三道前置检查。

**怎么做的**：

- 纯文字病历的整理是工程动作，**不需要动用模型**，录入即成型。
- 舌象照片由**视觉模型**识别，提取舌质、舌苔、舌形等结构化描述；识别失败时明确提示医生改为手工录入，不会悄悄跳过。
- 生命体征由系统自动核对危急值（血压、体温、脉搏、呼吸、血氧各有明确阈值），命中即提示。
- 涉及患者隐私的信息在送往模型分析前先做脱敏处理。

**这一步用到的数据**：急危重分诊词表（录入内容的初筛）、诊断用语规范词表（把口语表达归一为规范医学表述）、必填字段清单（明确一份合格门诊病历必须有哪些要素）。

**本病例中**：陆某生命体征全部正常、文字无急危重信号、无舌象照片（医生手录"舌淡苔薄白"）——采集环节零等待，直接进入下一步。

---

## 五、第二步：针对性追问

**做什么**：不是按模板问一整套，而是**只问"答案会改变诊断或用药"的问题**；医生用自然语言回答，系统自动理解并写回病历。

**怎么做的**：

- 系统先评估当前病历的信息完整度：急危重排查是否覆盖、主诉要素是否齐全、四诊是否完备、过敏与用药史是否明确。
- 针对真正的缺口生成少量追问，每个问题都附带"为什么这个问题影响判断"。
- 医生回答"没有""以前有过"这类口语时，系统区分为五种状态：确认有 / 可能有 / 确认没有 / 既往有 / 未知——**"没问过"永远记作"未知"，不记作"没有"**。
- 追问有轮次上限：问完一轮即使信息仍不完美，也允许带着"有限信息"的标注继续走，不会把医生卡在追问里。

**本病例中**：系统给出的待核实点是两个真正影响选药的鉴别点——

- **项背部是否僵硬拘紧**：若有，提示太阳经气不利，方药上要考虑是否加葛根、桂枝；
- **是否始终无汗**：用于鉴别表实表虚，影响解表药的选择与力度。

可以看到追问的粒度：不问"还有什么不舒服"这种宽泛问题，只问能改变处方构成的关键点。

---

## 六、第三步：辨病辨证（系统思考的中枢）

**做什么**：一次产出四层结果——① 西医工作诊断与鉴别方向；② 中医病名与证候；③ 病机拆解（症状如何组合成证、病位病性、病机如何演变）；④ 治法与方剂方向。

**怎么做的**（按实际执行顺序）：

1. **先过安全与完整度检查**：确认没有未处置的急危重信号、病历信息达到可诊断标准（完整度由系统规则独立评估，不采信模型的自我评价）。
2. **语义级风险补查**：模型再读一遍病历，专门捕捉口语化的风险线索（比如患者说"最近瘦得厉害"这类不在结构化字段里的信号）。这一层**只能追加提醒，永远不能推翻已确认的阳性发现**。
3. **装配证据**：把与本例相关的知识库条目、经典文献段落、外部循证证据整理好，随病例一起提供给模型。
4. **大模型主生成**：输出完整的结构化辨证结果——医生在界面上看到的每一项都来自这一步。
5. **系统逐条校验**（这是与"直接问大模型"最本质的区别）：
   - 病名、证候、病位、病性、治法必须落在**国家标准词表**内，模型自由发挥的词会被拒收；
   - 推荐的方剂名必须能在**权威方剂目录**中检索到，检索不到的推荐会被剔除；
   - 写入"患者事实""证候依据"的每句话，必须能在病历原文中找到——**患者明确否认的症状，禁止当作证据**（比如病历写了"无盗汗"，就不能因为某证型常见盗汗而写进依据）；
   - 信息完整度由系统重新独立评级。
6. **独立复核**：由模型以全新的视角对辨证一致性、证据可靠性、诊断标准符合度再做一遍复核，不通过则带着修改意见重新生成（有总时限，超时自动降级而不是无限重来）。
7. **结果签名**：辨证结果与本病例绑定签名，后续开方、审方环节都要验明"这张处方确实是从这份辨证来的"。

**这一步用到的数据**：

| 数据资产 | 规模 | 起什么作用 |
|---|---|---|
| 中医证候标准词表 | 2,000+ 条 | 证候名称必须出自词表，防止生造证名 |
| 病性、病位标准词表 | 31 + 36 条 | 气虚、血瘀、痰湿、肺、脾、肝等规范表达 |
| 治法标准词表 | 1,200+ 条 | 治法方向的规范表达 |
| 中医病名标准词表 | 1,267 条 | 以国家标准 GB/T 16751.2 病名为主体；关键词精确匹配 + 大模型自然语言理解兜底（医生怎么写都能对上规范病名） |
| 国际疾病分类（ICD-10）索引 | 45,000+ 条 | 西医诊断名称与编码规范 |
| 辨证规则库 | — | 八纲、脏腑等辨证框架规则 |
| 温病辨证规则 | 73 条 | 卫气营血全层、三焦全层、湿温及变体、伏暑秋燥疫毒、瘥后调治的辨治规则（每条均可回溯条文原文） |

| 外部循证证据库 | 实时检索 | 指南、说明书、文献级证据 |
| 古今医案语料 | 17,000+ 条 | **仅用于系统自我评测，绝不出现在给医生的依据里** |

**本病例中**，系统实际产出（与界面所见一致）：

- **证候**：风寒袭肺证；**病名**：咳嗽——均在标准词表内；
- **症状与病机的联系**：「咳嗽 3 天+气急+咽痒+咳白稀痰 → 风寒犯肺，肺气失宣，气逆作咳」「无汗+肢体酸痛+鼻塞+流清涕 → 风寒束表，卫阳被遏，经气不利」——每个症状都能回到病历原文；
- **子病机 1（始动）**：风寒外束，卫阳被遏，肺气失宣——"始动"即表示淋雨外感是整条疾病演变链的起点；
- **病位**：肺、卫表；**病性**：风寒、表实，依据为舌淡苔薄白；
- **待核实信息**如实列出（项背情况、汗出变化），而不是默默当作"没有"；
- **方剂方向**：从"风寒袭肺、表实"检索出的候选方集（三拗汤、止嗽散一类），经目录校验后才成立。

## 七、第四步：候选方药

**做什么**：把"方剂方向"落实为一张医生可审阅的完整候选处方：定方、定药味、定剂量、定煎服法、定加减，并逐味完成安全性核验。

**怎么做的**：

1. **先验明正身**：确认这张处方确实从当前病例的辨证结果而来（验签名）。
2. **判定处方权限**：系统按规则判定本例能出到哪一级——完整剂量 / 有限信息候选 / 只出不带剂量的建议。判定依据包括：急危重信号、儿童、妊娠哺乳、严重肾功能不全、正在抗凝治疗等高风险情形。
3. **核验全方可执行性**：所选方剂的每一味药，都必须同时满足"身份明确"（是确定的哪味药、哪种炮制规格）和"剂量有据"（有权威来源的数值范围）。任何一味不满足，整张方就不生成剂量——**宁可只给方向，不给半张处方**。
4. **大模型在边界内个体化**：系统把该方的标准组成、每味药的剂量上下限、先煎后下等要求交给模型，模型在这个"安全框"内根据病情做剂量与加减的个体化。
5. **处方完整性校验**：同一味药不得拆成两行含糊并列；剂数、每日服法、疗程必须相互吻合；加减建议中夹带未经审核的剂量会被剔除。
6. **统一审方**：整张处方过一遍统一审方——十八反十九畏配伍禁忌、剂量超限、特殊人群禁忌、中西药相互作用逐项核查。审方服务万一不可用时，降级为本地规则核查并提示人工复核，不会硬停流程。
7. **结果签名**，供最后一步验明。

**这一步用到的数据**：

| 数据资产 | 规模 | 起什么作用 |
|---|---|---|
| 权威方剂目录 | 2,937 首 | 选方的**唯一合法来源**，每首方带来源分级（国家经典目录/地方标准/验证补充） |
| 已验证补充方剂 | 2,219 首 | 从温病 19 部等方书中经"智能抽取+人工治理"双流程补充入库 |
| 同名异方出处分流表 | — | 防止不同来源的同名方张冠李戴 |
| 药材身份目录 | 630 个标准名（覆盖 493 个易混表述） | 把"炒白芍""杭白芍"这类写法归一到明确的药与规格 |
| 身份裁定记录 | 600+ 条 | 歧义药名（如芍药指白还是指赤）逐方裁定的结论 |
| 剂量权威边界 | 695 味药 | 每味药的剂量上下限、先煎后下、风险分级 |
| 毒性药品管理清单 | 按国家法规 | 国务院《医疗用毒性药品管理办法》品种、麻醉品种、大毒品种——含这些药的处方按法规从严管理 |

**本病例中**：陆某为成年人、无妊娠、无高风险用药、体征正常，获得完整剂量权限；所选方（三拗汤类）组成简洁，麻黄、苦杏仁、甘草等每味身份明确、剂量有据，顺利通过全部核验与统一审方。

**对照情形**：若另一位患者的辨证指向含附子的方剂，因附子属毒性品种，按现行口径该方只保留方向供医生参考、不生成剂量——这是法规性从严，不是系统能力不足。

## 八、第五步：审方随访与对接输出

**做什么**：

- **风险与随访汇总**：把审方结论、用药注意、复诊节点整理成随访规划。这一步是纯粹的规则汇总，不新增模型判断。
- **对接医院系统**：生成结构化的"AI 诊疗支持方案"传给医院信息系统；当本例只出了非剂量建议时，传给医院的也是同口径的非剂量内容——**医生看到什么，下游系统就收到什么**，不会两本账。

**本病例中**：审方通过，系统给出随访建议（服药 3 剂后评估汗出与咳嗽变化，若出现黄痰、咽痛等化热表现需复诊调方）、调护要点（避风寒、温服取微汗），以及明确的安全网提示（如高热不退、喘促憋闷应及时就诊）——这条安全网由急危重词表规则驱动，不是模型的自由发挥。

## 十、已知的边界与在途改进（如实说明）

- **急危重识别是"规则+智能"双保险**：词表负责精准命中的底线，语义理解负责兜底口语化表达。单靠任何一层都盖不住自然语言的全部说法，双层是刻意设计。
- **温病辨证规则已成体系**（73 条）：卫气营血全层、三焦全层、湿温及变体、伏暑、秋燥、疫毒、瘥后调治均有覆盖，每条规则可回溯条文原文。
- **"证候—方剂"关系网已基本织成**：2,060 个标准证候中 1,628 个（79.0%）已建立方剂关系。最终审查删除了“表/寒/热/虚”4 个单字八纲直接绑方的污染行，构建器现会对同类输入硬失败；残余约两成为泛根词与确无方可锚的长尾复合证，由模型推理兜底。
- **独立复核目前是同一模型的独立请求**：复核与生成尚未做到不同模型交叉验证，跨模型复核在规划中。
- **交互体验整改在途**：当前"不给剂量"的页面拦截感偏重，已确定改为"正常显示+风险标红+醒目提示"的方案，实施后将更新本文相关口径。
