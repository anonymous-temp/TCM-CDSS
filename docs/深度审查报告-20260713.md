## 2. 架构诊断：为什么补了一堆正则

### 2.1 一个系统里有两种活，要求正好相反

| | 干什么 | 该谁做 | 为什么 |
|---|---|---|---|
| **推理/生成** | 辨证、病机、候选方、随访 | **LLM**（现状即是） | NL 原生性是资产，我们没有用正则做辨证 |
| **安全裁决/接地** | 红旗、剂量上限、十八反、fail-closed 降级、反伪造 | **确定性**，且不信 LLM | LLM 会在真有胸痛的病人上幻觉"无红旗"；安全层要的是**可证明地 fail-closed**，不是"大概率对"。这也是 CLAUDE.md 的硬约束（advisory-only，结论须可溯源，不得让模型出硬裁决或绕过安全层）。 |

两列都对。问题不在"有确定性安全层"，而在它的**输入是散文**。

### 2.2 那 245 条正则在做什么——是抽取，不是推理

它们的活是把「黑便」「BP 190/110」「孕20周」从医生散文里抠出来。**正则是糟糕的 NL 抽取器**，于是越补越多、补不完。本次修复的 CRITICAL 就是活证据：

> `黑便3天，无腹痛、无发热` → 旧正则分不清"无"否定谁，把**黑便**当成被否定 → 消化道出血红旗漏报。

一个 LLM 抽取器一眼就知道"黑便=present、腹痛=negated"。**我们不是"用了 LLM 才要补正则"，恰恰是在 LLM 唯一真正擅长的地方（理解 NL、抽取事实）没用它。**

### 2.3 正确架构：LLM 抽取 + 确定性裁决（互补两层）

```
现状(错):  散文 ──▶ [正则抽取 + 安全裁决 混在一起]      ← 245条正则啃NL，漏了即 fail-open
                        └ 前端再用 ~40条正则 反解模型 markdown 去渲染

正解(对):  散文 ──▶ [LLM 受约束抽取] ──▶ ClinicalFacts(结构化，单一真源)
                                          ├──▶ [确定性规则]  红旗/剂量/十八反/裁决
                                          └──▶ [纯渲染]     报告卡片直接读结构
```

安全**检查**一条不删，只让它跑在结构上。LLM **只做加法、抬高召回**，永不覆盖确定性结论（合理用药那套 `_LLM_SUPPRESSIBLE = ∅`、additive-only、fail-closed）——LLM 状态再差只能让系统**更保守**。

### 2.4 现有"规则"诚实分三类

1. **该留、且本就该确定性查表**：十八反/十九畏、剂量上限、BP/体温危急阈值——这些是**事实不是判断**，确定性查表既对又可审计。这是正当的"审方式"内核（小而边界清晰）。
2. **放错位的抽取**：245 条啃散文的 NL 正则。不是删，是**换成 LLM 抽取 → 结构**，裁决照跑。
3. **纯自伤**：前端 ~40 条正则去反解模型自己吐的 markdown——而模型**已产出 sentinel 结构化 JSON**。直接删正则、从 JSON 渲染即可。
