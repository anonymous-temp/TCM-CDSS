# 倪海厦 skill 融合方案 v2（主体推演逻辑融合版）

> 取代 v1。v2 定位变化：**不做流派旁路，全部投入 M01–M05 主体推演逻辑**。版权已由甲方持有，内容可整体数据化；原始资料解析（含 10538 张页级证据卡、RAG 资产）已获许可。
> 两条仍然成立的硬约束：①**安全**——生附子/生硫磺/放血/民俗急救/拒西医言论进隔离区，永不穿透 advisory 输出；②**质量**——nihaixia 数量以实测为准（医案 ~196+245 非 849；modules/05 标题错标；针灸仅 132 行），稀疏字段重标。
> 分流原则从"流派标签"改为**证据等级制**：`canon`（公版条文：伤寒/金匮/内经/公版古籍）/ `common`（通用诊疗知识：十问、穴位表、八纲真假寒热鉴别）/ `experience`（倪派经验观点：扶阳思路、倪派剂量、闭门课）/ `quarantine`（危险品存证）。`canon/common` 进主线无标注负担；`experience` 进主线须标注"经验参考"且服从安全层；`quarantine` 仅存证。

> **v2.1 实测校正（2026-07-22，对 evidence-cards.jsonl 全量 10538 卡实测）**：
> ①卡构成：倪师课程 **3080 卡（29%）** / 公版古籍 **7458 卡（71%）**——T15 的主体是公版古籍，不是课程；
> ②**金匮四份源（人纪05金匮 342 页/倪海厦人纪金匮 419 页/醫宗金鑑傷寒 364 页/仲景心法 85 页）编号条文为 0**，只有篇名可锚——金匮证据只能是**篇-段级**，不能按条文抽取；
> ③伤寒两源编号条文（"一五：太阳中风…"式）**并集 326/398 ≈ 82%**，可正则切分——伤寒证据做到条文级；
> ④**term-index 不建**：它是滑窗短语碎片（含"桂枝汤"的词条 384 个多为"所以桂枝汤"类，命中仅 7 而全文实际出现 458 次，召回约 5%）；10538 卡全表朴素扫描 0.005s，运行时直接扫，不做预建索引；
> ⑤§6 首批 40 首经方实测锚定：**20 首可挂编号条文、19 首仅页级命中、2 首栽在方名异文**（麻杏石甘汤→源作"麻杏甘石汤"，实测 61:4）——须先建方名异文表再跑锚定；
> ⑥**隔离必须做在记录级，不能做在页级**：实测含"生附子"的 158 卡中 55 卡同页载有完整方证煎法（甘草干姜汤例），针灸页同页兼有穴位主治与反疫苗言论——页级隔离会误杀正典内容。

## 3. 设计一：M03 推理程序化（治"罗列病史"的根）

测评诊断类问题的总根是：**M03 规定了输出长什么样，没规定推理怎么走**。把七步走改造为 M03 的**七段推演链**，直接落进现有 schema（不动骨架，只给每段加"推演义务"和确定性校验）：

| 推演段 | 落点（现有字段） | 推演义务（新校验） |
|---|---|---|
| 1 定表里/病位 | `locationDifferentiation` | 每个病位必须带**支持该位的症状+舌脉证据**；禁止"仅主诉单症状定位"（单证据病位进 uncertainties） |
| 2 分阴阳/整体状态 | `overview.tcmDiagnosticRationale` | 先给整体状态判断（精神/睡眠/胃口/二便/手足温——十问维度），再给局部分析 |
| 3 辨寒热（真假） | `natureDifferentiation` | 寒热结论≥2 个维度证据（八维清单：面色/口鼻气/舌/脉/胸腹/小便/口渴/大便）；证据不足标注"寒热未明"而非硬判 |
| 4 判虚实/病性 | `natureDifferentiation` | 同上，病性词必须命中 T2 词表 |
| 5 病机链 | `chain` | 每环=始动因素→演变→当前状态，环间有因果词，每环节点挂患者事实锚点（≤60 字短引用，与 C2 修复并轨） |
| 6 候选方证+鉴别 | `tcmDifferentials` / `westernDiagnosis.differentials` | 每条鉴别必须**回答对侧问题**："未取 X 是因为缺少鉴别点 Y"（结构化字段 `discriminatingPoint` + `status: confirmed_absent/unknown`）；unknown 的鉴别点自动进建议补充信息 |
| 7 治则治法 | `therapy` | 治则锚 T4 词表、治法挂病机关联（已有校验，保留） |

- 落地：改 `reasoningV2Instruction`（diagnosis-prompts.ts:353-446）的字段说明 + `m03SemanticIssue` 加分步校验码（`discrimination_missing`、`single_evidence_location`、`nature_dimension_insufficient`）。**不加模型调用轮次**，只是输出结构与校验的程序化——不动延迟预算。
- reviewer 同步：M03 复核 prompt 增加"推演链完整性"审计（七段是否环环有证据）。

## 4. 设计二：鉴别驱动闭环（分水岭 = 主线核心推理原语）

**M02**：建追问题库 `discrimination-questions`（入 T14）：每题 = `{ questionText, options?, discriminates: [方证/证型 id 对], priority, sourceRef }`。题源三件套：symptom-index 11 症状×"必须问"清单（如有汗/无汗、恶风/恶寒、口渴与小便色、咽喉干燥、尺脉——注意它的"必须问"自带禁忌线索）、12 行快速分水岭总表、17 条白话→辨证映射。M02 选题逻辑：当前候选方证集合 >1 时，优先选鉴别值最高的分水岭题；兼顾十问覆盖度（§5）。
**M03**：鉴别点回答回填后确定性收敛候选（T14 边命中加权进锁方打分）；未知鉴别点显式列出（医生看到的"建议补充信息"从此有鉴别目的，不再是泛泛"信息不足"）。
**M04**：方证对应说明展示鉴别路径（"以有汗、脉浮缓取桂枝汤；与麻黄汤的鉴别点：汗之有无"）——测评"选药依据不明"的正面回答。

## 5. 设计三：四诊合参规则库（T13）

`src/data/tcm-differentiation-rules.json`：
1. **十问系统回顾**：十问（睡眠/胃口/大便/小便/口渴/寒热/汗/体力/性功能/月经——张景岳十问歌，通用体系）作为 M01/M02 的**覆盖度 checklist**：缺失维度进 M02 候选题（按信息增益排序），M03 输出须声明"本结论未覆盖的系统回顾维度"（防单症状定位）。
2. **脉舌合参**：脉诊 8 单脉+8 复合脉→主病、舌诊 5 单舌+6 复合舌→方证，转 JSON 作为 M03 舌脉解释的对照表（模型舌脉解读与表冲突时进 uncertainties）。
3. **冲突裁决**：脉舌矛盾树（"以舌为准"）等 5 条 → 确定性提示规则：检测到脉舌指向冲突时，在病机分析中显式说明取舍依据。
4. **真假寒热八维**：寒热判定的 8 维证据清单（§3 第 3 段使用）。
5. **六经辨证维度**：8 公式+合病并病 11 表+治疗先后 4 原则，作为病位/病性体系的**第三套标准维度**（与脏腑、卫气营血并列——六经本身是教材体系，不是流派私产）；T3 病位表同步补六经（太阳/阳明/少阳/太阴/少阴/厥阴）。

## 7. 设计五：方证鉴别图谱（T14）+ 经典证据层（T15）+ 解析管线

**T14 `tcm-formula-discrimination-graph.json`**：节点=方证（T8 id）×症状簇；边=鉴别问题（`{from,to,discriminatingSymptom,questionText,contraindicationHints?,sourceRef}`）。源：63 方证鉴别点 + 合病并病表 + 分水岭表 + 十问。消费：M02 选题、M03 收敛、M04 说明。
**T15 `tcm-classic-text-evidence.json`**：**记录级**证据单元（不是页级）——`{evidenceId, 文献, 卷篇, anchorLevel(tiaowen/chapter_paragraph/page), 条文或段落原文, 关联方剂[], 关联证型[], 页码, 版本, tier, safetyClass}`。解析时把每张页卡**切分为多条记录**（方证段/条文段/观点段），逐记录挂方挂证、逐记录定 tier 与 safetyClass——同一张页可同时产出 canon 方证记录与 quarantine 言论记录（实测 158 张含生附子卡中 55 张同页有完整方证煎法，页级处置会误杀）。切分规则按源分级：**伤寒系两源按"一五：…"编号正则切成条文记录（两源并集覆盖 326/398 ≈ 82%）**；**金匮四源无编号条文，按"篇名+段落"切成篇段记录**；公版古籍按页/节切。M03/M04 任何"出处/依据"展示都从这里取，**模型不再凭记忆引条文**；检索不做预建索引，运行时全表扫（10538 条 0.005s 量级）。
**原始资料解析管线**（用户已许可，见 §11 清单）：`scripts/ingest/` 下建四个解析器：页级卡→记录切分器（JSONL→记录级 T15，含编号/篇名两套切分规则）、记录级分类器（逐记录定 tier/safetyClass，隔离区记录进独立 quarantine 存储）、条文块抽取器（modules md→方证/方义/医案结构化）、交叉校对器（抽取结果与页级原文逐条对拍，不一致进 reviewQueue——沿用 nihaisha "BUILD_AND_UPDATE" 的同代资产原子发布纪律）。

## 8. 设计六：M04 方义、条文加减与禁忌矩阵

1. **方义（组成逻辑）**：从条文块与方证表抽取君臣佐使/组方原理入 T8 `compositionLogic` 字段——候选方药卡的"方剂组成逻辑和配伍分析"从模型即兴改为证据层生成。
2. **条文加减规则**：伤寒（条文级）/金匮（篇段级）的加减法（"若喘，加厚朴杏子"类）抽为 `textualModifications: [{triggerSymptom, addHerb, removeHerb?, sourceEvidenceId}]`——随症加减的"依据来源"列直接显示条文/篇段原文，trigger 仍须锚定当前病历（既有四层校验保留）。这是测评问题 23 最硬的解法。
3. **禁忌矩阵**：发汗禁忌条文（咽喉干燥、淋家、疮家、衄家、亡血家、尺脉迟微、少阴病禁汗）+ 用药铁律 7 条 → `contraindication-rules.json`（证型/状态 × 禁忌治法/方药），M04 `m04SemanticIssue` 前置确定性检查，审方前拦截。
4. **剂量**：条文原方剂量只作展示（"原方：桂枝三两"）；规则剂量永远取药典/KB；倪派剂量不入库。
