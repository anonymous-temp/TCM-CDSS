## 1. 已修复问题（本轮）

### 1.1 安全门过度拦截辨证 ✅
- **现象**：45 岁女性、信息齐全的病例，M03 在 31ms 内返回"信息不足建议模式"（未走模型），红旗把辨证也拦了。
- **根因**：`evaluateSafetyGate` 把"妊娠/哺乳/备孕状态"等**只与处方相关**的缺失项计入 `missingItems`，而 `missingItems.length>0` 直接置 `allowDiagnosis:false`，连辨证一起拦。
- **整改**：拆分 `diagnosisBlockingMissing`（核心辨证信息）与 `PRESCRIPTION_ONLY_MISSING`（妊娠/哺乳/备孕/儿童体重/已提及但缺过敏原·药名）。前者才拦辨证；后者只拦剂量级处方（`allowDosePrescription:false`），辨证放行。
- **文件**：`src/lib/diagnosis-safety.ts` `evaluateSafetyGate`
- **验证**：回归 144 例 0 失败；M03 恢复完整辨证。

### 1.2 M01 完整度四维分数恒为 50% ✅
- **现象**：信息充分度四个进度条永远 50%，对医生无意义。
- **根因**：`SENTINEL_INSTRUCTION` 的 JSON 示例把四项**硬写成 0.5**，且**无逐维打分规则**，模型直接照抄示例。
- **整改**：示例改为差异化数值 + 明确禁止四项同值 + 补 `redFlag/infoGain/managementImpact/answerability` 逐维打分口径。
- **文件**：`src/lib/diagnosis-prompts.ts` `SENTINEL_INSTRUCTION`
- **验证**：实测输出 `{0.6,0.7,0.6,0.65}`（差异化）。

### 1.3 完整度显示分数与已升级的等级矛盾 ✅
- **现象**：等级已（被确定性逻辑）升到 C，进度条却还显示模型的 50%。
- **根因**：`withSafetyGate` 取 `MAX(模型等级, 确定性等级)` 覆盖 `level`，但**保留模型的分数**用于显示。
- **整改**：显示分数改为**逐维 `max(模型, 确定性)`**，与驱动等级的评估一致。
- **文件**：`src/lib/diagnosis-safety.ts` `withSafetyGate`

### 1.4 M03 在门控=C 时自我降级 → 处方断链（非确定性）✅
- **现象**：同一病例，有时出处方、有时"信息不足建议模式"卡死不出处方。
- **根因**：M03 提示词给了三个结论选项，模型可因缺年龄/生命体征而选"信息不足建议模式"；前端 `isLimitedDiagnosisText` 命中即**在 M04 前掐断链路**。
- **整改**：向 M03 提示词**注入确定性完整度门控等级**，并加硬规则：门控=C 且无阳性红旗时**结论必须"完整候选方案"**，缺失项写入"缺失信息/下一步管理"，**不得据此降级**。
- **文件**：`src/lib/diagnosis-prompts.ts` `buildDiagnosePrompt`
- **验证**：实测结论=完整候选方案、链路续跑至 M04 出真实处方。

### 1.5 M03 各段孤立、治法与红旗不呼应 ✅
- **现象**：红旗排查喊"贫血/甲状腺待查"，治法自顾自"补益心脾"，中间无衔接；医生不知下一步。
- **整改**：M03 输出末尾新增"**下一步管理与医生须知**"段，强制串联 红旗排查→西医待排检查→中医治法→按优先级补录项→随访安全网。
- **文件**：`src/lib/diagnosis-prompts.ts` `buildDiagnosePrompt`
- **验证**：实测输出把"贫血→查血常规、甲状腺→查甲功"与治法逐条对应。

### 1.6 辨证充分度卡片混入旧"信息充分度"文案/配色 ✅

### 1.7 剂量处方门接入辨证充分度 + 轮次逃生阀 ✅

### 1.8 【本轮 A / 曾是 #1 关键】辨证门控依赖脆弱的正则解析模型标题 ✅
- **现象**：M03 返回完全有效的辨证（结论=完整候选方案），但把证候写在白名单外的标题（如"## 中医辨证结论"）下，`buildDecisionSummary` 解析不到 → 证候信号"missing" → 辨证充分度恒判"辨证不足" → 门控永不放行 → **假追问循环 + 每轮白跑一次 M03（LLM）**。

- **整改**：证候/病机信号**优先读结构化** `reasoningV2.overview.primarySyndrome / overallPathogenesis`，正则解析仅作兜底。门控从此不受标题措辞漂移影响。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx:699`（`buildDifferentiationSignals`）

### 1.9 【本轮 B / 安全 fail-OPEN】灵犀降级审方被当作低风险 ✅

## 2. 待修问题（按优先级 + 详细整改建议）

### O1 —【中·安全层】确定性风险 `hasStrongRisk` 全文过度扫描，良性医嘱被误升级为"强提示/较高风险" ⬜
- **现象**：灵犀判"中风险"，但下方"处方安全总评"写"最高提示强度：强提示 / 综合风险判断：较高风险"，二者当着医生面自相矛盾；几乎每张真实处方都会触发。
- **根因**：`buildDeterministicRiskFollowup` 的 `hasStrongRisk` 正则 `/(强提示|(?<!最)高风险|禁用|十八反|十九畏|…)/` 扫描 `state.riskAssessment + state.prescription + state.diagnosis` **整块**，命中处方里"郁李仁…便溏禁用"这类**逐味常规禁忌注记**、以及 M04 自己写的"提示强度：强提示"。
- **影响**：非安全漏洞（方向是过警 fail-safe），但**破坏专业可信度**，且让"综合风险判断"失去区分度（对真实处方几乎恒为较高风险）。
- **整改建议（谨慎，安全层）**：
  1. **按小节限定扫描**：只在"## 用药风险提示 / ## 处方安全总评 / ## 确定性处方风险复核 / 灵犀审方段"内扫描，不扫处方正文的逐味"安全提示/证据依据"列与诊断正文。可复用 `extractSectionLoose` 抽取这些小节再判。
  2. **与灵犀结论对账**：当灵犀审方成功时，"综合风险判断"应与灵犀 `highest_risk_level` 取较高者并**注明来源**（"本地从严叠加"），而非与之矛盾地各报一套。
  3. **不要简单删 `禁用` 等词**（会漏警真实禁忌）——务必走"限定小节"而非"删词"。
- **文件**：`src/lib/diagnosis-safety.ts` `buildDeterministicRiskFollowup`（`hasStrongRisk` ~915）
- **风险/成本**：中（动安全汇总层，需回归验证 red-flag/审方相关断言）。

### O2 —【中】"已达最大追问轮次"提示不可达；追问兜底缺终态 ⬜
- **现象**：追问轮次用尽、辨证仍不足时，卡片显示"第 1/1 轮追问"，但"已达最大追问轮次…转为信息不足分析模式"横幅永不出现。
- **根因**：横幅渲染条件是 `questionRounds>=maxQuestionRounds && phase==="done"`，而 `applyDifferentiationFollowupState` 把 phase 固定为 `"question"`，**永不进入 done**。（无限循环本身已被 1.7 的逃生阀堵住，但"信息不足终态"提示缺失。）
- **整改建议**：当 `questionRounds>=maxQuestionRounds` 且仍不足时，转入**显式终态** `applyCompletenessLimitedOutcome`（phase=`done`，输出"信息不足分析模式"+ 明确补录清单），而不是继续 `applyDifferentiationFollowupState`；或放宽横幅条件不再要求 `phase==="done"`。二者取其一，保证有终态提示与"补录后重评估"入口。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx`（横幅 ~1079；`runDiagnoseChain` 4743 分支；`runQuestion` 兜底 5014-5025）

### O3 —【中】报错后隐藏录入框，只能盲重试，坏输入成死路 ⬜
- **现象**：M01 因某条输入让模型出错 → `setError` 置 `phase="error"` → 录入框被隐藏（`showInput` 不含 "error"）→ 医生无法改那条输入，点"重试当前阶段"用**同样**内容再打 → 同样失败。
- **根因**：`showInput = ["idle","collect","question"].includes(phase) || …`，不含 "error"；且 `handleRetry` 用 `caseState.hisRecord`（上次已提交的病历），**不吃 `recordDraft` 的新编辑**。
- **整改建议**：
  1. `showInput` 纳入 `"error"`，让医生能编辑；
  2. `handleRetry`（或 error 分支的 `handleSubmit`）在重试 collect/question 时**从当前 `recordDraft` 重建请求**（复用 `applyDraftToCaseState`），使编辑生效；
  3. 区分瞬时错误（可盲重试）与输入错误（需编辑）——错误提示文案给出"修改左侧病历/下方补充后重试"的引导。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx`（`showInput` ~5117；`handleRetry` ~5036；`handleSubmit`）

### O4 —【中】追问每轮无条件重跑 M03（LLM），轮次计数只钳制显示不真正限流 ⬜
- **现象**：`maxQuestionRounds=1` 时，医生每答一次追问都会 `needsDiagnose=(phase==="diagnose"||!diagnosis)` 触发**重跑 M03**（~70s/次 LLM），而 `questionRounds=min(max, n+1)` 只钳制显示、不阻止重跑。
- **根因**：重跑 M03 的判据是 `needsDiagnose`，与轮次上限无关；`applyDifferentiationFollowupState` 又不清诊断也不增轮次，增轮次在 `handleSubmit` 的答复分支（4963/4994）。
- **影响**：非死循环（1.7 逃生阀 + 1.8 稳定标签后误触已大减），但**每轮一次昂贵 LLM 调用**，且答复未改变辨证要素时重跑是浪费。
- **整改建议**：
  1. 轮次用尽时**停止重跑 M03**、直接进入终态（见 O2）；
  2. 或答复未新增关键辨证要素时**复用现有 M03 诊断**，只重算门控与追问，不重打模型。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx` `runDiagnoseChain`（`needsDiagnose` 判定）

### O5 —【低】`outputLevel`（结论/完整候选方案）被解析但从不参与门控，是"死数据"⬜
- **现象**：M03 若无视"必须完整候选方案"指令、用散文写"结论：信息不足，建议补充舌脉后再辨证"（非精确短语），`isLimitedDiagnosisText` 不命中 → 链路照常进 M04，在一个自述信息不足的诊断上生成剂量级处方。
- **根因**：门控依赖 `isLimitedDiagnosisText` 的固定 4 短语，与模型自述结论 `outputLevel` 各行其是。
- **整改建议**：让 `isLimitedDiagnosisText` 成为唯一真源并覆盖更多措辞（"建议完善.*再(辨证|评估)""暂不进入(候选)?方药"等），或直接以结构化 `reasoningV2` + 完整度门控为准，`outputLevel` 仅作展示。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx`（`isLimitedDiagnosisText` 874；`buildDecisionSummary` 1902）

### O6 —【低】rxaudit `extractSyndromeName` 冒号正则脆弱（仅兜底路径）⬜
- **现象**：当 `reasoningV2` 缺失、退回从 `state.diagnosis` 抽证名时，只匹配"证候诊断:/主证候:/证型:"带冒号写法；表格化或改写的 M03 会把证名丢给灵犀审方。
- **缓解现状**：`buildAuditData` 已**优先** `state.reasoningV2?.overview?.primarySyndrome`（`rxaudit.ts:253`），仅兜底才走此函数，故实际影响低。
- **整改建议**：拓宽为可读"证候分布与病机映射"表首行、接受更多标签（主要证候/辨证/中医证候）；或复用前端 `buildDifferentiationSignals` 的结构化取值。
- **文件**：`src/lib/rxaudit.ts` `extractSyndromeName`（~102）

### O7 —【低】M04 截断前端不可见（靠运气 fail-closed）⬜
- **现象**：M04 因 `finish_reason==="length"` 截断时，`diagnosis-api.ts` 走 `truncateFallback` 分支输出安全受限处方文本，但**不再发 `[TRUNCATED]` 标记**；前端 `prescriptionTruncated` 的 `[TRUNCATED]`/sentinel 检测因此形同虚设。
- **缓解现状**：截断时 `truncateFallback` = `buildSafetyLimitedPrescription`（无剂量表），下游按无处方 fail-closed，故**结果安全**，但检测分支是死代码、语义脆弱。
- **整改建议**：即便用 `truncateFallback`，也发一个前端可识别的截断标记；或让 prescribe 路由显式返回截断标志，前端据此提示"处方生成不完整、请重试"。
- **文件**：`src/app/diagnosis/DiagnosisClient.tsx:4763`；`src/lib/diagnosis-api.ts:256`

### O8 —【低】充分度双指标一致性收尾核对 ⬜
- **现状**：`completenessStatus.label`（"可生成候选方案"）已不再单独渲染，卡片统一到辨证充分度；但 `completeness.level` 仍参与部分门控（`canEnterDiagnosisChain` 只看 level=C）。

- **文件**：`src/app/diagnosis/DiagnosisClient.tsx`（`canEnterDiagnosisChain` 802 / `canEnterDosePrescriptionChain` 807 / 卡片渲染）

## 5. 跨类根因（系统性模式，建议作为编码规约）🧭

- **P1 不要用"正则解析模型散文"来驱动流程或安全判断。** 一律以结构化 `reasoningV2` 载荷为准，正则仅兜底。（O5/O6/1.8 同源；#1 关键缺陷即由此而来。）
- **P2 充分度只保留一套权威口径。** "辨证充分度"应同时驱动**显示与流程**；任何"显示说 A、流程做 B"都是缺陷（1.7 修复的即此类）。
- **P3 审方不可用/降级一律 fail-closed，每个分支都要加锁。** degraded=真也要锁人工复核（1.9）；assess/post-prescription-risk/前端失败路径三处都要一致。
- **P4 确定性风险扫描必须按"风险小节"限定，并排除溯源/模板词。** 不要扫整份处方+诊断（O1/1.13 同类）。
- **P5 每个"信息不足/报错"状态都必须有明确下一步。** 要么弹可答的追问、要么可编辑重试，绝不留死路或无界循环（O2/O3/O4）。
- **P6 非确定性模型标签不得静默破坏流程。** 要么结构化、要么让解析器对措辞宽容并覆盖模型可能的表达（O5/1.4）。
