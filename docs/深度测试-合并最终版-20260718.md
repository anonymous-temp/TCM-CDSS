**功能可跑通、确定性安全层扎实，但临床质量与响应速度当前不可直接用于真实门诊。**

最迫切（发布阻断级）：
1. **M03/M04 结构化生成间歇失败**（最简病例也产出空处方，M04 实测成功率约 48%）
2. **"西医诊断依据=病历复述"**（prompt 层根因：字段语义要求列事实而非诊断推理；混入心率/舌象/孤片段）

## 2. P0 — 发布阻断

### P0-1 · 结构化生成间歇失败，M04 成功率约 48%（合并 A-P1-9 + B-F1）✅
- **现象**：最简病例（心脾两虚不寐）M04 产出 `CDSS_NON_DOSE_PRESCRIPTION` + `[TRUNCATED]`（"模型处方输出被截断或结构化结果未闭合"）；另一病例 M03 的 sentinel JSON 为 NULL → M04 因无签名直接 409。报告 A 100 例统计 M04 成功率仅 **48%（41/85）**。
- **根因**：模型有时不在结构化时限内闭合 `<!-- DIAGNOSIS_JSON_START/END -->` sentinel，结构化重试未能修复。
- **证据**：`deeptest/out/A/02-prescribe.md`、`deeptest/out/D/01-diagnose.structured.json`(=null)
- **修法**：统计线上 sentinel 闭合失败率；强化结构化修复策略；常见简单证型预置稳定模板兜底。

### P0-2 · 端到端 218 秒（A-P0-2）✅
- 单例 M01 0.4s + M02 26.6s + M03 86s + M04 105s ≈ 218s。大头：clinical-facts backstop 默认开（P0-3），每次 red-flags 触发 extractor+reviewer+adjudicator 3 次 LLM，p95 1ms→4-6s。
- **修法**：M03/M04 早期流式 render；拆 M03 并行；backstop 改异步预取。

### P0-3 · 西医诊断"依据"=病历复述（prompt 层根因，B-F3）✅ —— 用户原诉
- 结构化 `supportingFacts` 是带噪声事实堆砌：高血压例混入"88次/分"（心率为何是高血压依据）、"偶发"（孤片段）、"舌暗红苔薄黄"（**中医舌象混入西医依据**）。
- **根因**：`diagnosis-prompts.ts` L400 `**患者依据**：[仅列已提供事实]` + L166 `"supportingFacts":["病历中已提供的支持事实"]`——两处都要求"列事实"。对照病机字段(L410 `事实→依据→病机`)要求推理链，故系统能产出分析性依据却在该字段退化。红旗例(case F)的"依据"是分析性的（休克指数 1.04），证明**模型能、但不稳定**。
- **修法**：把 `supportingFacts` 语义改为"诊断支撑要点/异常分析/标准命中项"；呈现层把"已记录事实"与"诊断依据"分区。

### P0-4 · 西医诊断分级错误（B-F4）✅
- 168/102mmHg 判"高血压病 **3 级**"，按中国标准实为 **2 级**（3 级≥180/110）。事实性临床错误。
- **修法**：加"诊断标准逐项核对"显式推理与校验。

### P0-5 · M02 追问静默降级为通用 fallback（合并 A-P1-1/P1-6 + B-F2）✅
- harness 中模型对失眠例产出优质问句（"怕冷/怕热"辨阳虚阴虚；"月经是否停"判围绝经期），被 server 以"模型结构化追问计划不可用"替换为"症状加重/缓解/波动"通用 fallback；**真实 UI（高血压例）同样显示 fallback** 而非安全分诊问句。降级**不告知医生**。
- 另：M02 单选强迫二分（烦躁 vs 抑郁），临床混合常见会丢信息。
- **修法**：修契约校验 flaky；降级显式提示；单选改多选。

### P0-6 · 临床辨证过度医疗（A-P0-6/P0-7）🔬 —— 高危，须重点改造
- 既往已治愈/恢复期病例被强行辨证开方（NG01/02/04/06/09）；痛经"得温则减+月经后期+舌暗苔白"典型寒凝血瘀**误辨为气血亏虚**（TC11，寒证误补阴养血可能加重）；7+/85 用山药当君药（力度不够君药级）。
- **修法**：prompt 加"现病史=本次门诊当前症状；既往已治愈史不得作辨证依据"；M03 sentinel 加 `isHistoricalOnly`；寒热指征（得温则减/喜温喜按）强制正确识别；虚证君药选参芪术草类。
- **注**：本轮 6 例未复现这些具体病案，但其 85 例证据可信，且与系统"过度辨证"总倾向一致，定 P0。

### P0-7 · strictReady 非确定性（A-P0-3 + B 新发现）⚠️
- 首次健康检查 `strictReady:false`（tcm_treatment_capabilities_not_configured）；我重启 dev 后翻为 `true`。**同一配置两次结果不同**，本身就是部署阻断级不稳定。Docker 健康检查会因此时过时不过。
- **修法**：把 `tcm_treatment_capabilities` 移出 strict 阻断集合；排查 strict 探针的非确定性来源。

### P0-8 · hot-reload 中断推理 + 表单态不持久（A-P0-5）✅
- 我 Playwright 测试中页面反复触发 beforeunload、modal detach；报告 A 指出 hot-reload 后 UI 状态机矛盾（主区"重试本阶段" vs 右栏"等待病历信息"）、表单 React state 清空。生产虽无 hot-reload，但暴露表单输入态无持久化的真 bug（nginx reload/Docker restart 后丢表单）。
- **修法**：表单 debounce 写加密快照，reload 后 hydrate。

## 6. 五大重点领域深度评审

### 6.1 证据依据（用户首要关切）
- **核心问题 P0-3**：西医诊断"依据"=病历复述（prompt 层根因已定位，实证混入心率/舌象）。
- **正向 P2-6**：指南引用经联网核验**真实**（VA/DoD 2019 失眠指南；意大利 2023 失眠共识 Palagini PMID 38063870）。反伪造层（`evidence-source-validation.ts` fail-closed）有效，**未见编造 DOI/指南**。残留：来源不透明、人群外推。
- **同类 P2-2/P2-3**：结构化字段 JSON dump + 工程短语泄露。

### 6.2 西医诊断与中医证候推理
- **西医**：诊断倾向本身合理，但 P0-4 分级错误、P2-5 文本/结构不一致。
- **中医（正向）**：核心病机推理链质量高——case A "脾虚→气血乏源→血不养心→心神失养→失眠"；病名证型（不寐/心脾气血两虚、肺胀/外寒内饮、恶阻/脾胃虚弱、血证/气血两虚）规范；鉴别合理。**这是系统强项**，与报告 A 的 TC08 酸枣仁汤、AL10 归脾汤 5/5 优秀处方一致。
- **隐患 P0-6**：既往史当现病史、寒热误判（TC11）、山药君——需 prompt 改造。

### 6.3 处方推理
- **组方合理（正向）**：case C 外寒内饮方（干姜+法半夏+紫菀款冬花苦杏仁+陈皮厚朴五味子紫苏叶+桔梗）契合病机；避开附子（不触十八反）；法半夏规范炮制；苦杏仁 isToxic 正确；SpO₂<90%→急诊。
- **缺陷**：P2-1 方义乱码；P2-4 加减方空转；P1-1 独立复核弱；P0-1 间歇失败。
- **量化（报告 A）**：25 条结构化处方仅 4 条经典名方级能治病，8-10 条方向对力度不够（山药君系列），5+ 条过度医疗，1 条可能加重（TC11）。
