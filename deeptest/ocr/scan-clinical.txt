──────── Project Summary ────────

### Top Issues

1. **Unbounded input parsing leading to DoS risk**  
   - `src/lib/m04-proposal-compiler.ts`: `JSON.parse` in `compileM04JsonObjectContent` and `normalizeM04ProposalInput` processes untrusted input without size or depth limits → memory exhaustion.  
   - `src/lib/diagnosis-api.ts`: `retryCompletePrimaryResponse` concatenates raw JSON, clinical context, and multiple hints without an overall length guard, risking exceeding model max prompt size and causing silent truncation or API failures.  
   *These enable attackers or malformed inputs to exhaust memory or corrupt downstream LLM calls.*

2. **Stream resource leaks and unreliability**  
   - `src/lib/diagnosis-api.ts`: `callPrimaryTextModelStream` never calls `reader.releaseLock()` (unlike `callGlmStream` which releases in a finally block), risking locked streams.  
   - Error handler branches (`streamErrorFallback`, `truncateFallback`) call `enqueueClient` without protection; if `enqueueClient` throws, `closeClientStream()` is skipped, leaving the stream dangling.  
   - Inconsistent retry cleanup: `callPrimaryTextModelStream` uses raw `candidate.body?.cancel()` while `callGlmStream` uses a proper `cancelResponseBody` helper.  

3. **Silent failures and missing observability**  
   - `src/lib/m04-proposal-compiler.ts`: both `compileM04Proposal` and `m04ProposalIssueCode` swallow `safeParse` errors with no logging — impossible to distinguish “invalid input” from “internal bug” in production.  
   - Dead code (`useVision = true` never used in `diagnosis-api.ts`) and confusing patterns (double sanitization of `sanitizeDiagnoseStreamingDraft`, dual heartbeat-stop references) obscure debugging and maintenance.  

4. **Code quality and maintainability hazards**  
   - `src/lib/m04-proposal-compiler.ts`: nested ternary (prohibited by project rules), loose equality (`!= null`) in index checks, unsafe type assertion that `JSON.parse` result is an object.  
   - `src/lib/diagnosis-api.ts`: `callPrimaryTextModelStream` is ~370 lines, up to 7 levels of nesting, and mutates `m04RepairState` inside async blocks after await, making the control flow error-prone and nearly unreviewable.  

5. **Unexpected or brittle behavior**  
   - `src/lib/m04-proposal-compiler.ts`: `acupointCare` is always forced to `null`, discarding any provider input. If intentional, it’s undocumented; if unintentional, it silently breaks client data.  
   - `src/lib/diagnosis-api.ts`: `isM04AuditAdvisoryReason` regex for `herb_…_unsupported_high_impact_` is too permissive, potentially matching future non‑advisory suffixes. Double sanitization could cause side effects if the sanitizer is ever made non‑idempotent.

### Cross-Cutting Concerns

- **Inconsistent input validation**  
  Both files parse untrusted data without guardrails: unbounded `JSON.parse` in the compiler; no total‑length check for the repair prompt in the diagnosis API.  
  *Representative paths:* `compileM04JsonObjectContent`, `retryCompletePrimaryResponse`.

- **Incomplete resource cleanup patterns**  
  Stream handling diverges: missing `reader.releaseLock()` in the primary model stream, missing `closeClientStream()` when enqueueing fails, and mismatched retry cancels. The codebase lacks a uniform stream‑teardown wrapper.  
  *Paths:* `callPrimaryTextModelStream`, `callGlmStream`.

- **Missing error diagnostics**  
  Silent failures (compiler’s `safeParse` wraps) and no logging in fallback paths make root‑causing impossible in production.  
  *Paths:* `compileM04Proposal`, `m04ProposalIssueCode`.

### Quick Wins

*Low-effort, high-impact fixes based on the scan:*

1. **Add input size guard before JSON.parse**  
   In `m04-proposal-compiler.ts`, impose a reasonable max string length (e.g., 1 MB) before parsing; reject or truncate early.  
2. **Insert `reader.releaseLock()` in primary model stream**  
   In `callPrimaryTextModelStream`’s finally or cancel path, mirror `callGlmStream`’s pattern.  
3. **Replace loose equality with strict**  
   `firstIndex !== null && firstIndex !== undefined` → just `firstIndex !== undefined` (since index is a number).  
4. **Remove dead code**  
   Delete `const useVision = true;` from `diagnosis-api.ts`.  
5. **Refactor nested ternary**  
   Transform the nested ternary in `m04-proposal-compiler.ts` into a clear if/else or lookup table.  
6. **Add trivial logging on safeParse failure**  
   Log at `warn` level with the raw input snippet so operations can detect malformed payloads immediately.  
7. **Eliminate double sanitization**  
   If `sanitizeDiagnoseStreamingDraft` is idempotent, remove one of the duplicate calls (the second explicit one on `signedContent`). If not, fix the side‑effect risk.
