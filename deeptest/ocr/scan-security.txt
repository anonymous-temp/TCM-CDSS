### Top Issues

1. **Auth bypass via missing base path in middleware matcher** (`src/proxy.ts`)  
   When `NEXT_PUBLIC_BASE_PATH` is set, the middleware’s path helpers fail to strip the base path, allowing unauthenticated requests to reach protected `/api/` endpoints. An attacker can directly access the API without any authentication cookie or token.  
   **Impact:** Critical – complete bypass of gateway-level auth.

2. **Client-supplied header attacks on CDSS cookie security** (`src/lib/cdss-auth.ts`)  
   - An attacker can inject `X-Forwarded-Proto` to suppress the `Secure` flag on cookies, enabling theft over unencrypted connections.  
   - `@` is not rejected in the host header regex, enabling origin spoofing (e.g., `attacker.com@trusted.com`).  
   - Invalid base path configurations (trailing slash, empty) collapse the cookie path to `/`, leaking cookies across applications.  
   **Impact:** Critical – session hijacking, cookie theft, cross-application leakage.

3. **Non-deterministic HMAC signature payloads** (`src/lib/reasoning-contract-signature.ts`)  
   - `localeCompare` produces different sort orders across Node.js versions/locales, causing mismatched HMACs between signing and verification.  
   - `JSON.parse` lacks try‑catch, so malformed markers throw unhandled errors.  
   - The object-type guard passes `Date`, `RegExp`, `Map`, etc., leading to silent data loss and wrong signatures.  
   **Impact:** High – integrity checks fail unpredictably; either false rejection or silent bypass.

4. **Rate-limiting: single shared bucket enables cross‑client DoS** (`src/proxy.ts`)  
   When `CDSS_TRUST_PROXY_HEADERS` is not `"true"`, every client is mapped to the literal key `"direct"`. One attacker can exhaust the shared rate limit and lock out all legitimate clients. This is compounded by race conditions in the limiter (TOCTOU on a shared `Map`) and an unbounded memory leak because expired entries are never cleaned.  
   **Impact:** High – trivial multi‑client denial of service, memory exhaustion.

5. **Missing catch blocks cause unhandled promise rejections / fails‑open**  
   - `src/lib/http-guard.ts`: stream reading `while` loop wrapped in `try…finally` only; any stream error propagates as an unhandled rejection → fail‑open.  
   - `src/lib/rxaudit.ts`: `try…finally` around audit execution has no `catch`; an unexpected exception terminates the request without proper cleanup.  
   **Impact:** Medium‑High – process termination or security checks silently skipped.

6. **Regular expression ReDoS and reverse character range** (`src/lib/evidence-source-validation.ts`)  
   - The pattern `(?:-[A-Z0-9_-]+)+` contains a nested quantifier; crafted input like long hyphen‑delimited strings triggers exponential backtracking.  
   - `'\u2014'` (em dash) followed by `'-'` forms a reverse range, causing undefined behavior across engines.  
   **Impact:** Medium – attacker can stall the service with a single request; unreliable matching.

7. **Loose matching and silent data corruption in evidence validation** (`src/lib/evidence-source-validation.ts`)  
   - `sanitizeEvidenceObject` replaces the entire object with a placeholder if `evidenceLevel` is missing, discarding legitimate data.  
   - Title matching uses `includes(…)` without word boundaries, causing false positives (e.g., `'中国药典'` matches `'非中国药典标准'`).  
   - Year extraction captures years from citation IDs, polluting the year filter and incorrectly blocking/allowing atoms.  
   **Impact:** Medium – incorrect safety decisions; evidence incorrectly accepted or rejected.

8. **Privacy and data integrity in audit** (`src/lib/rxaudit.ts`)  
   - Exact patient age is transmitted to an external service alongside a sanitized clinical summary, risking re‑identification.  
   - The issue deduplication key strips all whitespace and punctuation, merging distinct safety warnings (e.g., “药物A” and “药物B” could collide).  
   - FNV‑1a 32‑bit hash for stable issue IDs has a low collision threshold, undermining audit traceability across many audits.  
   **Impact:** Medium – compliance risk, missed safety alerts.

### Module Hotspots

- **`src/proxy.ts`** – 8 findings, including critical auth bypass, CSRF origin checks, rate‑limiter DoS, and memory leak. The rate‑limiting and middleware logic is the most severely affected area.  
- **`src/lib/evidence-source-validation.ts`** – 7 findings, dominated by regex vulnerabilities (ReDoS, reverse range), duplicated patterns, and data‑corruption logic. The validation pipeline is brittle under adversarial input.  
- **`src/lib/cdss-auth.ts`** – 6 findings, all security‑critical: cookie security, host spoofing, weak constant‑time comparison, and DoS via client key fallback.  
- **`src/lib/rxaudit.ts`** – 6 findings spanning privacy, safety‑issue merging, hash collisions, and concurrency (atomicity of `requestSeq`).  
- **`src/lib/reasoning-contract-signature.ts`** – 4 findings, all high‑impact: non‑deterministic canonicalization, unsafe JSON parsing, and flawed object traversal for HMAC payloads.

### Cross-Cutting Concerns

- **Insecure header trust** – Multiple modules blindly trust or improperly sanitize proxy headers (`X-Forwarded-Proto` in `src/lib/cdss-auth.ts`, `X-Forwarded-Host` host spoofing, IP header fallback in `src/proxy.ts`). This pattern leads to authentication/cookie‑bypass and IP‑based access‑control failures.  
- **Non‑deterministic serialization for security checks** – `localeCompare` in `src/lib/reasoning-contract-signature.ts`, aggressive whitespace stripping in dedup keys (`src/lib/rxaudit.ts`), and fingerprint collisions in evidence matching (`src/lib/evidence-source-validation.ts`) all cause integrity‑critical decisions to vary across environments, undermining signing, deduplication, and evidence lookup.  
- **Missing error handling in async flows** – `try…finally` without `catch` appears in `src/lib/http-guard.ts` and `src/lib/rxaudit.ts`. Any thrown error becomes an unhandled rejection, causing either silent fail‑open or process crash. This pattern may exist elsewhere; every async boundary that touches untrusted data needs a robust error handler.  
- **Mutable state across concurrent requests** – The rate‑limiter `Map` in `src/proxy.ts` is mutated without synchronization, and `requestSeq` in `src/lib/rxaudit.ts` is incremented non‑atomically. These race conditions become severe under load, leading to incorrect rate limiting and duplicate event IDs.  
- **Regex safety** – Multiple files contain either backtracking‑susceptible patterns (`evidence-source-validation.ts`) or unsafe character ranges (`evidence-source-validation.ts`, potentially `cdss-auth.ts` host regex). Untrusted input can exploit them for DoS or bypass.
